## Что это такое

Prism Engine — медиа-движок на Rust без сторонних зависимостей в коде: чтение изображений, вёрстка,
отрисовка кадра, монтаж таймлайна, выпуск готового фильма — всё выполняется в одном детерминированном
движке. Все 110 зависимостей времени выполнения (плюс 20 тестовых зависимостей) являются `path`-зависимостями
этого репозитория — без обращения к сети, без менеджера пакетов, без рисков цепочки поставок.

Используется **дистрибуция исходников одним файлом**: весь движок (622 файла, 28 crate) объединён в один
UTF-8 текстовый файл `prism-engine-v2.0-source.txt`. Имея этот файл, можно локально восстановить дерево
каталогов, полностью совпадающее с репозиторием.

## Что умеет движок

Обзор в одном предложении: **изображение — это кадр в определённый момент времени, а видео — это
последовательность кадров на протяжении отрезка времени** — одно и то же описание сцены: зафиксируйте
момент и получите отдельный кадр, продвигайте его непрерывно и записывайте — получите видео; статика
и динамика используют один и тот же набор возможностей.
Далее — пять блоков по принципу «что вы хотите сделать»: **прочитать → разложить → нарисовать → выпустить → встроить в собственный инструментарий**.

### Что читает (ввод)

- **Единый фасад декодирования**: одна точка входа `decode_image(bytes, ext)` распределяет статические
  изображения — PNG (неинтерлейсные 8/16 bit), baseline JPEG (IDCT с фиксированной точкой, побитово
  детерминированно на разных платформах), **приоритет магического числа, расширение как резерв**
  (декодирование работает даже при неверно указанном расширении);
  форматы вне матрицы или требующие внешнего взаимодействия всегда сообщают об ошибке по трёхчастной
  схеме (где / что / как исправить) и дают рекомендацию по работе через ffmpeg,
  **никогда не завершаются молча**.
- **Анимация / аудио / контейнеры**: нативное покадровое декодирование GIF и APNG (`prism-media`);
  встроенное декодирование WAV, mp3/aac/FLAC — через путь определения ffmpeg (`prism-audio`);
  обратное чтение MP4-MJPEG (`decode_mp4_video`).
- **Полный набор EXR**: чтение и запись, сжатие, DWA, а также **кросс-реализационное побитовое сличение
  битового потока** с официальным OpenEXR (а не «сам записал — сам прочитал»).
- **Камерный RAW**: базовое декодирование RAW. **Граница**: `Compression=7` (lossless JPEG) в реальных
  DNG не реализован, DNG, снятые реальной камерой, не читаются — это записано в разделе «Честные границы»,
  без утаивания.
- **Трёхмерные ассеты**: импорт glTF / OBJ, разбор USD (`.usda`) и пакет параметров MaterialX,
  mesh может попасть в сцену рендеринга.
- **Внешние шрифты**: `load_font_file` напрямую загружает сторонние TTF/OTF, цепочка резервных вариантов
  разрешается по уровням, при отсутствии глифа выдаётся явная диагностика вместо квадратиков.

### Что раскладывает (синтаксис авторинга)

- **Полноблочный синтаксис DSL v2**: один `.prism` описывает «что нужно, как расположить, как двигать,
  как выглядит, во что экспортировать», результат компиляции — граф узлов + каналы свойств + таймлайн.
- **Пять комбинаторов**: высокоуровневые комбинаторы `title_card` / `lower_third` / `split_screen` / `ken_burns` /
  `morph_between` разворачиваются в граф узлов — «90-секундный фильм» больше не пишется кодом сцены
  вручную, а собирается из готовых блоков.
- **Переходы и morph**: Fade / Wipe / Dissolve / Push полностью параметризованы (длительность, easing, направление),
  Morph — деформация ломаных, последовательность сцен может быть выбрана в любой момент времени.
- **Вёрстка формул**: `math_ast` + `math_layout` верстают верхние и нижние индексы / дроби / радикалы / крупные операторы /
  матрицы, блок DSL `formula` верстается напрямую, на той же базовой линии, что и основной текст.

### Что рисует (рендеринг и симуляция)

- **Офлайн-рендеринг фотореалистичного уровня**: трассировка путей + физически корректные BSDF (диффузный / зеркальный / стекло / металл),
  стекло и металл используют случайное обращение (Монте-Карло по ряду Neumann), поддерживаются объёмные среды и подповерхностное рассеяние.
- **Четыре семейства криволинейных примитивов**: цилиндр / конус / тор / поверхность вращения, все с аналитическим
  пересечением (уравнение четвёртой степени через замкнутое решение Ferrari, точные корни); произвольный треугольный mesh + SAH-BVH, сверка parity по двум путям.
- **GPU compute**: независимый от устройства семантический слой compute + Vulkan dispatch + вручную написанный минимальный SPIR-V;
  на платформах без GPU всё полностью работает под программным ICD Mesa lavapipe (проверяемо в headless).
- **Физика и частицы**: единый решатель XPBD (твёрдые тела / мягкие тела / ткань / сочленения / жидкости / разрушение),
  дым FLIP, системы частиц (AudioReactive связан с огибающей аудио).
- **Генеративное искусство и постобработка**: поля потоков / L-системы / клеточные автоматы / реакционная диффузия / фракталы / Voronoi;
  blur / bloom / halation / зерно плёнки / четыре стиля NPR (toon / watercolor / halftone / oil) / тройное шумоподавление.
- **Цветокоррекция и векторы**: вторичная цветокоррекция (выделение по HSL + кривые RGB), пресеты стилей cinematic / film / anime и
  три уровня качества — черновик / стандарт / кино (качество — это параметр, а не магия); растеризация векторных путей, draw-on и morph путей.
- **Обработка аудио**: нормализация громкости (loudnorm), определение такта, спектральный анализ, извлечение огибающей —
  может синхронизироваться с изображением (частицы AudioReactive следуют за огибающей аудио).
- **CPU-референсный бэкенд — полноценный участник**: на машине без GPU всё равно получаются корректные изображения, и одновременно он служит эталоном проверки для GPU.

### Что выдаёт (доставка)

- **`render_movie` напрямую**: результат компиляции DSL v2 за один вызов проходит «покадровое вычисление → рендеринг tile →
  доставка», из `.prism` одной командой получается готовый фильм (`prism-app render demo.prism`); узлы без поддержки честно сообщают об ошибке, без молчаливого приближения.
- **Замкнутый цикл предпросмотра**: `prism-app preview` запускает сервис предпросмотра; в редакторе два режима предпросмотра —
  Draft (геометрические паттерны для сохранения частоты кадров) / Real (реальный рендеринг с низким spp, асинхронное обновление).
- **Собственный кодировщик + управление битрейтом**: временной кодировщик в области JPEG с I/P-кадрами работает через приватный контейнер `PRMV`
  (две генерации схемы, v2/v3), управление битрейтом по принципу water-filling + субпиксельная оценка движения qpel (измерено: PSNR +2.577 dB,
  объём −21.6%).
- **Цепочка взаимодействия с ffmpeg**: есть ffmpeg → преобразование в H.264/HEVC через канал stdin rawvideo;
  нет ffmpeg → автоматическое понижение до MJPEG, **движок всегда может выдать фильм**; никакие бинарники не встраиваются.
- **Доставка последовательностей EXR**: последовательность кадров пишется сразу в EXR и уходит в конвейер постобработки.
- **Распределённая ферма**: распределение на уровне кадров + N процессов worker + детерминированное слияние — параллельный MD5 == последовательный MD5,
  поддерживается возобновление расчёта с места остановки.

### Как интегрируется (экосистема)

- **Поверхность инструментов MCP**: три инструмента stdio JSON-RPC — `scene_check` (компиляция + пробный рендер + оценка числа кадров),
  `render_submit` (детерминированный job id + покадровая MD5-сводка), `diagnose` (трёхчастная локализация ошибки).
- **Node SDK**: семантическое согласование версий (включая особый случай 0.x), в комплект входит пример пакета узлов
  (`examples/sdk-nodes/cinematic-basic/`, компилируется / загружается / согласуется).
- **Каркас определения аппаратного кодирования**: `prism-ffi-hwenc` — цепочка определения для трёх платформ (VideoToolbox / NVENC / VAAPI)
  + матрица feature gate; при несоответствии платформы явно сообщается о неподдержке.

> Подробные границы возможностей (что именно **невозможно**) см. в разделе «Честные границы» файла `开发者指南.md` из пакета —
> там зафиксировано текущее реальное состояние (криволинейные примитивы идут только через CPU, ускорение GPU нужно измерять на целевом оборудовании, аппаратное кодирование подключается
> под целевую платформу…); эта статья даёт лишь общую картину, без рекламных обещаний.

## Почему дистрибуция одним файлом

- **Проверяемость**: один текстовый файл, читаемый глазами, доступный для `diff` и проверки хешем; публикация сразу фиксируется.
- **Воспроизводимость**: упаковка детерминирована — при одинаковых входных данных SHA-256 двух упаковок полностью совпадает.
- **Переносимость**: не нужно клонировать огромный репозиторий, один файл можно передать почтой или в чате, а сборку можно восстановить даже офлайн.
- **О компромиссе**: дистрибуция одним файлом отказывается от удобства «просматривать код прямо на GitHub» в обмен на детерминизм «один файл уносит всё и проверяется побайтово». После распаковки получается обычный Cargo workspace, ничем не отличающийся от типичного проекта на Rust.

## Быстрый старт

Предварительно: установите [Rust](https://www.rust-lang.org/) (включая `cargo`) и [Node.js](https://nodejs.org/) 18+.

```bash
# 1. Скачайте из репозитория prism-engine-v2.0-source.txt и сохраните как локальный файл
# 2. Откройте текстовым редактором и сохраните Node.js-скрипт, расположенный между
#    "UNPACK SCRIPT BEGIN" и "UNPACK SCRIPT END", в тот же каталог под именем unpack.cjs
# 3. Запустите распаковку (несколько секунд, восстанавливается 622 файла)
node unpack.cjs
# 4. В восстановленном каталоге (то есть в корне workspace) запустите полный набор тестов
cargo test --workspace --release
# Ожидается: 3714 passed / 0 failed
```

После распаковки получается стандартный Cargo workspace (28 crate в `src/`), дальнейшие команды `cargo` такие же, как в обычном проекте на Rust.

> Цепочка проверки wasm на мобильных устройствах: `rustup target add wasm32-unknown-unknown`, затем `cargo build -p prism-core --target wasm32-unknown-unknown`.

## Сборка и тестирование

```bash
# Дымовой прогон по всему репозиторию (release, рекомендуется)
cargo test --workspace --release
# Эквивалентный псевдоним
cargo xtest
# Быстрая проверка одного crate
cargo test -p prism-core --release
```

- Полный набор тестов: **3714 passed / 0 failed / 0 ignored** (эта версия реально прогнана на **распакованном дереве**: 166 блоков тестов)
- CI: **6 job** — защита от призрачных записей (ghost-guard) / компиляция + полный набор тестов (native) / сборка wasm32 (wasm) /
  статическая проверка WGSL (wasm-verify) / кросс-реализационное побитовое сличение битового потока с официальным OpenEXR (interop) / перекрёстная сверка на хосте node (lint).
- Локальных скриптов гейтов 3 (полностью без зависимостей, только `node`, см. ниже) + скрипт упаковки 1;
  среди них самопроверка соответствия — **9/9 пройдено**, обратное самодоказательство — **8/8 помечено красным**.

Запуск гейтов локально (требуется Node 18+):

```bash
node tools/ghost_guard.mjs --check        # защита от призрачных записей: G1 повторное определение/G2 строгое надмножество/G3 документация с начала строки/G4 компиляция
node tools/hygiene_scan.mjs               # гигиена открытого кода: по пунктам перечисляет оставшиеся внутренние формулировки (файл:строка), при совпадении exit 1
node tools/compliance_check.mjs           # самопроверка соответствия: должно быть 9/9 пройдено
node tools/compliance_check.mjs --self-test   # обратное самодоказательство: должно дать красный, доказывая различительную способность критериев
```

> **Гигиеническое сканирование открытого кода пока даёт остаточные совпадения**: в репозитории остались ранние внутренние формулировки, при этом
> **уровень документации, входящей в пакет, уже очищен до нуля** (README / руководство разработчика / Compliance), остальное находится в **комментариях к исходникам внутри дистрибутива**
> и в **файлах репозитория, не входящих в пакет**; они классифицированы по факту и вынесены в отдельные пункты очистки. Скрипт существует именно для того, чтобы остатки были
> **видимы и устранялись по пунктам**, а не для вида чистоты — не воспринимайте «число совпадений не равно 0» как отказ гейта.

## Соответствие требованиям

Движок гарантирует **отсутствие сторонних зависимостей в коде**, что подтверждено самопроверкой:

- **C1 Ноль сторонних зависимостей в коде**: все 130 зависимостей (110 времени выполнения + 20 тестовых) — `path`-зависимости этого репозитория; нет `build.rs`, нет директив нативной линковки, `Cargo.lock` фиксирует 29 пакетов этого репозитория.
- **C2 Реестр ассетов полон**: в основной таблице 5 ассетов заполнены все поля, статус собственной разработки попадает в контролируемый словарь; полный текст лицензии шрифта OFL 1.1 размещён вместе со шрифтом в `src/prism-text/font_data/LICENSE`.
- **C3 Уведомления об авторстве третьих сторон**: присутствует `Compliance/THIRD-PARTY-NOTICES.md`, где явно разграничено «данные-ассеты ≠ зависимости в коде».

> Примечание: этот репозиторий распространяет **исходный код**. Шрифтовой ассет (подмножество Prism Sans SC) лицензирован по SIL OFL 1.1, **полный текст лицензии размещён вместе со шрифтом** в `src/prism-text/font_data/LICENSE`; источник ассетов и регистрация лицензий — в `Compliance/assets/资产登记.md`.
