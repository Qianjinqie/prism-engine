## Что это

Prism Engine — написанный на Rust медиадвижок без сторонних зависимостей в коде: чтение изображений,
компоновка, отрисовка кадра, монтаж таймлайна и выпуск готового материала — всё выполняется внутри
одного детерминированного движка. Все 110 зависимостей времени выполнения
(плюс ещё 20 тестовых) — это `path`-зависимости данного репозитория: без обращения к сети,
без пакетного менеджера, без рисков цепочки поставок.

Используется **дистрибуция исходников одним файлом**: весь движок (622 файла, 28 crate) объединён
в один UTF-8-текст `prism-engine-v2.0-source.txt`. Владея этим файлом, можно локально восстановить
дерево каталогов, полностью совпадающее с репозиторием.

## Что умеет движок

Обзор в одну фразу: **изображение — это кадр в определённый момент, видео — это последовательность
кадров за промежуток времени** — у одного и того же описания сцены фиксация момента даёт отдельный
кадр, а непрерывное продвижение с записью даёт видео; статичные и динамичные изображения используют
один и тот же набор возможностей. Ниже — пять блоков по принципу «что вы хотите сделать»:
**прочитать → разложить → нарисовать → выпустить → встроить в собственный инструментарий**.

### Что читает (вход)

- **Единый фасад декодирования**: одна точка входа `decode_image(bytes, ext)` распределяет статичные
  изображения — PNG (нечересстрочный 8/16 bit), baseline JPEG (фиксированный IDCT, побитово
  детерминированный на разных платформах), **приоритет магических чисел, расширение как резерв**
  (декодируется даже при неверном расширении); для форматов вне матрицы поддержки или требующих
  внешнего участия выдаётся единообразная трёхуровневая ошибка (где / что / как исправить) вместе
  с рекомендацией задействовать ffmpeg — **тихих отказов не бывает**.
- **Анимированные изображения / аудио / контейнеры**: GIF и APNG декодируются покадрово нативно
  (`prism-media`); WAV декодируется встроенно, mp3/aac/FLAC идут через путь обнаружения ffmpeg
  (`prism-audio`); чтение MP4-MJPEG (`decode_mp4_video`).
- **Полный набор для EXR**: чтение и запись, сжатие, DWA, причём с **кросс-реализационным
  сопоставлением битовых потоков** с официальным OpenEXR (а не «сами пишем — сами читаем»).
- **RAW с камер**: базовое декодирование RAW. **Граница**: для реальных DNG не реализован
  `Compression=7` (lossless JPEG), поэтому DNG с настоящих камер не читаются — это записано
  в разделе «Честные границы» и не скрывается.
- **Трёхмерные ассеты**: импорт glTF / OBJ, разбор USD (`.usda`) и пакеты параметров MaterialX;
  mesh можно помещать в сцену рендеринга.
- **Внешние шрифты**: `load_font_file` напрямую загружает сторонние TTF/OTF, цепочка резервных
  вариантов разрешается по уровням, при отсутствии глифа выдаётся понятная диагностика, а не «тофу».

### Что раскладывает (язык описания сцен)

- **Полная блочная грамматика DSL v2**: единый `.prism` описывает «что нужно, как расположить,
  как двигать, как это выглядит, во что экспортировать», а результат компиляции — граф узлов,
  каналы свойств и таймлайн.
- **Пять комбинаторов**: `title_card` / `lower_third` / `split_screen` / `ken_burns` /
  `morph_between` — высокоуровневые комбинаторы разворачиваются в граф узлов, и «90-секундный
  готовый ролик» сводится от рукописного кода сцены к сборке из блоков.
- **Переходы и morph**: Fade / Wipe / Dissolve / Push полностью параметризованы (длительность,
  сглаживание, направление), Morph деформирует ломаную, последовательность сцен можно
  сэмплировать в любой момент времени.
- **Набор формул**: `math_ast` + `math_layout` набирают верхние и нижние индексы / дроби / корни /
  крупные операторы / матрицы, блок DSL `formula` набирает напрямую и с той же базовой линией,
  что и основной текст.

### Что рисует (рендеринг и симуляция)

- **Офлайн-рендеринг фотореалистичного уровня**: трассировка путей + физически корректные BSDF
  (диффузный / зеркальный / стекло / металл), стекло и металл считаются случайной инверсией
  (монте-карловская сумма ряда Neumann), поддерживаются объёмные среды и подповерхностное рассеяние.
- **Четыре семейства криволинейных примитивов**: цилиндр / конус / тор / поверхность вращения —
  все с аналитическим пересечением (уравнение четвёртой степени через замкнутое решение Ferrari,
  точные корни); произвольный треугольный mesh + SAH-BVH, двойная проверка parity двумя путями.
- **GPU compute**: аппаратно-независимый семантический слой compute + Vulkan dispatch + вручную
  написанный минимальный SPIR-V; под программным ICD Mesa lavapipe полностью работает на платформах
  без GPU (проверяемо в headless-режиме).
- **Физика и частицы**: единый решатель XPBD (твёрдые тела / мягкие тела / ткань / сочленения /
  жидкости / разрушение), дым FLIP, система частиц (AudioReactive связан с огибающей аудио).
- **Генеративное искусство и постобработка**: поля потоков / L-system / клеточные автоматы /
  реакция-диффузия / фракталы / Voronoi; blur / bloom / halation / плёночное зерно / четыре стиля
  NPR (toon / watercolor / halftone / oil) / трёхкомпонентное шумоподавление.
- **Цветокоррекция и вектор**: вторичная цветокоррекция (HSL-выделение + кривые RGB), пресеты
  стилей cinematic / film / anime и три уровня качества — черновой/стандартный/кинематографический
  (качество — это параметр, а не магия); растеризация векторных путей, draw-on и morph путей.
- **Обработка аудио**: нормализация громкости (loudnorm), определение темпа, спектральный анализ,
  извлечение огибающей — всё может быть связано с изображением (частицы AudioReactive следуют
  за огибающей аудио).
- **CPU-бэкенд как эталон — полноправный участник**: на машинах без GPU изображения всё равно
  получаются корректными, и одновременно он служит эталоном правильности для GPU.

### Что выдаёт (доставка)

- **Прямой `render_movie`**: результат компиляции DSL v2 одним вызовом проходит путь «вычисление
  покадрово → рендеринг по tile → выдача», `.prism` превращается в готовый материал одной командой
  (`prism-app render demo.prism`); для неподдерживаемых узлов выдаётся честная ошибка без тихого
  приближения.
- **Замкнутый цикл предпросмотра**: `prism-app preview` поднимает сервис предпросмотра; в редакторе
  два режима — Draft (геометрические паттерны сохраняют частоту кадров) и Real (настоящий рендеринг
  с низким spp, асинхронное обновление).
- **Собственный кодировщик + управление битрейтом**: временной кодировщик в области JPEG с I/P-кадрами
  использует закрытый контейнер `PRMV` (две генерации схемы — v2/v3), управление битрейтом
  по принципу water-filling + субпиксельная оценка движения qpel (измерено: PSNR +2.577 dB,
  объём −21.6%).
- **Цепочка взаимодействия с ffmpeg**: есть ffmpeg → через stdin-конвейер rawvideo материал
  перекодируется в H.264/HEVC; нет ffmpeg → автоматическое понижение до MJPEG, **движок всегда
  способен выдать материал**; никакие бинарники не поставляются в комплекте.
- **Выдача последовательностей EXR**: последовательность кадров пишется сразу в EXR и уходит
  в конвейер постобработки.
- **Распределённая ферма**: распределение по кадрам + N worker-процессов + детерминированное
  слияние — параллельный MD5 == последовательный MD5, поддерживается продолжение расчёта после
  прерывания.

### Как интегрируется (экосистема)

- **Поверхность инструментов MCP**: три инструмента stdio JSON-RPC — `scene_check` (компиляция +
  пробный рендер + оценка числа кадров), `render_submit` (детерминированный job id + покадровые
  MD5-дайджесты), `diagnose` (трёхуровневая локализация ошибки).
- **SDK узлов**: согласование семантической версии (включая особый случай 0.x), вместе с пакетом
  поставляется пример пакета узлов (`examples/sdk-nodes/cinematic-basic/` — компилируется,
  загружается, согласуется).
- **Каркас обнаружения аппаратного кодирования**: `prism-ffi-hwenc` — цепочка обнаружения для трёх
  платформ (VideoToolbox / NVENC / VAAPI) + матрица feature gate; при несовпадении платформы
  явно сообщается о неподдерживаемости.

> Подробные границы возможностей (что **нельзя** сделать) — в разделе «Честные границы» файла
> `开发者指南.md` из пакета: там зафиксировано реальное текущее состояние (криволинейные примитивы
> идут только на CPU, ускорение GPU нужно измерять на целевом оборудовании, аппаратное кодирование
> подключается под целевую платформу…), а этот документ даёт лишь общую картину и ничего не приукрашивает.

## Почему дистрибуция одним файлом

- **Проверяемость**: один текстовый файл, читаемый человеком, пригодный для `diff` и проверки хешем, публикуется и замораживается.
- **Воспроизводимость**: упаковка детерминирована — два прогона на одних и тех же входных данных дают идентичный SHA-256.
- **Переносимость**: не нужно клонировать огромный репозиторий, один файл передаётся по почте или в мессенджере, и сборку можно восстановить даже офлайн.
- **О компромиссе**: дистрибуция одним файлом отдаёт удобство «просматривать код прямо на GitHub» в обмен на детерминированность «один файл несёт всё и проверяется побайтово». После распаковки получается обычный Cargo workspace, ничем не отличающийся от типичного Rust-проекта.

## Быстрый старт

Требования: установите [Rust](https://www.rust-lang.org/) (вместе с `cargo`) и [Node.js](https://nodejs.org/) 18+.

```bash
# 1. Скачайте из репозитория prism-engine-v2.0-source.txt и сохраните как локальный файл
# 2. Откройте его текстовым редактором и сохраните Node.js-скрипт, расположенный между строками
#    "UNPACK SCRIPT BEGIN" и "UNPACK SCRIPT END", в файл unpack.cjs в том же каталоге
# 3. Запустите распаковку (несколько секунд, восстанавливаются 622 файла)
node unpack.cjs
# 4. В восстановленном каталоге (это корень workspace) запустите полный набор тестов
cargo test --workspace --release
# Ожидается: 3714 passed / 0 failed
```

После распаковки получается стандартный Cargo workspace (28 crate внутри `src/`), и дальнейшие команды `cargo` работают так же, как в обычном Rust-проекте.

> Цепочка проверки wasm на мобильных устройствах: `rustup target add wasm32-unknown-unknown`, затем `cargo build -p prism-core --target wasm32-unknown-unknown`.

## Сборка и тесты

```bash
# Дымовой прогон всего репозитория (release, рекомендуется)
cargo test --workspace --release
# Эквивалентный псевдоним
cargo xtest
# Быстрая проверка одного crate
cargo test -p prism-core --release
```

- Полный набор тестов: **3714 passed / 0 failed / 0 ignored** (в этой версии прогон выполнен реально
  на **распакованном дереве**: 166 тестовых блоков; в репозитории 167 блоков, разница в 1 блок —
  это пустой тестовый блок демонстрационного crate, число тестов совпадает).
- CI: **6 job** — защита от призрачных записей (ghost-guard) / компиляция + полный набор тестов (native) /
  сборка под wasm32 (wasm) / статическая проверка WGSL (wasm-verify) / кросс-реализационное
  сопоставление битовых потоков с официальным OpenEXR (interop) / перекрёстная проверка правильности
  на node-хосте (lint).
- Локальных скриптов контроля 3 (полностью без зависимостей, только `node`, ниже) + 1 скрипт упаковки;
  из них самопроверка соответствия — **9/9 пройдено**, обратное самодоказательство — **8/8 дают
  отрицательный результат**.

Запуск локального контроля (нужен Node 18+):

```bash
node tools/ghost_guard.mjs --check        # защита от призрачных записей: G1 повторное определение / G2 строгое надмножество / G3 документация верхнего уровня / G4 компиляция
node tools/hygiene_scan.mjs               # гигиена открытого кода: построчно перечисляет оставшиеся внутренние формулировки (файл:строка), при совпадении exit 1
node tools/compliance_check.mjs           # самопроверка соответствия: должно быть 9/9 пройдено
node tools/compliance_check.mjs --self-test   # обратное самодоказательство: должно давать отрицательный результат, что доказывает различающую способность критериев
```

> **В гигиеническом сканировании открытого кода всё ещё есть накопленные совпадения**: в репозитории
> остались ранние внутренние формулировки, причём **в слое документации, входящей в пакет, они
> обнулены** (README / руководство разработчика / Compliance), а остальные находятся **в комментариях
> исходников внутри дистрибутива** и в **файлах репозитория, не входящих в пакет**; они честно
> классифицированы и вынесены в отдельные задачи по очистке. Скрипт существует именно для того,
> чтобы остатки были **видимы и устранялись построчно**, а не для вида чистоты — не воспринимайте
> «ненулевое число совпадений» как отказ контроля.

## Соответствие требованиям

Движок заявляет **нулевые сторонние зависимости в коде**, что подтверждено самопроверкой:

- **C1 Нулевые сторонние зависимости в коде**: все 130 зависимостей (110 времени выполнения + 20 тестовых) являются `path`-зависимостями данного репозитория; нет `build.rs`, нет директив нативной компоновки, `Cargo.lock` фиксирует 29 пакетов этого репозитория.
- **C2 Полнота реестра ассетов**: по всем 5 ассетам заполнены поля основной таблицы, статус собственной разработки соответствует контролируемому словарю; полный текст лицензии шрифта OFL 1.1 расположен вместе со шрифтом в `src/prism-text/font_data/LICENSE`.
- **C3 Уведомления о принадлежности третьим сторонам**: `Compliance/THIRD-PARTY-NOTICES.md` присутствует и явно разделяет «ассеты-данные ≠ зависимости в коде».

> Примечание: этот репозиторий распространяет **исходный код**. ## Детерминированная упаковка (для издателя)

Если нужно заново сгенерировать дистрибутивный TXT из полного репозитория (номер версии можно передать, по умолчанию берётся текущая версия v2.0):

```bash
node tools/pack_source_txt.mjs          # по умолчанию → dist/prism-engine-v2.0-source.txt
node tools/pack_source_txt.mjs 2.0      # эквивалентная запись (явная передача номера версии)
node tools/pack_source_txt.mjs 1.0      # имя артефакта эпохи v1.0 (при запуске на исходниках v1.0 побайтово воспроизводит старый пакет)
node tools/pack_source_txt.mjs --verify # сразу после упаковки — проверка распаковкой и обратным сравнением (побайтовое сравнение каждого файла дерева исходников)
# Запустите дважды подряд: совпадение выходного SHA-256 доказывает состоятельность детерминированной упаковки
```

Область упаковки строго ограничена: `crates/` (→ `src/`), `docs/合规/` (→ `Compliance/`), `docs/开发者指南.md`, `tools/`, `.github/`, `.cargo/`, `examples/`, `Cargo.toml`, `Cargo.lock`. Намеренно **исключены** `docs/设计/`, `target/`, `node_modules/`, сам `dist/` и любые промежуточные продукты.
