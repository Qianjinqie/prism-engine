## 1. 产品目标

V2.2 是 prism-engine 在「零未证项」之后**第一次主动扩边**，而它扩的不是能力列表，是**能力的可审计性**：GPU 四后端（CPU 参考 / Vulkan / Metal / WebGPU）从「README 只列三条路径三种状态」推到「四条都有可指认的代码，能自动验的全部自动验，验不了的逐条登记」；画质长尾从「留名」推到「有可判定切片」（光谱/降噪/材质三条各自带退化一致性与 golden）；交付边界从「README 说做不到」推到「README 每一行都能指到代码证据或结构化拒绝点」；性能与分发从「没有度量」推到「有确定性计数器与可复现报表」。**V2.2 结束时引擎不承诺「四个后端都能跑」，只承诺「每一句对外声称都有锚点，每一个未验项都有登记」——边界可以被逐条审计，而不是被叙述。**

#### 3.0.1 出口判据分层（硬纪律，先于一切）

V2.2 的交付环境是 **Linux 沙箱：无 Apple 设备、无真实 GPU（只有 lavapipe 软件光栅）、无硬件编码器**，Chromium 可用。因此：

1. **凡依赖真机的判据，一律拆两档**：`代码就绪`（CI 可判）与 `实机验证`（CI 不可判）。
2. **实机验证档不构成版本 Go/No-Go 条件**。它只以「**已交付待验**」登记（登记表格式见下），每版复述一次；连续两版未验的项，须在 README 边界表保持原措辞，**不得因为"代码写了"而改写为已完成**。
3. **反过来亦成立**：代码就绪档任一判据不通过 ⇒ **No-Go**，不得用"真机反正验不了"作豁免。
4. 若某项的全部判据都落在实机档（如 V2.2-D-1 加速比），该项**不进范围**，只登记。

### 3.1 流 A（重）：GPU 四后端收口

#### V2.2-A-1（P0）WebGPU 渲染路径实现
