## 1. 版本定位

用**能力矩阵**语言定义：每个版本回答"引擎能接住哪些活"。

### 1.1 V1.5「超级通用」—— 接住"什么活都能干"

**定义**：输入/输出闭环 + 通用语法 + 通用图元，使引擎**不存在"彻底干不了的常见活"**。

| 能力问题 | V1.5 的答案 |
|---|---|
| 素材进得来吗？ | PNG/JPEG 位图、WAV 音频内置可读；FLAC/常见容器视频经 ffmpeg 探测可读（三层矩阵见 D-6） |
| 语法够通用吗？ | Morph 变形可用、转场 ≥4 种且时长参数化，不再只有硬编码 0.5s Fade |
| 图元够通用吗？ | 3D 场景解析图元（球/盒/抛物面/平面）+ USD 资产读入路径就绪；任意三角形 mesh 与 BVH 属 V2.0 专业深度项（V2.0-H） |
| 成片出得去吗？ | 一条正式交付 API（内置 MP4/MJPEG 兜底 + ffmpeg 协作），不再靠人手敲命令行；无 ffmpeg 环境自动降级 MJPEG，引擎永远能出片 |
| 质量闸门有吗？ | 黄金解码器回归门禁（PSNR≥40dB）进 CI |
| 上手成本高吗？ | 90s 成片 = 一次 `render_film(spec)` 调用；`.prism` 单命令直达成片 |

**一句话**：V1.5 之后，"给一段素材、一段 DSL/API 描述，出一盘带声音的 MP4"成为无需绕路的最小用例。

### 1.2 V2.0「深度专业」—— 接住"专业管线里的活"

**定义**：每个维度从"能跑"进到"专业级"，使引擎**不是玩具**。

| 能力问题 | V2.0 的答案 |
|---|---|
| 渲染质量上限？ | GPU 生产管线 + 自适应采样 + 降噪，画质对标离线渲染器 |
| 物理仿真？ | prism-physics（已有 11k+ 行求解器）接入生产场景，物理镜头可排期 |
| 音频深度？ | 多轨混音总线 + 帧级音画同步 |
| 性能上限？ | 内容哈希缓存 + 分布式渲染，90s 成片从 ~35 分钟降到分钟级 |
| 交付专业度？ | 硬件编码（H.264/HEVC）真机启用，文件体积/兼容性对标行业 |
| 生态位？ | 外部字体、MCP 工具面、节点 SDK 稳定化，可作为生产管线的可嵌入组件 |

**一句话**：V2.0 之后，引擎可作为专业制作管线的候选组件，而非个人项目的渲染脚本。

## 4. V2.0 需求池（主题：深度专业）

按五个专业维度组织：**渲染质量 / 物理模拟 / 音频深度 / 性能工程 / 生态**。

### 4.1 渲染质量

| 编号 | 需求 | 优先级 | 验收标准 |

| V2.0-RQ-1 | **GPU 路径追踪生产管线**：prism-gpu compute + wasm 打通，接入生产渲染入口 | **P0** | GPU 双门禁（按 D-3 定案）：① kernel 语义级 parity 对拍——与 CPU wavefront 同输入，浮点末位差异按统计判定（均值/方差有界）；② 输出级 PSNR≥40dB + 固定 seed 采样序列 + 多次运行统计；CPU 路径维持 MD5 逐字节一致；90s 成片渲染 ≤10 分钟 |

## 6. 风险与决策点（D-1~D-6 已定案）

| # | 决策点 | 背景与选项 | 影响 | 建议 |
|---|---|---|---|---|
| **D-1** | **外部 ffmpeg 分发策略**——**已定案（2026-10-16）：不捆绑 ffmpeg** | 定案理由：捆绑 GPL/LGPL 二进制的合规争议与跨平台矩阵成本，会直接冲击引擎"零依赖、可审计、可分发"核心卖点；D-10"不自研编码器、交付走运行时 ffmpeg 探测"（`docs/开发者指南.md:1275`）延续不变。交付策略 = 探测 + 明确降级 + 文档化矩阵三件套：有 ffmpeg → 协作链出 H.264/HEVC；无 ffmpeg → 自动降级 MJPEG-AVI/MP4（引擎永远能出片，MJPEG 是兜底能力而非缺陷） | 决定 V1.5-P0-9 与 V2.0-EC-1 的工程形态；docs/合规 目录需同步记录"不分发 GPL/LGPL 二进制"立场 | 定案内容：① 不捆绑任何 ffmpeg 二进制；② extprobe 探测 + 三段式降级提示（"未检测到 ffmpeg，已降级 MJPEG 交付；安装 ffmpeg 可获 H.264/HEVC"）；③ 交付矩阵文档化（PRMV 中间格式 / ffmpeg-h264 / MJPEG 三档的能力-确定性-体积对照表）；④ docs/合规 目录同步记录"不分发 GPL/LGPL 二进制"立场 |
| **D-2** | **降噪器路线——已定案（2026-10-16）：自研降噪** | 定案理由：OIDN 为 C++ 依赖，破 D-15 运行期零第三方红线；作者拍板"自研！"。实现分两阶段落地：先时域累积（快速见效、可独立验收），再 SVGF 空域（深度），每阶段各自 golden 对拍验收 | 决定 V2.0-RQ-2 工程形态；守住运行期零第三方依赖红线 | 定案内容：① 自研两阶段（时域累积 → SVGF 空域）；② 每阶段各自 golden 对拍验收；③ 不引入 OIDN |
| **D-3** | **GPU 确定性豁免——已定案（2026-10-16）：双门禁验收** | 定案理由：GPU 浮点归约顺序非确定，与"两跑 MD5 逐字节一致"黄金基线直接冲突。GPU 路径验收 = ① kernel 语义级 parity 对拍（与 CPU wavefront 同输入，浮点末位差异按统计判定：均值/方差有界）+ ② 输出级 PSNR≥40dB + 固定 seed 采样序列 + 多次运行统计；CPU 路径维持 MD5 逐字节一致不动；交付产物分两级文档化（CPU 确定性产物 MD5 可复现 / GPU 高性能产物 PSNR 合格+统计稳定） | 决定 GPU 路径验收方式与交付产物文档分级 | 定案内容：① GPU 双门禁（kernel parity 统计对拍 + 输出级 PSNR≥40dB/固定 seed/多次运行统计）；② CPU 路径维持 MD5 逐字节一致；③ 交付产物两级文档化 |
| **D-4** | **硬件编码 FFI——已定案（2026-10-16）：独立 crate + feature gate** | 定案理由：hwenc.rs 自述"设计+骨架，Phase 4 真机启用"；FFI 绑定层放独立 crate 不破主干零依赖红线。新建 `prism-ffi-hwenc`（VideoToolbox/NVENC/VAAPI 绑定层），主干 prism-mux 保持零依赖；V2.0-M3 执行；V1.5 不捎带（V1.5 的 hwenc 只做探测链完善，不做真机编码绑定） | 决定 V2.0-M3 工程形态；V1.5 不捎带真机编码绑定 | 定案内容：① 独立 `prism-ffi-hwenc` crate + feature gate；② V2.0-M3 执行；③ V1.5 仅完善硬编探测链 |
| **D-5** | **AI 边界——已定案（2026-10-16）：维持 mock** | 定案理由：确定性契约纯度（真实 AI 引入网络/密钥/非确定性三重污染）+ 攻击面（作者是 AI 安全研究员，prompt injection/供应链攻击面与其研究关注直接冲突）。prism-ai 保持"引擎 = 纯渲染执行器"定位，仅完善 MCP 工具面；真实 AI 留 V2.5+ 专篇 | 影响生态维度范围与确定性契约纯度 | 定案内容：① V2.0 不开真实 AI 适配；② prism-ai 维持 mock，仅完善 MCP 工具面；③ 真实 AI 留 V2.5+ 专篇 |
| **D-6** | **读入三层支持矩阵——已定案（2026-10-16）：L0 内置 / L1 探测 / L2 不支持** | 定案理由：平衡"裸环境永远可用"与"不自研全部解码器"。L0 裸环境内置（零外部依赖、永远可读）：PNG 非交错 8/16bit、WAV、GIF/APNG、MP4-MJPEG 回读（V1.5-A 顺手做：自家解封装 + 自家 JPEG 解码器）；L1 ffmpeg 探测协作（无 ffmpeg → 三段式错误 + 建议）：H.264/HEVC 的 mp4/mov/webm、mp3/aac、FLAC；L2 明确不支持（如实报错）：交错 PNG、WebP、ProRes 等。矩阵写进 README 当承诺，矩阵外永不静默失败（D-17 执行化）。FLAC 归 L1 探测层（原 P0-3 内置解码相应修订）：自研 FLAC 解码器工作量与"不带 ffmpeg"策略叠加后收益有限；WAV 保内置 | 决定"通用"的成色与 V1.5-P0-3/4 边界；README 矩阵即对外承诺 | 定案内容：① L0/L1/L2 三层矩阵写进 README；② FLAC 归 L1 探测层，WAV 保内置；③ 矩阵外格式永不静默失败（D-17 执行化） |

**最大风险**（非决策但需监控）：M1 的 P0 八项（P0-7 已移出 V2.0-H）全部是地基工程，任何一项未达出口判据都会阻断后续波次；建议 M1 按波次切片（解码四件套 → 语法图元 → 门禁+交付），每波末演示并对照出口判据，未达即重评。
