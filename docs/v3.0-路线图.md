## 0. 为什么是「重新设计」

### 0.1 旧稿的性质与缺口

`docs/v2.5-v3.0-路线图.md` §5「V3.0 作者契约」是**愿景层**文档：定形态（单文件）、定语法气质（Python 级）、定 6 条出口判据。它不是工程路线图——缺能力矩阵、需求池、波次计划、依赖图、跨波红线、Go/No-Go 的量化门槛与决策点表。

更关键的是，那 6 条判据里 **4 条偏软**，按 V2.5 一路在打的「反假绿」口径（V2.5 §1.4）衡量，不足以判定通过：

| §5.4 原判据 | 软在哪 | 本文的硬化 |
|---|---|---|
| 「每项至少一个 DSL 样例，样例全部进 CI」 | **样例存在 ≠ 能力触达**：只暴露 20% 参数的封装，样例照样跑通、照样全绿 | 改为 **触达度 L2 + 参数覆盖率门禁 100%**（§1.1、§1.2），样例必须同时跑覆盖断言与负控 |
| 「Python 级可读性」 | 主观形容词，无测法 | 拆成 §4 A1 的**语法特性清单 + 错误注入集**，逐条可测 |
| 「确定性：同文件两跑逐字节」 | 只测了产物，没测**语言层求值**的确定性（求值顺序、迭代、随机播种、闭包） | §1.4 **确定性受限子集**，种子进产物哈希、求值顺序固定、`det_*` 全覆盖 |
| 「能力覆盖：§2 矩阵 39 项」 | §2 是 V2.5 的**能力有无**矩阵，不是**语言能否触达**矩阵；维度错配 | 新建 §2 **V3.0 能力触达矩阵**，用 L0–L3 分级取代五态制 |

**还有一层旧稿根本没写**：以上全部只回答「能不能把引擎能力用语言写出来」，没有一条回答「**出来的片子像不像人做的**」。V2.5 把「渲染得对」做完了，观感从来不是验收对象。本版 §3 补上这一整条质量轴。

## 1. 判定规则（V3.0 专用，先定规则再谈内容）

### 1.1 触达度分级 L0–L3（取代五态制）

V2.5 五态制回答的是「**有没有这个能力**」；V3.0 要回答的是「**语言能不能完整触达这个能力**」。维度不同，不能沿用——否则「引擎已对齐」会被误读成「语言已暴露」，这正是最容易假绿的地方。

| 级 | 定义 | 可测判据形式 |
|---|---|---|
| **L0** | 不可表达：该能力在语言里连声明都写不出 | 写该能力的 `.prism` → 明确的 `R5xxx` / `W1001`，不是崩溃也不是静默 |
| **L1** | 可声明但残缺：参数不全，或求值链未贯通 | 参数覆盖率 < 100%，或仍走 `R5010` 拒绝，或产物与引擎直接调用有差异 |
| **L2** | **完整表达**：引擎侧公开参数全集 ≡ 语言侧字段全集，求值链贯通，且与引擎直接调用**同源对拍逐字节** | 覆盖率门禁 = 100% + 对拍 `0 差异` + 负控必 FAIL（三条同时） |
| **L3** | L2 + **时序可驱动**：时间轴 / 关键帧 / 命名通道能改这个参数，且改后帧值可断言 | 两帧取到不同参数值，且逐帧值与解析式对拍一致 |

**出口口径**：A 系列所有 P0 能力项 ≥ **L2**；核心项（相机、材质、光源、几何、时间线、后处理）须达 **L3**。

> **维度边界**：L 级只衡量「语言能否触达能力」。**观感不是能力项，不用 L 级**，走 §1.6 + §3.5 独立判据。把观感塞进 L 级就是本文自己批判的维度错配。

### 1.2 参数覆盖率门禁（把「能力不打折」变成可测）

对矩阵每一行，取**引擎侧公开 API 的参数全集**与**语言侧字段集合**做差：

```
| params(api) \ fields(dsl) | = 0    （每个缺项必须挂一条正式裁定编号，否则门禁红）
```

门禁形态：一张 39 行的规格表，每行 `api_path / api_params / dsl_fields / exempt_ruling`，静态测试遍历全表；**缺映射且无裁定 ⇒ 编译期红**。这防的是「样例跑了、字段其实只有默认值」这一类假绿。

### 1.3 反假绿三条（语言层新增，继承 V2.5 §1.4）

1. **样例存在 ≠ 触达**：CI 中每个样例必须**同时**跑参数覆盖断言；只跑通不算过。
2. **同源对拍**：语言求值产物 ≡ **直接调用引擎 API** 构造同一场景的产物，逐字节。禁止「语言自己再算一遍然后比自己」——两端同错不构成证据。
3. **负控注入**：故意写错参数、漏必填字段、传非法值，必须 FAIL 且给行号；**静默取默认 = 该波 No-Go**。沿 `render_cli.rs:110-111` 已有的「R5010 + 节点类型」断言风格。

### 1.4 确定性受限子集（V3.0 最大难点）

语言一旦有表达式与函数，就引入了 V2.5 从未面对的求值顺序问题。硬约束：

- **白名单语义**：无系统时间、无网络、无文件写、无环境变量读取、无隐式全局状态；无 `while` / 无界递归 / 通用 IO（**不做图灵完备**，见 D-23）。
- **随机显式播种**：种子必须是文件里的一等字段，且进产物哈希；底层沿用 `prism-core/src/eval.rs:592-611` 的 `hash_mix(seed, node_id, frame, pixel, sample, dimension)`，不新造随机源。
- **浮点确定性**：所有超越函数走 `prism-math/src/det_pow.rs` 与 `colorspace_registry.rs:220` 的 `det_*` 族；超出覆盖面的函数**先补实现再开放语法**（不许借平台 libm）。
- **求值顺序固定**：表达式 AST 求值是左→右深度优先、容器迭代按声明序、`for` 展开上界必须编译期可判定。
- **同文件同种子两跑逐字节一致**，CPU 与 GPU 两腿分别验（GPU 按 D-3 双门禁）。

### 1.5 未点亮（继承 V2.5 §1.3，三条同时）

真 GPU / Apple Silicon / 硬件编码等环境项照 V2.5 口径保留，三处同步标注 + 复验触发条件，**不在 V3.0 重开**。V3.0 新增能力若需设备验证，同样按此登记，不写「支持」。

### 1.6 观感判定总纲（本版新立）

观感是**横切全部能力的输出品质轴**，不是第 40 项能力。它的判定对象是「**产物是否忠实于用户显式声明的档位**」，不是「有没有痕迹」。三条总则：

1. **双档一等**：`finish = analytic | crafted` 是文件里的一等字段、进产物哈希；**不替用户默认选**（漏填即静态报错，沿用红线 3）。`analytic`（纯净匀质）与 `crafted`（像人搓的）**都是交付物，都不是失败**。
2. **靶子是声明一致性**：不测「有没有塑料感」这种主观形容词，测「声明的档位与产物是否一致」「痕迹是否注入在生成源头」「噪声是否种子化确定性」「盲测是否显著」。
3. **完整规格见 §3**（塑料感诊断、痕迹维度清单、两条治本禁令、§3.5 判据全套），出口判据落在 §7 #10。

## 3. 观感体系（W3 独立波，本版新立）

> 作者 2026-11-06 原话：「必须要做到看起来不能像是代码生成而像是搓的一样，目前代码生成的视频，我觉得就是塑料感。比如说 HTML，他的视频就一股塑料感，一眼就能看出来即便加上 CSS 等也一样」；「必须是可选择的，如果用户就要匀质，就要均匀呢？」

### 3.1 塑料感的诊断：不是没装饰，是生成逻辑太干净

**「加 CSS 也一样」是本节的关键证据**——它证明塑料感不在表面装饰，而在**生成逻辑本身是解析的、完美的、无介质的**。所以出完帧再贴一层 grain / 滤镜 / 色调模板救不了，那正是 CSS 的等价物。

| 层 | 代码生成的默认样子 | 「搓出来的」样子 | 仓库现状触点 |
|---|---|---|---|
| 运动 | 匀速 / 标准 easing | 有惯性、犹豫、微抖、呼吸 | `prism-author/src/easing.rs`（现成缓动族） |
| 几何 | 正圆、笔直、完美对称 | 受控的手工不完美、微不对称 | `prism-genart/src/generators.rs:145`（`pcg::hash2_f32` 种子化 `jitter`）、`:371` `site_jitter` |
| 材质 / 光照 | 干净均匀、无瑕疵 | 微表面、划痕、脏污、漏光、色偏 | `prism-rt` 材质 + 纹理（W2 接入）；`prism-postfx/src/effects/film.rs`（halation + 分层 bloom + 胶片曲线 + 科学化颗粒）、`ca.rs`、`vignette.rs`、`dof_full.rs` |
| 时间 / 镜头 | 帧率齐整、快门「太正确」 | 快门角度、运动模糊、辉光溢出 | `film.rs` / `bloom.rs` / `blur.rs` |
| 构图 / 色彩意图 | 居中、对称、留白规整 | 有意图的取舍、三分线、色调倾向 | `prism-aesthetic/src/critic.rs`（曝光/对比/色彩/清晰度/构图 **五维可计算指标** + `Rubric` + `Target`）；CLI 已接 `prism-app/src/cmd_critique.rs` |
| 剪辑 / 音画 | 卡点齐整、节拍器对齐 | 不等长的呼吸、人在操作的取舍 | `prism-audio/src/beats.rs`（`detect_beats`）、`score.rs`（`compose` / `mood_scale` / `compose_pieces`）、`harmony.rs`（`progression` / `voice_lead`）、`reactive.rs`（`bake_reactive` 音画同源、状态可重建） |

> **最重要的事实判断**：上面几乎所有能力**都已经在仓库里**（`prism-aesthetic` 2410 行 / `prism-genart` 1206 行 / `prism-postfx` 7659 行 / `prism-audio` 7702 行 / `prism-author` 5882 行），而且全部卡在「**引擎有、CLI 有、DSL 没接**」——**与 V2.5 补遗漏时的病根完全一致**。W3 是接线 + 立判据，不是从零造质感引擎。

### 3.2 一等档位：匀质与搓感都是交付物

`finish` 是 `.prism` 文件的一等字段，**进产物哈希**（§1.4），两档语义：

| 档位 | 语义 | 硬判据 |
|---|---|---|
| `analytic` | **纯净匀质**：所有痕迹维度强度 = 0，产物严格等于纯解析基线 | 与解析式 / 引擎直接调用**同源对拍逐字节**；全帧无任何意外噪点（防「为了去塑料感偷偷全局加噪」） |
| `crafted` | **像人搓的**：按声明的维度与强度把痕迹注入生成源头 | 每个已声明维度在**求值链**里可静态检出、帧值与注入量对拍一致；盲测胜率过门槛（§3.5） |

- **每个痕迹维度独立开关 + 强度，且都能设 0**；用户要「只有运动带呼吸、几何绝对匀质」必须能表达。
- **不替用户默认选**：新语法（`// prism-dsl 2`）下漏填 `finish` 或写非法值 ⇒ 静态报错带行号（红线 3 / §7 #5），**不取默认**。
- **零损失兼容**：`// prism-dsl 1` 旧文件按版本化语义视为 `analytic`（历史行为），永久可解析、逐字节同帧（D-24）。这不是「取默认」，是版本契约——旧文件本来就没有任何痕迹注入，语义与 `analytic` 恒等。

### 3.3 两条治本禁令（钉死，违反即 W3 No-Go）

1. **禁止 post-hoc 贴皮**：痕迹必须在**生成源头**（运动 / 几何 / 材质 / 光照 / 时间 / 镜头 / 音画的求值链）注入，不许出完帧再在帧缓冲上贴 grain / 滤镜 / 色调模板冒充。
   - 现成反例：`crates/prism-dsl/src/codegen.rs:2810` 的 `post { bloom, grain, vignette, chromatic }` 把 `grain` 建成 S4 双尺度颗粒**帧后效果节点**（`:2790`）——**它是负控的标准样本，不是 W3 的实现**。W3 若只是把这个字段调大，静态门禁必须判红。
2. **不规则必须种子化确定性噪声**：所有「抖动 / 呼吸 / 微扰」走 `eval.rs:592-611` 的 `hash_mix` 或 `prism-genart/generators.rs:145` 的 `pcg::hash2_f32`，**零真随机、零平台 libm**，两跑逐字节。视觉上伪随机、计算上确定——去塑料感与确定性红线不冲突，冲突的是真随机。

### 3.4 痕迹维度清单（可注入、可计数、有开关）

W3 定桩时冻结下表（**逐行给 `注入点:行` 与 `字段`，不写「待核验」**），这是 §3.5 判据的执行体：

```
| 维度 | 引擎触点 | 注入点（生成源，禁止填 postfx 末端） | dsl 字段 | 强度范围 | analytic 值 |
```

六个维度族：**运动 / 几何 / 材质光照 / 时间镜头 / 构图色彩 / 剪辑音画**。每族至少一条可静态检出的注入断言与一条帧值对拍断言。

### 3.5 W3 判据（靶子 = 声明一致性 + 实现合规，不是主观审美）

| # | 判据 | 验证方式 | 门槛 |
|---|---|---|---|
| **V1** | **档位忠实** | `analytic` 对拍纯解析基线；`crafted` 逐维度静态检出 + 帧值对拍 | `analytic` 逐字节 ≡ 基线且零意外噪点；`crafted` 每个已声明维度非零且与声明强度一致 |
| **V2** | **负控（盯实现违规，与用户选哪档无关）** | ①把痕迹从生成源挪到帧后贴皮 ②用真随机替代种子化噪声 ③声明 `crafted` 实际全 0 ④漏填 / 非法 `finish` ⑤改某维度强度而帧不变（字段没接） | **五种全部 FAIL 且带行号**；④另须三段式报错 |
| **V3** | **成对盲测** | **只在 `crafted` 档跑**：A = 同场景 `analytic`、B = 同场景 `crafted`，固定样本池 / 种子 / 协议，判「哪个更像人搓的」 | 胜率过门槛（**样本数与门槛值由 W3 定桩冻结并显式记录，此处不编数字**）；同时用 `prism-aesthetic::critic` 五维做客观侧证，主客观双证都要 |
| **V4** | **匀质同样是能力** | 用户显式要匀质的场景，`analytic` 出片与解析式对拍 | 逐字节一致、无全局加噪；**不因「不够搓」被判失败** |
| **V5** | **同源对拍** | 语言声明 ≡ 直接调引擎 API 构造同一观感配置 | 逐字节（§1.3 第 2 条） |
| **V6** | **确定性 + 零损失** | 两跑逐字节；既有 `.prism` 与 golden | 逐字节同帧（§1.4、§7 #6） |

> **反假绿要点**：V3 盲测只证明「`crafted` 档确实有效」，**不证明也不要求所有片子都得搓**；选 `analytic` 时根本不跑盲测。禁止「我看过觉得像搓的」当判据——主观侧证必须走固定协议的盲测，客观侧证走 critic 的可计算指标。

### 3.6 与既有裁定的边界

- **不重开 C2**：C2 是「交付层编码桥」（H.264/HEVC 硬编、容器适配），已裁定不做；W3 的「视频直接相关」指**剪辑节奏、转场、镜头语言、传感器/介质响应、音画呼吸**这些创作层内容，两者不是一回事。
- **不重做棱镜里已有的编码器**：MJPEG-in-MP4/AVI、EXR/PNG/JPEG/DNG 保持 V2.5 终态。
- **不把 `prism-ffi-hwenc` / P-5 混进来**：那是平台能力项（未点亮），与观感无关。

### 5.1 时间盒与节奏

## 6. 四条跨波红线（V3.0 专用）

> V2.5 §4.4 有两条红线（预览不得另起近似路径、每波结束可停）。V3.0 的语言层风险更大，先扩到三条，本版因观感轴再补第四条。

1. **语言层不得成为第二事实源。** 所有求值下沉到既有 crate（`prism-rt` / `prism-particles` / `prism-physics` / `prism-audio` / `prism-postfx` / `prism-aesthetic` / `prism-math`），语言只做声明、编译与调度，**禁止在语言层重实现任何数学、渲染或质感**。判据：同源对拍逐字节（§1.3 第 2 条）。这是 V2.5「预览必须同一渲染器」红线在全语言层的推广。
2. **每一波结束必须可停。** ①零损失：旧 `.prism` 与全部既有 golden 逐字节同帧；②**语法特性不许半截**——一个特性要么全做（正例 + 负控 + 报错 + 文档），要么不做且明确拒绝，不许出现「部分支持」「某些情况可用」。不留半截 ABI、不留只改一个后端的中间态。
3. **不许静默降级、不许取默认。** 未知节点、非法值、漏必填字段、超范围参数一律 `R5xxx` / 新错误码三段式报错并给行号；**绝不取默认值蒙混过关**。这是 `v2-节点覆盖盘点.md` §0「绝不静默跳过」纪律提升为红线，也是防「参数覆盖率假绿」的最后一道闸。
4. **观感不许贴皮、不许偷加噪、不许替用户选档。** ①痕迹只在生成源头注入，出帧后贴 grain / 滤镜 / 色调模板冒充 ⇒ W3 No-Go；②所有不规则必须种子化确定性噪声，真随机 ⇒ 两跑判 FAIL；③`finish` 必须显式声明，漏填 / 非法值静态报错，**匀质与搓感都不许默认**；④不许为「去塑料感」给 `analytic` 全局加噪。
