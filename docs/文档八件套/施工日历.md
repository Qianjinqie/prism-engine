# Prism Engine 施工日历（v4.4 · 低并行度 × 7 天窗口）

> 基准：**2026-10-01 开工**，总窗口 **7 天（10/1 – 10/7）**，修复往返窗至 10/10。
> 校准史：v1.0 排 21 天 → 用户以旧引擎实证否决；v2.0 压至 8 天；v3.0 流式执行 5 天 → **v4.0：用户裁定 5–7 天对 Agent 军团仍是富余，改为降低一次性并行 agent 数量以减轻钱包压力，"实际上还是 7"**——用时间换并发成本。
> **并行度纪律（D-19）：一次性在线 agent 峰值 ≤3 路**（多数波次 2–3 路，合并/QA 时 1–2 路）；波次间尽量复用 agent 会话（减少上下文重建开销）。总工作量不变，省的是并发峰值。
> **产能基准（D-25 军团产能模型）：单 Agent 任务明确写 1000 行代码不需小时级；峰值 3 路并行 = 3000 行/批不需小时级；一天可多次召唤 ⇒ 日产能万行级；④批次耗时 = 最长 Agent 的耗时（max 非加和）——切块均衡、先完成先回收**——波次容量按此校准，提前完成的机动位优先还账（账四 10/1–10/2、账二待令）；产能前提是任务明确，开工前必读对应文档章节（做什么=路线图 / 怎么算=白皮书 / 本体=架构 / 怎么不出事=宪章）。
> 真正的节拍器：**逻辑依赖串行**（A1 未绿则波 2 不开工）+ **手机往返的人类延迟**。
> 配套文档：《强大版路线图.md》（验收标准全文，D-1~D-30）、《兼容性宪章.md》、《架构总设计.md》（v2.4 双视图×自定义光谱）、《算法白皮书.md》（v1.3，含数学附录 §25+§26）、《差距账本.md》（v2.3 平账收官）。
