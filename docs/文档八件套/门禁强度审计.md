## 0. 判定标准（本表使用的口径）

沿用本项目「假绿」定义：**断言存在，但断言与真实执行脱节**。

| 强度 | 判据 |
|---|---|
| ✅ **强** | 断言挂在真实 dispatch / 真实 I/O / 真实编译结果上，**且失败会红**，含反向自证 |
| ⚠️ **弱** | 只检查"字段存在 / 格式合法"而未检查值域，或容差宽到能掩盖空转 |
| ❌ **假绿** | 断言与执行脱节（校验了一个恒为真的量 / 静默短路 / `\|\| true` 式通过） |
| 📐 **结构级** | 定位本就是结构自检，**不冒充**真 dispatch 级；职责分层，不算缺陷 |

**为什么要建这张表**：事故 I（`hair_scatter.wgsl` 编译不过却全绿）、事故 II
（`rt_scene` bindgroup 失效却回读零值）、事故 III（zlib 尾部校验用压缩后长度比
解压后长度）——**三次都栽在"绿灯与执行脱节"上**。而"门禁全绿"这四个字本身
**不能**作为"代码真跑过"的证据，必须逐条挂钩。

## 3. 本波修掉的弱断言（1 条）

### 3.1 `host_test.mjs:721-733` —— 真机 GI 指纹只判"格式合法"

| 项 | 内容 |
|---|---|
| **原断言** | `fp !== null && /^[0-9a-f]{8}$/.test(fp)` —— 只检查"上报了 8 位十六进制" |
| **为何是弱** | **恒可通过**。`0x00000000` 也照样绿。而事故 II 的形态恰恰是"submit 无效 → dispatch 没跑 → 回读拿到零初始化缓冲"。**这条断言无法区分"跑过"和"没跑"** |
| **实测依据** | WebGPU 新建缓冲**零初始化**。"没跑"时的指纹是**可计算的定值**：`FNV-1a32(93 个 u32 全 0)`（= 3 探针×9 SH×RGB + 4 查询点×RGB）= **`0x06a083d5`**。真机实测指纹 `0x87ac3cf3`、CPU 锚 `0xaf8429a3`，三者两两不同 |
| **修法** | 新增 `giFingerprintLooksIdle()`：指纹等于 `0x06a083d5`（空转特征值）或 `0x00000000`（恒零）或字段缺失/格式非法 → 判红 |
| **反向用例** | `host_test.mjs --self-test`（**7 例，0 失败**）：喂 `0x06a083d5` / `0x00000000` / `null` / `0x1a2` 四种坏值**全部判红**；喂 `0x87ac3cf3` / `0xaf8429a3` 两种真跑过形态**放行**；附1 例判据区分力检查 |
| **强度** | ✅ 强（由 ⚠️ 弱升级） |

**为什么这条判据不会误伤真机**：判据只排除"全零"这一个点，**不与 CPU 锚比较**，

## 4. 新增规则 F20（4 条 · 强）

**名称**：`F20 //!include 依赖图无环 + 引用存在性`
**位置**：`wgsl_lint.mjs:1797-1894`（`ruleF20`），经 `ruleF` 末尾并入主流程（`:1628`）

### 4.1 为什么选这条规则（理由）

任务书候选为"LIBRARIES 库件的 `//!include` 依赖图无环 + 引用文件存在性"。我采纳该候选，
理由是**它堵的正是事故 I 的同族形态，且此前完全无门禁**：

两处展开器对坏依赖图的处理都是**静默**的——
- `wgsl_lint.mjs::expandShaderIncludes`：`if (!existsSync(p)) return "";`
- `shaders.rs::expand_into`：`let Some(src) = source(name) else { return; };`

后果：把 `//!include rt_common.wgsl` 改成 `rt_commonn.wgsl`（少一个字母），或让
A include B、B include A，两处展开器都**安安静静少拼一段源码**，编译照过、门禁照绿，
而真机拿到的是一份**缺声明**的模块。

**为什么真机未必立刻炸**：缺声明时报的是 `unresolved_symbols`（规则 A 的符号可解析性），
而它**只在"缺的符号确实被调用"时**才报。若被丢掉的 include 贡献的是常量、struct
或当前路径未用到的函数，**连符号检查都抓不到**。这正是"断言与真实执行脱节"的第四种形态。

**环更严重**：两处展开器都靠 `visited` 集合截断环，展开结果因此**依赖遍历顺序**——
直接违反全链路确定性铁律，且真机报错往往指向一个与环毫无关系的符号。

### 4.2 判据（4 条）

| 文件:行 | 断言 | 强度 | 依据 |
|---|---|---|---|
| `:1840` | 每条 `//!include` 引用的文件**真实存在** | ✅ 强 | 当前 12 条边全部有落点；悬空即红 |
| `:1875` | `//!include` 依赖图**无环**（三色 DFS，回边即环） | ✅ 强 | 展开结果与遍历顺序无关 = 确定性 |
| `:1882` | `//!include` 指令**格式合法**（独占一行、单个文件名） | ✅ 强 | 格式非法的行会被展开器当普通行拼进 WGSL 源码 |
| `:1889` | **非空集**（≥1 份 shader 且 ≥1 条边） | ✅ 强 | 防空集恒真——F20 若一条边都没比，就是恒真门禁 |

### 4.3 反向自证（5 例，全部判红）

`wgsl_lint --self-test` 38 → **43**，5 例新用例：

| # | 注入的破坏 | 预期红点 | 实测 |
|---|---|---|---|

### 5.1 #4 `gpu.gi_compute` 真机分支只断言"指纹在场" —— **站得住**，但注释有一处不准确

| 复核项 | 结论 |

## 7. 诚实边界（未验证项 · 禁止夸大）

1. **SwiftShader ≠ 真 GPU**。本波真机验证跑在 **SwiftShader**（`adapter=google /
   arch=swiftshader / SwiftShader Device (Subzero)`）上——这是 **CPU 光栅化**，
   **不是**真实独立显卡。故一切"真机"结论只证明「链路正确 + 数值一致」，
   **不构成性能凭据**，也不能推断真实 GPU 驱动的行为（尤其是 FMA 收缩、
   纹理过滤与后端差异）。
2. **真机逐位一致性未验证、且结构上不可验证**。GI 指纹 GPU `0x87ac3cf3`
