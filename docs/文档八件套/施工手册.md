## §2 代码组织规范

### 2.1 crate 依赖方向（架构 §6.3，无环）

依赖方向（依赖者→被依赖者，架构 §6.3 同款读法）：**L2 依赖 L1，L3 依赖 L2（及 prism-gpu），L4 依赖 L3，L5 依赖 L4**；prism-gpu 依赖 prism-math，被 GPU-only 宿主与 prism-render 调用。自下而上：`prism-math(L1 结构层) · prism-gpu(骨架)` ← `prism-core(L2 注册表/调度/签名/alias)` ← `L3 特解宿主（noise·anim·geometry·texture·rt·physics·postfx·audio·text·raster·particles·genart·vector·media·ai·aesthetic）` ← `L4 声明面与出口（dsl·io·render·mux·infra）` ← `prism-app(L5)`。

- **L1 不依赖任何上层**；出现反向引用 = 架构违规，合并审查打回（§5.3）。
- 现状 7 crate（math/gpu/core/dsl/io/render/app）职责见架构 §6.2；M0/M1 已验证资产零损迁移、不得回退（架构 §8.1 资产安放表）。

### 2.2 模块组织

- **12 结构 = 1 个接口 crate + N 个特解宿主**（架构 §6）：结构 trait 与格类型只写进 prism-math；特解实现落对应宿主 crate（查架构 §6.1 映射表、§7 工作流映射表定位），禁止在 prism-math 堆功能特解（**纯函数数学件除外**：ACES 拟合、确定性超越函数等属 L1 数学层，落 prism-math 名正言顺）。
- **新文件落位**：一律以路线图对应工作流"新增/修改文件"列为准（路线图 §4 Phase 表），不自创位置、不碰任务清单外文件。
- **公开 API 面最小化（D-16）**：模块间只暴露工作流清单列出的接口；多余 `pub` 不许合入。
- **禁旁路**：一切硬实力必须以可组合节点暴露，禁焊死旁路管线（D-1 铁律）；GPU-only 项只做设计+骨架（D-4）；编解码外部协作走运行时探测降级，不做代码依赖（D-10/D-17）。

### 2.3 命名约定

| 词汇面 | 规则 | 来源 |
|--------|------|------|
| 官方预置面（DSL 名/参数名/报错/`--help`/MCP 描述/用户文档） | 只用创作词汇；行业已有概念照抄行业词，自造词必须挂行业锚点并过"命名三问" | 宪章 C4/C5、架构 §2.5 |
| 官方别名注册 | **单一出口** prism-core `alias.rs`（条目 = 友好名+StructureId+预置参数包+schema+行业对照）；codegen/报错/MCP/文档全由它生成，映射禁止散落 | 架构 §2.1/§8.3 |
| 内核词汇（S1–S12/核/对偶/格/求逆…） | 合法居所 = crate 代码与注释、贡献者文档、施工指令、opt-in 自定义通道；出现在官方预置面 = 流程事故，CI 结构化断言拦截 | 架构 §2.5-3/4、§8.3 |
| 自定义组件命名 | 自由归开发者，不做行业对照强制——opt-in 通道 = 显式责任边界（类比 unsafe），非错误 | D-23、架构 §2.5-5 |
| Rust API 角度参数 | 弧度一律 `_rad` 后缀或 `Angle` 类型，禁裸 f64 角度参数；单位字面量必带单位 | 宪章 C17 |
| 全局文本/路径 | UTF-8、路径 `/` 分隔、写盘 LF、容器端序按各格式标准、禁硬编码核数/内存/路径假设（按 4 核 8G 规划） | 宪章 C24 |

## §3 实现模板

### 3.1 新特解标准写法（L3 特解级；官方特解同构，仅注册通道不同）

> 决策锚（D-22）：新功能 = 新特解，内核零改动——本模板即"加一个特解"的全部动作，调度器一行不改（架构 §4）。

步骤清单（Rust 代码示意见架构 §2.6.2，此处不重抄）：

1. **定义**：宿主/用户 crate 内普通 Rust 代码 `struct X;` + `impl MathStructure`——实现 `meta()` 与能力面内的 `apply / invert / sample` 三操作（架构 §3.3）；实现只准用 prism-math / prism-core 原语，禁拉外部 crate（架构 §2.6.3 护栏一）。
2. **三问 meta**（`StructureMeta` 三字段）：`kernel: KernelKind`（问一：核是什么）+ `duality: DualityPair`（问二：配对哪一侧）+ `lattice: LatticePlan`（问三：格锚了吗）——**不齐注册表拒绝**，编译期结构化报错（白皮书 §25.5 纪律 1、架构 §3.2）。三问由特解作者填写，使用者无感（架构 §3.2）。
3. **注册**：官方特解经 `alias.rs` 单一出口（友好名 = 预置参数包，创作词汇）；自定义经 `registry! { structure X => custom(N); }`（`macro_rules!` 编译期收集，**禁 inventory/proc-macro 等第三方方案**）——双通道汇入同一注册表，运行时无差别（架构 §2.6.2）。`StructureId` 官方段 1–12，用户段 S13+ 按 crate 名隔离冲突（架构 §2.6.1）。
4. **确定性自检**：一切随机只准 `hash(全局种子, 节点id, 帧号, 样本索引[, 维度])` 派生，**禁私开 RNG**；实现只依赖 `EvalCtx` 注入的上下文（架构 §4.4）。
5. **免费红利自证**：参数进图签名 → 缓存/增量/逐字节复现自动覆盖；不许另建缓存或绕过签名缓存（架构 §2.6.3 护栏四、§4.2）。

**生命周期（D-23 v2 补记）**：定义 → 注册 → 往后使用（此后 DSL 按名写、L2 数据包引用、代码直构皆可，调度器只认 StructureId 不认来源）。存档图按名记录、读档按当前程序注册表解析——**缺定义 = 明确结构化报错，绝不静默降级**。
**逐级 opt-in**：参数级/组合级能解决的不进特解级/结构级——皮肤解决的事不惊动骨骼（架构 §2.5-6、§2.6.1 四级光谱表）；L4 结构级另须通过结构性质测试套件验收并附贡献者文档（架构 §2.6.1）。

### 3.2 新 L2 数据包要点（数据即组件，D-8）

- 目录结构：`manifest.toml` + `presets/*.prism` + `subgraphs/*.prism` + `assets/`（路线图 §2.4）；**纯数据、无动态代码加载**。
- manifest 必填：`name`（kebab-case）、semver、许可证白名单、**引擎版本区间 `engine = ">=x.y, <x.z"`（强制字段）**——区间外拒绝加载并给出"该包需要引擎 x.y–z.w，当前 a.b.c"（宪章 C12、验收 V9）。
- 数据包引用自定义特解：加载期校验三问齐备 + C12 区间（架构 §2.6.1 L1/L2 协议要点）。
- 引擎内部格式（.prismir 图缓存/tile 缓存/快照/cache.json）三条件：文件头带格式与引擎版本号 + 公开 schema（或 CLI 一键转 JSON）+ 版本废弃静默失效重建——**缓存失效 ≠ 用户数据丢失**；缓存键含 (schema_version, engine_version)（宪章 C8/C13、验收 V10/V11）。
- 官方数据包与引擎同版本号发布（宪章 C12）。

### 3.3 三段式结构化报错模板（宪章 C18/C19）

```text
error[P1xxx] file.prism:7:11          ← 第一段【在哪】file:line:col
  检测到的事实（可附历史教训链接，作为可选第四段【为什么】）   ← 第二段【什么事】
  建议：给出可直接粘贴的修复写法                      ← 第三段【怎么补】
```

- 错误码分段：P1xxx 防呆参数 / P2xxx 类型语法 / P3xxx 图结构（环、悬空引用）/ P4xxx 资产 IO / W1xxx 警告（宪章 C18）。
- **无"建议"段的错误不许合入**——编译器测试集结构化断言每条 error/warning 含建议段，不靠人审（宪章 C19、验收 V7）。
- 默认全部报错，静默容错只能进 `docs/silent-fallbacks.md` 白名单（每条带 WL 编号：歧义/引擎选择/理由/显式规避写法）；白名单外一切静默行为 = bug（宪章 C20、验收 V8）。
- **禁危险默认值**：默认不得掩盖错误（禁"默认 0 秒""默认 1×1"式兜底）；无合理默认必须显式必填；默认值变更 = 渲染行为变化，进 changelog 清单（宪章 C21）。
- **教训入库**：每个已发生事故必须转化为一条防呆规则或验收项，不许只活在回忆里（宪章 C3）。

## §4 测试规范

### 4.1 golden-file 写法与落位

- golden 期望文件是**测试资产**：随测试代码同库管理、逐字节只读；同参数重跑必须 md5 全等，不满足即先查实现再查期望。
- golden 期望的任何变更 = 渲染行为变化 → 逐条对应 changelog《渲染行为变化清单》（宪章 C15、验收 V17），变更说明必须给出原因与影响面。
- 渲染验证过程产物（对照图/中间帧/GIF）一律进隐藏工作区，禁止散落项目目录（路线图 §8）。
- 每个新效果/特性交付必带 golden 或专项断言——关卡不降价，验收标准逐字不变（路线图 §4 各 Phase 验收、日历纪律 2"关卡不降价"）。

### 4.2 确定性验收判据（全链路逐字节）

| 判据 | 操作化 | 来源 |
|------|--------|------|
| 双遍一致性 | 同版本同输入渲染两遍：全帧 + WAV + 容器 md5 全一致，进 CI | 路线图 §2.3、宪章 V18 |
| tile ≡ 整幅 | 16×9 tile 拼接与整幅渲染逐字节一致（须含一个 halo 型全帧效果用例） | 路线图 Phase 1 验收 2、架构 §4.3 |
| **并行 ≡ 串行** | 同种子同图：并行求值 md5 == 串行求值 md5，**逐位**；一切浮点归约走唯一形状函数 `reduction_shape(n)`（prism-core 单点定义），禁私定结合序；无序集合（碰撞对/邻居列表）先按节点 id 排序再处理；分布式分片按同一形状函数切分 | 白皮书 §26 工程四律 + 验收判据（10/2 基座首个验收项） |
| seek 等价 | 跳第 N 帧结果 ≡ 顺序推进到第 N 帧——模拟快照与视频时间映射同判据 | 路线图 Phase 2 验收 3、B11 验收 |
| 格锚纪律 | 种子/节点id/帧号/样本索引/迭代计数入 Zᵏ 整数运算；定点相位 Q32.32 禁浮点相位；浮点只允许格点间局部插值；hash 禁浮点三角（sin 大数法）；fma 全局统一开或关 | 架构 §4.3 格锚定规则表 |
| 结构性质测试 | 按核类各做一次：S1 平移不变/归一、S9 插值端点命中、S7 解析解 vs RK <1e-3、S4 样本流纯函数性（同索引同值、无状态） | 白皮书 §25.5 纪律 4、架构 §8.4 |
| 格式往返 | 每个对外格式一条解析/编码往返测试，编码器与解析器互为对方写测试 | 宪章 V12 |

### 4.3 验收测试挂接宪章 V 项

- 挂接总表 = 宪章修订点 **R7**：A4←V1/V2/V5/V6/V7/V8/V9；A6←V10/V11；B3/B4/B5/B6/B10←V12 相应格式项；C2←V12(PNG16)；C4←V12(JPEG 往返)/V13/V14；B2←V12(HDRI)；C6←V16；全程←V17/V19/V20。

## §5 施工 SOP

### 5.1 派工指令模板（标准任务包）

```markdown
【任务包 W?-?】<工作流编号 + 名称>（例：B1 路径追踪 CpuRef）

  ② 白皮书对应 §（怎么算——架构 §7 工作流映射表给出特解锚）
  ③ 架构对应 §（本体落位——结构/宿主 crate/组合方式）
  ④ 宪章挂接 V 项（怎么不出事——R7 挂接表）
- 文件清单：<照抄路线图该工作流"新增/修改文件"列，禁自创位置>
- 关卡（逐条可测试）：<路线图 Phase 验收对应款 + 日历波次关卡 + 挂接 Vxx 编号>

  过程产物进 /root/media-engine-archive/（路线图 §8）
```

### 5.2 完工自检单（Agent 交活前逐项过，全绿才许报完工）

1. [ ] 关卡判据逐条绿：md5 双遍一致 / golden / 专项断言 / 挂接 V 项各就位（§4）；
2. [ ] 新特解三问 meta 齐备、注册通道正确（alias.rs 或 registry!）、无私开 RNG（§3.1）；
3. [ ] Mini Code 五判据过：重复模式已抽取复用 / 无死代码 / 无过度防御 / 无 YAGNI 式提前抽象 / 公开 API 面最小（D-16）；"简化导致质量下降"= 违规；
4. [ ] 官方预置面零内核词汇泄漏（对照架构 §2.4 可见性边界表，与 CI 断言同判据）；
5. [ ] 一切错误/警告三段式且含"建议"段；无白名单外静默行为；无危险默认值（宪章 C18/C19/C20/C21）；
6. [ ] 零第三方依赖新增；crate 依赖方向无环、L1 无反向依赖（§2.1）；
7. [ ] 平台中立：无硬编码 `\` 路径、无核数/内存假设、全文件 UTF-8（宪章 C24、验收 V19）；
8. [ ] 过程产物已进隐藏工作区，`/workspace` 无散落（路线图 §8）。

### 5.3 全局一致性审查流程（IS_PASS 判定）

1. **逐波合并审查**（日历各"合并"行）：波内全部任务包完工自检单（§5.2）收齐 + 波内关卡全绿 → 该波 IS_PASS。
2. **收官审查**（四锚点处，日历 §一）逐项核：
   ① 测试总数达标（>60 / >200）；② 全链确定性回归——演示 DSL（多场景+过渡+文本+字幕+配乐+后处理+布料+粒子+AI mock）双遍渲染帧+WAV+容器 md5 全一致，进 CI（路线图 Phase 3 验收 7）；③ 并行 ≡ 串行判据过（白皮书 §26）；④ CI 结构化断言全绿——术语不泄漏 / 错误建议覆盖率 / 静默白名单穷尽 / 版本头双读（架构 §8.3、宪章 V1/V7/V8）；⑤ 清欠判定：关卡未过 → 下一波首优先级清欠，QA 智能路由（日历纪律 3）。
3. **双实现判对**：GPU 实装项对 CpuRef 逐像素统计 diff（视觉等价阈值）+ 确定性模式 md5（路线图 Phase 4 验收）；**CpuRef 永远是黄金参照**（宪章 C22 一等运行后端）。
4. 审查结论只有两种：**IS_PASS** 或 **清欠清单**（逐条带工作流编号与关卡编号）。不设"基本通过"。

### 5.4 批次纪律（D-19 / D-25 / 日历 §三）

| 纪律 | 操作化 |
|------|--------|
| 峰值 ≤3 路 | 一次性在线 agent 峰值不超 3；多数波 2–3 路，合并/QA 1–2 路（D-19） |
| 会话复用 | 波次间复用 agent 会话，降低上下文重建开销（D-19） |
| 切块均衡 | 任务包工作量尽量均匀，防最长尾拖住整批——批次耗时 = 最长 Agent 耗时（max），非加法叠加（sum）（D-25） |
| 先完成先回收 | 先完工先回收，机动位即刻释放接续派活；提前释放的机动位优先还账（按账本触发条件：账四→账二等）（D-25、日历机动还账位） |
| 关卡不降价 | 压缩的是并发峰值，不是验证标准——验收与历版逐字相同（日历纪律 2） |
| 逻辑依赖串行 | 上游关卡未绿，下游波不开工——真正的节拍器是依赖与人类延迟，不是日期（日历"流式原则"） |

### 5.5 并发写入纪律（2026-10-06 幽灵写入事故后增设）

**事故记录（真实发生，故此节不是预设）**：`crates/prism-io/src/raw.rs` 在
**17:31 与 17:58 两次**被**无人运行的写入**注入 254 行代码，导致
`error[E0592]: duplicate definitions`、`prism-io` 编译不通过；18:02 又"自愈"
回良好态。来源未定位（`ps` 无残留 Agent 进程，疑为客户端网络中断后重试重放写入）。

已查明并**已工具化**的三个指纹：① 破损态 8479 行 vs 良好态 8225 行，
`diff` = **多 254 行、删 0 行**（严格超集）；② 注入块首行是**无缩进的 `///`**
（截断写入指纹）；③ 注入内容是旧版重复实现（同作用域同名函数 ⇒ E0592）。

#### 操作化四步

| 步骤 | 命令 | 不许做的事 |
|------|------|-----------|
| 1. 改前备份 | `./tools/backup.sh backup <file>` | 不许不备份就动`crates/` 下任何文件 |
| 2. 记录 stat | 备份命令已自动记md5 / 行数 / mtime 到 `tools/backups/ledger.tsv` | 不许口头记忆"我改过" |
| 3. 改后复看 | `./tools/backup.sh status` 比对台账；怀疑被覆盖时用 `verify` | 不许凭印象判断文件状态 |
| 4. 门禁自查 | `node tools/ghost_guard.mjs --check --no-compile` | **不许用 `#[allow]` 或注释掉检测逻辑来"让它变绿"** |

#### 铁律：发现非本人改动立即停手上报

改文件前先跑一次 `backup`，若发现：

- **文件 md5 与自己动手前记录的不一致**，或
- **出现自己没写过的内容**（重复定义、陌生的文档块），或
- **`--check` 判红而自己没改过该文件**

⇒ **立即停手，上报主理人，不许顺手"修好"**。

理由不是"怕担责"，而是**那可能是在途工作**：另一路 Agent 正在写这个文件，
你"修好"的瞬间它可能又写一次，两个写入互相覆盖，产出比谁都错。2026-10-06
这次事故里"18:02 自愈"就是这类竞态的表现——**没有人确认它是否真是自愈**。

#### `verify` 的判定标准

`./tools/backup.sh verify <file> <baseline>` 判定"精确还原"要求**两条同时成立**：

1. **md5 完全一致** —— 逐字节相同；
2. **`diff` 无任何输出** —— 行级一致（含行序与空白）。

两者都过才输出 `结论：精确还原`。任一不过即打印差异行号并返回退出码 1。
