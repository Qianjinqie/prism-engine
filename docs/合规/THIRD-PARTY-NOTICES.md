## 1. 「代码依赖」与「数据资产」的区分（**本文件最关键的一节**）

用户 2026-10-02 亲自收窄的口径（[D-31](../文档八件套/强大版路线图.md) 修订记录）：

> 零第三方依赖约束的是**代码**（零外部 crate，CPU 侧延伸到 GPU 侧）；
> **数据资产**（字形 / 数学表 / 词典）**不是依赖**，
> 允许取自外部明确许可来源，但**来源、许可、合规动作三者齐备，缺一不得入仓**。

| | **第三方代码依赖** | **第三方数据资产** |
|---|---|---|
| **定义** | 被链接进二进制的**可执行代码**（外部 crate / C 库 / JS 运行时依赖） | 喂进去的**数据**（数值表、字形、词典、模型权重） |
| **本项目约束** | **零容忍**（铁律） | **允许，但须三项登记齐备** |
| **是否随包分发** | 不适用（零个） | 部分分发（如字体） |
| **登记处** | 本文件 §2（**空表**） | §3 + [`assets/资产登记.md`](assets/资产登记.md) |

**为什么这个区分成立**：一段数据被读取 ≠ 一段代码被执行。
字体子集是**一串字节**，方向数表是**一串数字**——它们不参与编译，
不进入可执行路径，只作为常量/数据被本项目**自研代码**读取。
反之，外部 crate 会**进入编译期与运行期**，其缺陷即本项目的缺陷。

## 2. 第三方代码依赖：**无**

### 2.1 核验方式与结果（W16 实测）

| # | 核验项 | 命令 | 结果 |
|---:|---|---|---|
| 1 | 全仓 `[dependencies]` 无外部 crate | 逐个审阅 `Cargo.toml` + `crates/*/Cargo.toml` | ✅26 个 crate **全部只有 `path =` 依赖** |
| 2 | 无构建期外部代码 | `find . -name build.rs -not -path './target/*'` | ✅ **输出为空**（无 `build.rs` ⇒ 无 `bindgen`/外部代码生成） |
| 3 | 无外部 C/C++ 库链接 | `grep -rn 'extern "C"\|#\[link' crates/ --include='*.rs'` | ✅ 仅 `ffi` 类型声明，**无 `-lfoo`/pkg-config 外部库链接** |
| 4 | 依赖锁文件核对 | `Cargo.lock` | ✅ 仅本仓 26 个包 |
| 5 | 自动化核验 | `node tools/compliance_check.mjs` | ✅ **exit 0** |

> **本节的核验是可复现的，不是声明。** 上表每条命令都可自行执行。

### 2.2 "零依赖"意味着什么（以及不意味着什么）

**意味着**（结构性收益）：
- 无第三方 CVE 继承面；
- 无上游版本漂移导致"昨天能编译今天不能"；
- 可离线构建（无网络亦可）；
- 供应链审计面 = 26 个自有crate，**不是** 154 文件 + 19M `node_modules`；
- 分发成本结构性下降。

**不意味着**（诚实边界）：
- **不意味着没有任何外部内容**——字体与方向数表是外部来源，
  它们在 §3 登记，**其许可义务照常履行**；
- **不意味着算法都是原创**——Disney/GGX/Schlick 等**论文公式**被实现，
  受保护的是论文**表述**，不是数学**公式与数值系数**（详见 §3.4#4）。
