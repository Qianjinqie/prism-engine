## §1 病灶的精确陈述

引擎 `over`（`compose.rs:85-91`）：

```
αo = αb + αa(1−αb)
c_o = a·(1−αb) + b·αb
```

两处偏离标准 Porter-Duff（b = 上层/源，a = 下层/背景）：

1. **缺 αa 权重**：标准 `Co = Ca + Cb(1−αa)`，等价非预乘
   `c_o = (αa·a·(1−αb) + αb·b)/αo`；引擎下层色按 `1` 而非 `αa` 加权；
2. **缺归一化**：输出未除以 `αo`。

后果（前序已证）：非结合；嵌套半透明误差随深度复利；图层树不可扁平化。

## §2 修复：预乘域 + over

**定义 2.1（内部表示）**。内部表示改为预乘 RGBA：`C = α·c`（四通道，
`C_α = α`）。对外 `LayerBuf` 出入仍是非预乘。

**定义 2.2（转换）**。`to_pre(c,α) = α·c`；`from_pre(C,α) = C/α`（α>0），
`α=0 ⟹ (0,0,0,0)`。

**定义 2.3（over，预乘域）**：

```
Co = Ca + Cb·(1 − αa)
αo = αa + αb·(1 − αa)
```

**命题 2.4（over 结合律）【定理】**。定义 2.3 满足结合律。

*证明*。四通道统一：每通道 `O_x(y) = y + x(1−y_α)`，`y_α = αa`。

```
over(a, over(b,c))：C = Ca + [Cb + Cc(1−αb)](1−αa)
                          = Ca + Cb(1−αa) + Cc(1−αb)(1−αa)
over(over(a,b), c)：C = [Ca + Cb(1−αa)] + Cc(1−[αa + αb(1−αa)])
```

展开后者：`1−αa−αb(1−αa) = (1−αa)(1−αb)`（实数代数），故

```
C = Ca + Cb(1−αa) + Cc(1−αa)(1−αb)
```

两侧逐项相同（只用乘法交换律与分配律）。∎

**注 2.4.1（比教科书细一层）【定理】**。浮点上，预乘版每项是独立乘积，
括号只影响最后求和的舍入：误差 **O(ε) 单层**。非预乘版是嵌套递归
`(a(1−αb)+bαb)` 的复合，误差随深度 **复利 O(nε)**。**预乘化的真实收益是
误差结构从复利变单层；结合律是它的推论，不是全部。**

### 命题 2.5（兼容性）【定理】——本稿的自我纠正

**第一版（错）**：「下层不透明（αa=1）时三公式逐位相同」。
**重算发现**：`αa=1` 时标准公式输出 `Co = Ca = a`（上层被完全遮住），
而引擎公式输出 `a(1−αb)+bαb`（半透明上层混入颜色）——**两者不同，
引擎是错的一方**。我最初的「物理预期」写反了。

**修正后**：

> **(a) 上层不透明（αb=1）**：标准 `Co = Cb`、`αo = 1`；引擎 `a·0+b·1 = b`、
> `αo = 1`。**逐位相同 ✓**（最常见用例：不透明层盖任意背景）。
> **(b) 下层不透明、上层半透明（αa=1, 0<αb<1）**：标准输出 = 下层色 `a`
> （上层被遮）；引擎输出 = `a(1−αb)+bαb`。**不同——引擎错。**
> **(c) 双不透明（αa=αb=1）**：两者都输出 `b`。相同 ✓。

**实施必读**：修复会改变情形 (b) 的既有输出。那不是「修正后更对」的
审美问题，是**既有行为本来就错、修正后符合 Porter-Duff**。凡既有测试/
基线画面用到「半透明层叠不透明层」，须重录。**这是坏消息，必须先说。**

## §3 混合模式的二分：覆盖类 vs 着色类

逐个算子核对预乘域定义后，得到真分类：

| 算子 | 引擎现状 | 预乘域 | 归类 |
|---|---|---|---|
| **Over** | 偏离标准 | `Co=Ca+Cb(1−αa)`（§2） | **覆盖类**（预乘、结合） |
| **Plus** | 四通道相加 | `Co=Ca+Cb`（同现状） | **覆盖类**（无需改） |
| **Mask** | `out=a·m, αo=αa·m` | **无对应**（见下） | **着色类** |
| **Screen** | `1−(1−a)(1−b)` | 无标准定义 | **着色类** |
| **Multiply** | `a·b` | 无标准定义 | **着色类** |

**Mask 为何无预乘对应（推证）**。引擎 mask 语义：`c_o = a·m`（亮度乘 m），
`αo = αa·m`（覆盖乘 m）。若预乘域做 `Co = Ca·m`，则
`from_pre = a`、`αo = αa·m`——那是「色不变、覆盖减」= **淡出**，不是遮罩。
同一 `m` 在两个通道扮演不同角色（色=亮度缩放、α=覆盖缩放），**该运算本质
依赖非预乘表示**。强行预乘化会静默改语义。

**命题 3.1（二分纪律）【定理（分类陈述）】**。Compose 树中：

- **覆盖类**（over/plus）的子树可任意括号化、可扁平化、可重排（结合+交换
  对 plus；over 结合不交换，但括号自由）；
- **着色类**（screen/multiply/mask）必须**固定层序 + 固定括号化**（左结合），
  不可与覆盖类混布后重排——混排改变结果。

**这正是「固定形状归约 = 非结合代数规范括号化」在混合层的落地**：覆盖类
走预乘平坦路径（快），着色类走层序树路径（保语义），树的静态类型决定路径。

## §4 边界与 alpha 语义

**命题 4.1（零 alpha 边界）【定理】**。`αo = 0` 仅当 `αa = αb = 0`，此时
`Co = 0`（`Ca = Cb = 0`），输出 `(0,0,0,0)` = `LayerBuf` 的透明黑初值。
**无新增边界情形；无需特判码。**

**alpha 三语义（记录，非不一致）**：

| 算子 | alpha 公式 | 语义 |
|---|---|---|
| Over | `αa + αb(1−αa)` | 覆盖合成（概率并集） |
| Plus | `αa + αb` | 覆盖相加（可 >1，HDR 设计） |
| Screen/Multiply | `max(αa,αb)` | 覆盖不增（着色不改覆盖） |
| Mask | `αa·αb` | 覆盖相交 |

三者各自自洽；`max` 结合（`max(max(a,b),c)=max(a,b,c)`）但与 over 的加法型
alpha 混布时整体不结合——归入命题 3.1 的混布纪律管。

## §5 验收标准（实施时照此断言，不许多不许少）

1. **结合律**：over 随机 20000 组，`(a∘b)∘c = a∘(b∘c)` 逐位（前序已跑，
   换公式后重跑——必须 20000/20000）；
2. **兼容性 (a)(c)**：αb=1 任意背景 ⟹ 输出 = b；双不透明 ⟹ 输出 = b；
   **旧基线中情形 (b) 的样本须显式重录**（坏消息的执行动作）；
3. **误差结构**：n 层嵌套 over，预乘版误差 ≤ 单层 ε 量级（非复利）——
   实测误差曲线应平坦，不随 n 增长；
4. **零 alpha**：双透明层合并 = 透明黑，无 NaN（`from_pre` 不被 0 除）；
5. **扁平化**：覆盖类子树 `eval_flat`（固定形状归约）与树形 `eval` 逐位相同
   （over 结合后此断言才成立——**修复前它不成立，这正是 bug 的判据**）；
6. **plus/mask/screen/multiply 行为不变**（不碰它们的公式，只归档语义）。

## §6 规格总结（实施者取这一页）

- 内部改预乘表示（`C = α·c`），对外 `LayerBuf` 接口不变；
- `over` 换定义 2.3；`plus` 无需改（已是预乘法）；
- `screen/multiply/mask` 留在非预乘、锁层序——**不强行预乘**；
- 兼容性：上层不透明/双不透明逐位兼容；**半透明叠不透明输出改变（既有错）**；
- 边界无新情形；验收六条见 §5。
