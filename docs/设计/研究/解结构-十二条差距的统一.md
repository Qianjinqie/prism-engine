## §0 问题与赌注

**问题**。十二条差距（《差距清单》#1–#12，见附录）能否统一到**一条偿还路径**，
使得「补一个东西」同时推进多条差距？

**赌注（可被本报告自身证伪）**：

> 引擎的一切计算都是算子方程 `f = g + Kf` 的**解结构实例**，
> 每个实例由三元组 (核 K, 对偶侧, 格) 刻画；十二条差距分别是这个三元组
> 加求值器、语法投影共五个侧面的缺失。

赌注的来源不是新造：白皮书 §25 已在**算法层**用同一方程统一 24 个算法
（六种求逆策略）。本报告追问：同一方程能否统一**编排层**——若可以，
则「算法层的统一」与「编排层的统一」是同一个统一，§25 的一个定理两处用。

**证伪条件（先立后破）**。若某条差距的映射只能是【类比】（找不到定理级陈述），
如实降级并记录；若超过 4 条落入【不适用】，本赌注失败，归档。

## §1 定义：解结构实例

**定义 1.1（解结构）**。一个解结构是四元组 `S = (K, g, D, L)`：

- `K`：核（算子/依赖投影/生成元），决定「怎么解」；
- `g`：源项（已知输入），解方程的右端；
- `D`：对偶侧声明（边界↔体、前向↔反向、表示 A↔表示 B 的哪一侧）；
- `L`：值域格（解所在的格 + 运算的合法性）。

**定义 1.2（解结构实例）**。引擎中的一个节点/子系统/格式是解结构实例，
若其求值/转换可写成 `f = g + Kf` 的解，且其正确性条件可在 `(K, D, L)` 上陈述。

**定义 1.3（五个侧面）**。一个能力域接入引擎需要五样东西：

| 侧面 | 内容 | 缺失时的症状 |
|---|---|---|
| 核库 | 该域的核有哪些（卷积/投影/生成元/传输） | 功能不存在 |
| 求值器 | 解结构怎么求（精确/迭代/流/优化） | 功能不可调度 |
| 对偶刻画 | 表示切换/复用的判据 | 不可复用、不可缓存 |
| 格锚定 | 值域格 + 运算合法性 | 代数错误、静默语义错误 |
| 语法投影 | DSL 能表达的解结构类型 | 用户够不着 |

**赌注的精化**：十二条差距 = 五个侧面的缺失组合。偿还 = 补五个侧面，不是十二条路。

## §2 承重定理批（第 1 轮）

### 命题 2.1（迭代解 = Neumann 截断）【可证，本轮证】

**陈述**。不动点迭代 `x_{k+1} = M x_k + c` 的误差满足 `e_{k+1} = M e_k`，
从而 `e_k = M^k e_0`；当 `ρ(M) = q < 1` 时 `‖e_k‖ ≤ q^k ‖e_0‖`（任一相容范数），
残差按 `O(q^k)` 衰减。这正是 Neumann 级数 `(I−M)^{-1}c = Σ_{k≥0} M^k c` 的
部分和误差 `Σ_{k>n} M^k e_0` 的衰减率。**「固定 n 步迭代」= Neumann 级数的截断**。

*证明*。标准线性代数结果（不动点迭代误差传播 + 谱半径与范数的 Jordan 估计），
逐步可查，无非标准内容。∎

**引擎实例（差距 #5 物理的映射，【定理】级）**。
`physics/xpbd.rs:18` 自述「每子步的 Gauss–Seidel 投影是**不动点迭代**：
残差按 O(q^iters) 衰减，q < 1」。按命题 2.1，这就是 Neumann 截断的字面陈述——
**引擎自己的注释写了一半，本报告补上另一半**（该衰减率就是 Neumann 余项率）。

**推论 2.1a**。求值台三模式统一于 Neumann 的三种停机（承接《求值台的数学》命题 3.10）：

| 模式 | Neumann 语言 | 停机 |
|---|---|---|
| M1 Kleene-exact | 格上级数部分和 | 链触顶（有限高格 ⟹ 有限步） |
| M2 Metric-tol | 范数下级数部分和 | 残差 < ε（即余项范数界） |
| M3 Fixed-steps | 级数**截断** | 定数 n（无停机判据） |

**推论 2.1b**。「补求值器」的具体形状：一个 Neumann 求值器 + 三种停机策略，
覆盖 DAG（M1 退化：D+1 步）、物理（M3）、一切容差求解（M2）。**#2 与 #5 的
偿还路径合并。**

### 命题 2.2（M1 ⟹ M2 的条件）【可证，路径明确，待证】

**陈述（猜想精化）**。若格有限高（无无穷升链），则格上 Neumann 触顶步数 `N ≤ |V|·(|L|−1)`
（《求值台的数学》命题 3.9 已证），且触顶值 = lfp；同时 lfp 满足
`‖x* − G(x*)‖ = 0 < ε` 对一切 ε。故 M1 的输出自动是 M2 在任意 ε 下的解。
反向不成立：度量收敛不蕴含格触顶（ℝ 有无穷升链，命题 3.9 推论 9a）。

**意义**：模式选择不是任意工程决定——**有格保证时用 M1（语义最强），无格保证时
只能 M2（近似 + 残差），无结构时 M3（截断 + 事后验证）**。引擎现状
XPBD = M3 是「没有把值域格化」的后果，不是设计选择。**这给了 #5 的一条升级路径：
值域格化后 XPBD 可从 M3 升 M1/M2**——但按《求值台的数学》命题 3.9 推论 9b，
f32 点值域不能有限高格化，故 XPBD 的实际出路是 M2（残差驱动停机，
`report.residuals` 已在记录，缺的是停机路径——`xpbd.rs:458-465` 已铺一半）。

### 命题 2.3（资产 = 核的对偶侧）【可证，路径明确，待证】

**陈述（猜想精化）**。`mesh` 与 `SDF` 是同一几何的两种核：mesh = **边界核**
（分布，支在 ∂V 上），SDF = **体积核**（函数，定义在 V 上）。表示转换 =
§25 的对偶切换（边界↔体），其判据是「转换保持层的同构类」
（《视觉计算的函子结构》§4.2）。资产管线的正确性 = 转换保同构。

**引擎实例（差距 #9 的映射）**。`geometry`（mesh↔SDF）、`io`（USD/MaterialX）。
USD/MaterialX 的接入 = 注册「该格式的核 ↔ 引擎核」的对偶映射，不是写解析器了事。
**格式广度债降级为「对偶映射注册债」**——工作量仍存（每个格式一对映射），
但每条从「造子系统」降级为「注册 + 同构测试」。

### 6.2 结论：#1 不是「语法缺类」，是「三个接线断点」

此前判断「DSL 只能摆一个球」**不准确**，撤回。准确形状：

1. **断点 A（audio）**：`AudioAst`/`NoteAst` 语法完整（作曲系统：音阶/根音/BPM/琶音），
   codegen 只产出 `music: BTreeMap<f32>` 参数摘要——**没有节点、没有图、没有
   与 prism-audio（9.5k 行合成器军火库）的任何连接**。
2. **断点 B（post）**：`PostAst` → `PostInfo.params`，同样无节点。`prism-postfx`
   7.8k 行（bloom/grain/…）与 DSL 之间只有一层参数平铺，无调度关系。
3. **断点 C（light）**：`light` 块解析、校验、然后**丢弃**（自述后续接入）。

**偿还 #1 = 补三个 codegen→graph 投影**，不是发明新语法。工作量从「设计 DSL
统一理论」降为「三个接线活 + 每个活对应一个求值台节点类型声明」。

### 6.3 语法投影模式（猜想，从 3 个活实例归纳）

已贯通的块（stage3d/layer/sim/compose）共享同一模式：

> **每个已贯通块 = 一个 Info 摘要（人读/诊断用）+ 一个 node_id（机读/求值用），
> 且 Info 的每个白名单参数最终成为节点的 Params 或 PropertyChannel 绑定。**

audio/post/light 的断点 = **只有 Info 没有 node_id**。故猜想：

**猜想 E（语法投影模式）**。DSL 块到 graph 的投影是完备的，当且仅当每个块都
落地为「Info + node_id」对；缺 node_id 的块对求值台不可见（用户写了等于没写）。
模式的存在性已被 4 个块实例化；完备性（「当且仅当」方向）未证——但即使只有
存在性方向，也足够指导偿还：**给 audio/post/light 补 node_id 投影**。

**分级**【可证】存在性方向已有实例；完备性方向【类比】。

### 6.4 对 §4 偿还路径的修订

S4 从「设计 DSL 解结构投影定理」修订为：

1. 补断点 A/B/C（三个 codegen 投影，每个 ≈ 一层 Info→node 转换 + 参数白名单）；
2. 同步给求值台注册对应结构特解（audio 合成节点、post 效果节点、light 节点），
   模式标签按 §25 归类（audio = 谱解+流、post = 卷积核、light = 场景源项 g）；
3. 用猜想 E 的「Info + node_id」对做验收：补完后每个 DSL 块都有 node_id，
   且 `out.graph.node(id)` 可达。

**工作量估计**：三个断点各数十行级 codegen + 各自的结构特解注册。不需要新数学
（除 §25 归类），主要是把已有 16 万行军火库（audio 9.5k + postfx 7.8k）接到台上。

## §8 第 3 轮：音频统一的精确化（差距 #7 从【类比】升【可证】）

### 8.0 引擎事实

`prism-audio/src/synth/mod.rs:69-79`：`sample_osc(waveform, freq, index, sample_rate)`
—— 相位 `p = fract(freq·index/sample_rate)`，是 **index 的纯函数**；
`mod.rs:158` 测试名 `phase_is_pure_function_of_index`；
`lfo.rs`：LFO 同构（rate + phase_offset）；`mod.rs:103`：ADSR `value_at(t, note_dur)`
是 t 的纯函数；`filter.rs`：FIR/IIR 滤波；`fft.rs`：频谱；`arp.rs`/`drums.rs`/
`harmony.rs`/`score.rs`：规则生成。

### 命题 F1（振荡器 = 旋转流）【定理】

**陈述**。振荡器求值是圆周群 `S¹ = ℝ/ℤ` 上的**旋转流**与波形函数的复合：

```
相空间 = S¹；生成元 ω = f/sr；流 R(i) = (φ₀ + ω·i) mod 1；
振荡器 x(i) = w(R(i)(φ₀))，w 为波形函数（sine/saw/square/triangle）
```

*证明*（逐条可核）。(1) `fract` = 模 1 商映射 `ℝ → ℝ/ℤ`；(2) `R(i+j) = R(i) + R(j) mod 1`
——旋转的复合性 = `ℤ` 在 `S¹` 上的**群作用**；(3) 引擎测试
`phase_is_pure_function_of_index` 断言的正是该群作用的确定性：
同 index 必同相位；(4) `sine_f64(TAU·p)` = 覆叠映射 `ℝ → S¹ → ℝ` 与 `w = sin(2π·)`
的复合。∎

**读法**。引擎把「相位是 index 纯函数」当**确定性纪律**（对的），但它的数学身份是
**群作用公理**——纪律是定理的弱化形式。**白皮书「格锚定」的音频实例：相位格 =
`ℤ`（整数索引）在 `S¹` 上的均匀投影。**

### 命题 F2（ADSR / LFO = 流）【可证】

`value_at(t, note_dur)` 是分段线性的：attack/decay/sustain/release 四段各为
常生成元（斜率）段。分段常生成元的流 = ADSR。LFO = F1 的振荡器以低频参数化
（同一个 `sample_osc` 机制，rate 参数不同）。**无新数学，归类而已。**

### 命题 F3（滤波 = 卷积核；FFT = 对偶投影）【可证】

FIR = 核 `K = h[·]` 的显式卷积（`f = g + Kf` 的 K 就是滤波器）；IIR = 反馈形式
`f = g + Kf` 的自递归解（§25 的迭代求逆）；FFT = **对偶侧切换**：时域格 → 频域格
的幺正变换（§25「对偶在哪侧」的音频实例：卷积在对偶侧变乘积）。

### 命题 F4（作曲生成 = 自由层）【可证】

### 命题 F5（统一连接点：音频 index 流 = 物理帧间轨道）【可证，本轮最重要】

**陈述**。`sample_osc` 的 index 流与 ConstraintFlow 的帧间快照是**同一个离散流**
的两种实现风格：

| | 音频 index 流 | 物理帧间轨道 |
|---|---|---|
| 数学 | `ℤ` 在 `S¹`（或一般相空间）上的群作用 | 帧间算子 `Φ` 的轨道 |
| 实现 | **纯函数**（每样本重算相位，O(1)） | **状态递推**（快照存状态，每帧读上帧） |
| 为什么不同 | 求值 O(1)，重算比存便宜 | 求值昂贵（子步×迭代），存比算便宜 |

**推论 F5a（原则）**：**「该不该存状态」由求值成本决定，不由数学决定。**
引擎两种写法共存不是不一致，是同一数学的成本优化分叉。**这是「为什么物理存快照、
音频不存」的第一个原则性回答**，也给出了求值台的统一接口：节点声明
「流/群作用 + 相空间 + 生成元」，存不存状态是求值器的成本决策（可缓存/可重算）。

**推论 F5b**：DSL 断点 A（audio 无 node_id）的偿还有了精确形状——音频节点 =
注册「群作用 + 波形」的流节点（M1：相位可精确重算 ⟹ 无快照路径），
与物理节点（M3：截断 Neumann + 快照）共用同一个求值器的不同停机配置。
**#7 与 #2、#5 在「离散流」上合并。**

## §10 第 4 轮：粒子统一的精确化（差距 #6 升【定理】级）

### 10.0 引擎事实

- `particles/emitter.rs:9`：`stream(i, k) = hash(seed, i, k)`——**纯函数**，
  「同 `(seed, i, k)` 跨机逐位一致」；`emitter.rs:174`：`derive(i)` 同 `(seed, i)`
  恒同；`emitter.rs:202`：`spawn_count(frame)` 是 frame 的纯函数。
- `particles/sim.rs:110-126`：`step()` = 发射 → `apply_forces`（**半隐式 Euler**，
  `spawn_index` 升序定序）→ 帧边界回收 → 帧号/时刻推进。
- `particles/sim.rs:139-150`：**`seek_with(target, forces)` 从空池重放 0..target**，
  注释自述「结果与顺序推进逐位一致（D-28 seek 等价）」。
- `sim.rs` 注释：力场「纯函数、无隐藏状态，同规格重建即等价（D-23）」。

### 命题 P1（粒子 seek = 命题 4.3 的活实例）【定理（引擎实践级）】

**陈述**。`seek_with` 的正确性 = 《求值台的数学》命题 4.3（seek 等式）三条件
在粒子上的实例：(i) 写入正确性——`step` 纯函数推进，无外部写；(ii) 马尔可夫性——
`step` 只依赖当前池 + frame（无跨帧历史）；(iii) 无断档——重放从 0 起，断档
不可能发生。三条件全满 ⟹ 重放 = 顺序推进逐位一致。**引擎已用测试断言该结论。**

**对比（本轮最重要发现）**。同一个引擎，两个 seek：

| | 粒子 `seek_with` | 求值台快照路径（修复前） |
|---|---|---|
| seek 策略 | **显式重放**（从 0 顺序推进） | **静默 fallback**（缺失即用初值） |
| 正确性依据 | 三条件全满（4.3 实例） | 无（承诺写在注释里，实现是 fallback） |
| 逐位一致 | 有测试断言 | 无（且实际不等价） |

**不是能力差距，是求值台缺 seek 语义的显式定义**——粒子自己带了一套正确的，
没上台。**P3012 修复不必发明：把 `seek_with` 的「显式重放」模式上台即可**
（求值台报断档，调用方按粒子同款重放）。

### 命题 P2（发射流 = 群作用纯函数）【定理】

`stream(i,k) = hash(seed,i,k)`、`derive(i)`、`spawn_count(frame)` 都是
**index → 状态的纯函数映射**——与 F1 的振荡器（`sample_osc` 相位纯函数）
**同一个模式**：都是「离散时间到状态的函数式定义」，群作用公理
（同 index 必同状态）由确定性哈希保证。**「无全局 RNG」约束 = 群作用的
确定性公理**。发射与振荡在数学上同构：都是 index 驱动的状态生成。

### 命题 P3（推进 = 半隐式 Euler 离散流）【可证】

`step` 的半隐式 Euler（`spawn_index` 升序定序）= ODE `ẋ = F(x,t)` 的一阶
离散化 = 沿生成元 `F` 的**离散流**；定序是命题 3.11（M2/M3 确定性）的前提，
与 XPBD 的「子步×迭代定序」（`xpbd.rs:245`）**同一条纪律**。

### 命题 P4（力场 = 生成元，trait object 不可克隆是工程约束非数学缺口）【可证】

`ForceSet` 为 trait object，`seek_with` 需调用方同规格重建——注释自述
「力场纯函数、无隐藏状态，同规格重建即等价」。数学上：力场 = 流的生成元，
同规格 = 同一生成元，重建保轨道。**Rust 的对象约束不产生数学债。**

## §12 第四轮：第三圈压缩——四维配置论（对 §4 五侧面的再压缩）

### 12.0 为什么五侧面不够

五侧面（核库/求值器/对偶/格/语法）是**分类学**：它把十二条差距分门别类放进抽屉，
告诉你「差距在哪」，没告诉你「引擎由什么构成」。分类的尽头是抽屉，不是核心。
继续压。

### 12.1 核心论（猜想 G，本报告的压缩终点候选）

> **引擎 = 求值器（一部解方程的机器）。一切能力 = 方程 `f = g + Kf` 的一个
> 四维配置 `(L, K, S, D)`：**
>
> | 维 | 含义 | 实例 |
> |---|---|---|
> | **L** | 值域格 | Scalar / Vec3 / Image / AudioBuffer / EventSeq |
> | **K** | 核 | 卷积核 / 依赖投影 / 生成元（力场、色彩生成元）/ 传输算子 / 恒等 |
> | **S** | 停机策略 | 精确（D+1）/ 容差 ε / 定数 n / 流推进 |
> | **D** | 对偶判定 | 签名键 / 表示切换判据 / 缓存复用判据 |
>
> **十二条差距 = 四个维度上各自的配置缺口**，不是十二条独立债务。

**十二条 → 四维缺口的重映射**：

| 差距 | 缺口维度 |
|---|---|
| #2 编排调度 | S（只有精确一种停机，无容差/流推进的统一路径） |
| #3 混合代数 | L（运算合法性未分区：over 非结合、Multiply 符号条件） |
| #5/#6/#7 物理/粒子/音频 | K（求解器/合成器是现成的核，从未注册上台） |
| #1 DSL | 四维的语法暴露（用户写不出任何配置） |
| #8 缓存 | D（配置等价性判定未定义） |
| #9 资产 | D（表示切换判据未定义） |
| #12 色彩 | L（格间映射未定义；非负格纪律已立） |
| #10/#11 渲染特性/GPU | K 的实例广度 + L 的并行化（tile 化判据已证） |
| #4 范例 | 四维配置的集成样本，非独立债务 |

### 12.2 第四圈：「纯工作量」不是不可压缩——压缩它的是配置语言

§4 曾把 S5（核库内容：格式/求解器/特性）判为「纯工作量，研究豁免」。
**该判断现在被修正**：S5 之所以看起来不可压缩，是因为还在用**实现视角**看它
（「每个格式一对映射，每个求解器一个实现」）。换成**配置视角**：

> 每个核实例 = 一段「从配置到行为」的声明。声明可以任意短；长的从来是**实现**。
> 把实现变成声言的机器，就是配置语言。

**推论 G1（S4 的重新定位）**。S4（语法投影）不是「补三个接线断点」的小活，
它是**把引擎作者的纯工作量转化为用户配置的那台机器**。DSL/注册语言每完善一分，
需要亲手写的子系统就少一分。三个断点（audio/post/light）只是它的第一茬。

**推论 G2（#8 与 #1 的统一）**。「两个能力相同 ⟺ 配置在同构意义下相同」——
这正是签名闭包（#8 的 Infl 定理）的推广形式：**签名 = 四维配置的哈希**。
#1（语法）与 #8（缓存）在「配置等价性」上合流：语法写得出配置，签名判得清
配置等价。两差距一台机器。

### 12.3 新浮出的真问题：配置语言与内容语言的分层

推论 G1 立刻逼出一个必须回答的问题：**配置语言和内容语言是同一层还是两层？**

- 同一层：DSL 既能写内容（一个球、一段音频）又能写配置（一个新核、一种停机）——
  最压缩，但 DSL 变成通用编程语言（确定性与安全性的代价未评估）；
- 两层：DSL = 内容层（用户写片子），Rust 注册 API = 配置层（引擎作者/高级用户
  写核）——业界先例：UE 的 C++/Blueprint、Houdini 的 HDK/VEX 都是两层，
  且**两层都可编程**。

**本研究未决**：分层与否的判据（表达能力 vs 确定性 vs 安全面）没有定理。
这是 S4 从「接线活」升级为「设计活」后欠的第一笔账。**下一轮主攻。**

### 12.4 证伪条件（先立后破）

猜想 G 被下列任一情形证伪：
1. 某能力的正确性依赖四元组之外的东西（如全局时序副作用不可归约为 S/D）；
2. 某能力无法声明为有限配置（必须过程式生成核本身）；
3. 配置语言分层研究得出「两层不可通约」且用户侧配置不可能完备。

7. **§4 五侧面的定位修正（第 4 轮压缩后）**：五侧面是分类学不是结构论。
