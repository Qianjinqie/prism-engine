## §0 研究问题

**精确陈述**。引擎求值台（`prism-core` 的 `graph.rs` / `eval.rs`）当前支持的能力集：

| 能力 | 现状 | 证据 |
|---|---|---|
| 无环图求值 | 支持 | `graph.topo_order`（Kahn），`eval` 单遍拓扑序 |
| 环 / 不动点 | **禁止** | `connect` 拒自环（P3005）；拓扑排序遇环报错 |
| 帧间状态 | 一个结构的私有协议 | `eval.rs:184-195`：仅 `ConstraintFlow` 读 `(sig, frame-1)` 快照 |
| 增量重算 / 缓存命中 | **未接入** | `eval.rs:10-11` 自述「缓存存储归签名模块」，求值台无 dirty/cache 路径 |
| 值域 | Scalar / Vec3 / Empty | `node.rs` `Payload`；组合仅 `Merge(Plus\|Multiply)`，图像域 P3010 报错 |

成熟引擎（UE 节点图、AE 时间线、Houdini）的求值台同时具有：环（物理/反馈）、时间（帧间状态）、增量（参数改动局部重算）、富值域（图像/几何/音频）。引擎与它们的差距不在功能数量，在**求值台能否同时容纳这四种动态性**。

**主问题**。是否存在一个数学框架 M，使得：

1. **兼容性**：现有 DAG 求值是 M 的实例（不是重写，是特例）；
2. **正确性**：M 给出环求值（收敛性）、缓存复用（seek 等价）、最小重算的**定理**，而非工程惯例；
3. **经济性**：实现 = 一个通用内核 + 各能力域注册节点，内核行数与能力域数量无关。

三条全中，才够格称「一次性还债」。

**方法论纪律**。先证「现状为什么只能如此」（缺什么结构导致什么不可能），再建框架。禁跳过第一步直接设计——第一步的答案决定框架的形状。

## §1 第一批事实（代码勘定，第 1 轮）

以下全部可从源码直接核对，非印象：

**F1. 图结构禁环是结构性的，不是疏漏。**
`graph.rs:342-348` 显式拒绝 `from == to`（P3005，建议「环依赖请拆解为多个节点」）；
`graph.rs:384` 起 `topo_order` 为 Kahn 算法，环 → P3005。即：环在图构造层被拒绝，
不存在「带环求值」的代码路径。

**F2. 求值是无记忆单遍。**
`eval.rs:142-198`：一次 `topo_order`，逐节点 `values.insert`。无 dirty 标记、
无 memo 查询、无「上游未变则跳过」。每帧全图重算是唯一路径。

**F3. 时间状态是特例通道。**
`eval.rs:184-195`：仅当 `structure == StructureId::ConstraintFlow` 时读上一帧快照、
写当前帧。时间不是求值台的一等概念，是一个结构私有的输入源。音频驱动视觉（reactive）、
粒子（帧间发射历史）要复用同一机制，只能各自复制这段逻辑——**这就是「吸管」的求值台侧根因**。

**F4. 值域无信息序。**
`Payload` = `Scalar(f32) | Vec3 | Empty`，无 `Ord`/偏序定义（`node.rs` 可核）。
组合运算
`payload_add` / `payload_mul`（`eval.rs:270-289`）是纯代数运算，不是格运算。

**F5. 帧间快照的键是 `(sig, frame)`，sig 由调用方传入。**
`eval.rs:350-361`：`SnapshotKey = (Hash256, u64)`。签名计算归 `signature.rs`，
求值台不校验签名是否刻画同构类——《场复用-签名等价.md》定理 4 的条件
（「只许过近似」）在求值台侧**无强制机制**。

## §2 框架候选：单调框架（Monotone Framework）

选型理由（不是拍脑袋）：同时要求「环有收敛保证 + 缓存有正确性定理 + DAG 是特例」，
经典数学里唯一齐备的是**格上不动点理论**（Tarski 1939 / Kleene 1952；数据流分析的标准骨架）。

**定义 2.1（完全格值域）**。设 `(L, ⊑, ⊔, ⊓, ⊤, ⊥)` 为完全格。`⊥` 读作「无信息」。

**定义 2.2（单调框架）**。一个框架是三元组 `(V, E, F)`：

- `V`：有限节点集；
- `E ⊆ V × V`：依赖边（**允许环**，`(u,v) ∈ E` 读作 v 依赖 u）；
- `F = {f_v : L^{dep(v)} → L}`：每个节点一个**单调**函数（`x ⊑ y ⟹ f_v(x) ⊑ f_v(y)`）。

**定义 2.3（同步算子）**。`G : L^V → L^V`，`G(x)_v = f_v(x|_{dep(v)})`。求值 = 求
`lfp(G)`（最小不动点）或其在 DAG 上的有限近似。

**定义 2.4（深度）**。DAG 上 `δ(v) =` 最长依赖链长度（无依赖节点 `δ = 0`）。

## §3 命题批一号（第 1 轮）

### 命题 3.1（兼容性）【定理】

设框架 DAG（`E` 无环）。令 `τ` 为按拓扑序逐节点求值的结果（引擎 `eval` 的语义），
`D = max_v δ(v)`。则对一切 `v ∈ V`：

```
G^{D+1}(⊥)|_v = τ(v)        （在 L 中逐分量相等）
```

*证明*。对 `δ(v)` 归纳。

- **基例** `δ(v) = 0`：`dep(v) = ∅`，`f_v` 是零元函数。`G^1(⊥)_v = f_v() = τ(v)`，
  且 `G^n(⊥)_v` 对所有 `n ≥ 1` 同值。∮
- **归纳步**：设 `δ(v) = k > 0`。对任意 `u ∈ dep(v)`，DAG 无环 ⟹ `δ(u) ≤ k−1`
  （否则 `u` 经某路径回到 `v`……严格地说：`u ∈ dep(v)` 且 `δ(u) ≥ k` 意味着存在从 `u`
  出发长 `k` 的依赖链，加上边 `u→v` 得从 `v` 出发长 `k+1` 的链，与 `δ(v)=k` 矛盾）。
  由归纳假设，`u` 在 `G^{δ(u)+1}(⊥)` 处已得 `τ(u)`，即在 `G^k(⊥)` 处已终
  （`δ(u)+1 ≤ k`）。于是 `G^{k+1}(⊥)_v = f_v(G^k(⊥)|_{dep(v)}) = f_v(τ|_{dep(v)}) = τ(v)`。∎

**读法**。引擎现有的「单遍拓扑序求值」正是单调框架的同步 Kleene 迭代在 DAG 上的
第 `D+1` 步。`EvalOutput` 的初态空 map 就是 `⊥`。**兼容性成立：换框架不是重写求值台，
是给它补上 `G^n` 中 `n > D+1` 的步（环）与 `n` 的提前终止判据（增量）。**

**可验证推论**。引擎现有全部求值测试（关卡 1–5）在本命题下应逐位不变——若换内核后
指纹变，则内核错。这是后续实现的验收标准，不是可选项。

### 命题 3.2（现状的刚性原因）【定理（定义级）】

当前 `Payload` 域上没有定义任何偏序（F4）。因此在现状下：

- Kleene 迭代的链（`⊥ ⊑ G(⊥) ⊑ G²(⊥) ⊑ …`）无定义——「链」要求序；
- Tarski 不动点定理的前提（完全格）不满足；
- 于是**环求值的收敛性在现状中无任何定理可引**。

这不是「证明了环一定错」，是「环的正确性无依据」。`graph.rs` 禁环因此不是保守，
是**唯一诚实的选择**：没有格，放环进场等于放未定义行为进场。

**推论 2a**。「要支持环」的第一动作不是写迭代器，是给值域装格结构（见 Q1）。
**推论 2b**。工程上另有一条路：固定迭代次数、不承诺收敛（大量商用求解器实际如此）。
该路的代价是静默错误无检测手段——与引擎宪章「绝不静默」（C20）冲突。**默认走装格路。**

### 命题 3.3（时间不是不动点，是轨道）【定理（语义级）】

帧间状态满足 `x(f) = Φ_f(x(f−1))`，`x(−1) = ⊥`。这是 `Φ_f` 从初值出发的**轨道**
（orbit）。`lfp` 框架求的是方程 `x = Φ_f(x)` 的**解**。二者一般不等：

- 轨道依赖初值；不动点不依赖。
- 物理模拟是初值问题（《视觉计算的表示-探索.md》§1.2 已证 XPBD 是初值问题）——
  引擎选轨道是**语义正确**，不是将就。

**读法**。求值台的数学因此不是单纯的不动点理论，是

```
求值 = 时间维（轨道） ⊗ 空间维（帧内框架的不动点）
```

`eval.rs:184-195` 的 ConstraintFlow 快照正是这个张量积的一个手工特例：
帧内无环（D+1 步收敛）⊗ 帧间轨道。推广 = 让帧内也允许环（物理 XPBD 每帧迭代），
即把「每帧一次拓扑遍历」升级为「每帧解一个小 lfp」。

### 命题 3.4（帧内环 × 帧间状态的复合）【猜想，未证】

设帧内框架 `(V, E_f, F_f)` 允许环，帧间算子 `Φ_f(y) = lfp(G_{·,y})` 以 `y` 为参数
（`G` 的节点函数可引用上一帧自身状态）。则时间线

```
x(f) = lfp(G_{·, x(f−1)}),  x(−1) = ⊥
```

与「先按帧内框架求不动点、再沿帧间算子推进」**逐帧相等**（这是定义，平凡）。
非平凡的部分是：**`Φ_f` 单调 ⟺ 每个 `f_v` 对其「上一帧自身」输入分量单调**（若单调）。
「⟸」方向显然（单调复合）。「⟹」需要构造：若 `Φ_f` 单调而某 `f_v` 对状态输入
非单调，能否举出反例？**开放**（见 Q4）。此猜想是「物理每帧迭代 + 帧间状态」正确性的
承重墙，暂标猜想。

## §5 命题批二号：值域的格化（第 2 轮，Q1 主攻）

### 命题 3.5（点值格与有限精度）【定理】

**(a)** `D = ℝ ∪ {−∞, +∞}` 按自然序是完全格（全序 ⟹ 任意子集确界存在；无界子集
以 ±∞ 为界）。f32 本身**不是**完全格——它是 ℝ 的离散子集，两个相邻可表示数之间
无 f32。故格在 ℝ 上证明，f32 是有限精度**实现**。

**(b)** 在 D 上：`+` 单调（`x ⊑ x′, y ⊑ y′ ⟹ x+y ⊑ x′+y′`，实数序标准事实）；
`×` **仅对非负乘数单调**。反例：`1 ⊑ 2` 但 `1·(−1) = −1 ⊐ −2 = 2·(−1)`。
Vec3 逐分量同此。

**(c)** 舍入 `RN`（round-to-nearest-even）单调：`x ⊑ y ⟹ RN(x) ⊑ RN(y)`。
故「格上运算后舍入到 f32」不破坏链的单调性——框架结构在有限精度下存活。

**推论 5a（引擎现状核对）**。`Merge(Multiply)` 作为框架节点，仅当两输入**全域可证
非负**时合法。引擎色彩域已立此纪律——`colorspace_registry.rs:397`「引擎色彩域恒非负 →
返回结构化错误而非 NaN」。Vec3 域（速度/位移/方向分量可负）**不合法**，除非按分量
单独证明非负。**`payload_mul` 目前无条件执行 = 一个未分区的合法性漏洞**，不是 bug
（结果数值正确），是「该节点不能进单调框架」的标记。

### 命题 3.6（Empty 的身份）【观察，附带一处文档矛盾】

`node.rs:214` 注释称 `Empty` 为「无值（单位元 / 占位）」，但 `eval.rs:274`
`payload_add` 对含 `Empty` 的输入**报错 P3011**。归约路径的单位元
（`eval.rs:263` `unit = Ok(Payload::Empty)`）与代数单位元（Scalar 的 `0.0`）是两回事。

**数学后果**：Scalar 域上的 `+` 至今没有单位元载体；格的 `⊥` 无处安放。
这不是数值错误，是**框架缺件的实现侧症状**：`⊥` 未装，Kleene 链无从起步。
修正方向：`Empty` 降级为「无节点」类型标记；格的 `⊥` 用值域最元素
（Scalar 域 `−∞`，图像域零 alpha 零色）。

### 命题 3.7（区间分析域）【定理】

闭区间 `[a,b]`（`a ≤ b ∈ ℝ∪{±∞}`）按**包含-精度序**：
`[a,b] ⊑ [a′,b′] ⟺ a′ ≤ a ∧ b ≤ b′`（更窄 = 更精确 = **更大**）。
该序下区间构成完全格（交 = 逐端 max/min；空区间不存在——`a > b` 时约定为 `[+∞,−∞]` ⊥）。
区间运算定义为**集合包络**：`A ⊗ B = env{a ⊗ b : a ∈ A, b ∈ B}`，则 `+`, `−`, `×` 均单调。

*证明*。设 `A ⊆ A′`（作为实数集）。则 `A ⊗ B ⊆ A′ ⊗ B`（集合单调，逐元素成立）；
包络保集合包含，故 `env(A ⊗ B) ⊆ env(A′ ⊗ B)`，即区间更窄，即 `env(A⊗B) ⊑ env(A′⊗B)`。∎

**用途（纪律所在）**：验证「用户注册的 `f_v` 是否单调」的正确方法是在区间格上检验
其提升 `f_v^♯` 的单调性——**静态判定**。逐点采样只能证伪、永远不能证单调
（无限域）。这防止「跑 20000 组没反例 ⟹ 宣布合法」的伪证复发。

### 命题 3.8（严格性条件）【定理】

若 `f_v` **严格**（任一输入为 `⊥` ⟹ 输出为 `⊥`），则同步 Kleene 链 `⊥ ⊑ G(⊥) ⊑ …`
上，环内节点在真实输入到达前恒持 `⊥`，领域函数不会收到 `−∞` 之类的非法输入。

*证明*。归纳同步步数：第 0 步全 `⊥`；若第 n 步某依赖为 `⊥`，严格性使该输入分量
不参与领域计算，输出 `⊥`。∎

**推论 8a**。不严格的 `f_v`（如 `f(⊥) ↦ 0.0`）把 `⊥` 误译成领域初值 `0.0`——
物理上意味着「未计算的力当作 0N」。**所有注册节点必须严格，或框架层把 `⊥` 特判
为「不执行」**。这解释了数据流分析框架为何一律要求 transfer function 严格。

### 开放问题（第 2 轮新增）

**Q1.2（与 Q4 合并攻坚）seek 等价**。缓存续算的正确性：从某帧快照 `y` 起步的迭代

## §7 命题批三号：两种收敛机制与三模式（第 3 轮）

### 7.0 引擎事实（先核对，再立论）

- `physics/xpbd.rs:18`（实现自述）：「每子步的 Gauss–Seidel 投影是**不动点迭代**：
  残差按 O(q^iters) 衰减，q < 1」——引擎自己知道这是**压缩迭代**，不是 Kleene。
- `physics/xpbd.rs:399-404`：`iterations = 0` 拒绝，「迭代数固定是确定性纪律」。
- `physics/session.rs:250`：「迭代数是签名的组成部分」。
- `physics/xpbd.rs:245-246`：残差序列「长度 = substeps × iterations；顺序 = 子步外层 ×
  迭代内层（**固定**）」；`xpbd.rs:458-465` 逐次记录 `max_residual`；
  `xpbd.rs:535` 测试断言「8 次迭代后 final_residual < 1e-4」。

即：引擎物理的既有模式 = **固定步数 + 残差事后可查**。没有容差停机路径。

### 命题 3.9（Kleene 有限性）【定理】

若 `(L, ⊑)` 无无穷升链，则任意单调 `G : L^V → L^V` 的 Kleene 链至多 `|L|^|V|` 步
触顶（`G^N(⊥) = lfp(G)`，`N ≤ |L|^|V|`）。

*证明*。每分量一条链，长 ≤ |L|；V 个分量同步推进，触顶步数 ≤ 各分量链长的
最大必要值的乘积上界 |L|^|V|（精确上界是各分量「最晚触顶步」的最大值 ≤ |L|−1，
乘积界是宽松但正确的表述——**此处收紧为：同步链步数 ≤ max_v(分量链长) ≤ |L|−1**，
因同步推进每步至少推进一个未触顶分量……严格论证：同步链是逐分量链的「逐坐标
最小公共细化」，每步至少一个分量严格升或全部触顶；每分量至多 |L|−1 次严格升，
故总步数 ≤ |V|·(|L|−1)。这是紧的正确上界。）∎

**收紧后的正确表述**：同步 Kleene 至多 `|V|·(|L|−1)` 步触顶。

**推论 9a**。`ℝ∪{±∞}` 有无穷升链（`½ ⊏ ¾ ⊏ …`）⟹ **引擎点值域上 Kleene 无有限
步保证**。第 2 轮「求值域 = 点值格」因此只提供了**语义**（lfp 存在且唯一——Tarski），
没有提供**算法**。
**推论 9b**。数据流分析的全部格都是**有限高**的（故意的）：常量/非常量格高 2，
符号格高 3。若要「有保证收敛的环」，值域必须有限高格化——对媒体引擎这是过度设计
（每个 f32 通道 → 有限标签格，信息损失不可接受）。**诚实结论：媒体引擎的正确路径
不是格化到底，是显式近似模式。**

### 命题 3.10（三模式分类）【设计，各模式附承诺等级】

节点（含环的）求值收敛模式三选一，**必须显式声明，进签名**：

| 模式 | 数学依据 | 停机 | 承诺 | 确定性 |
|---|---|---|---|---|
| **M1 Kleene-exact** | 有限高格 + Tarski | 链触顶 | 输出 = lfp（精确语义） | 逐位一致 |
| **M2 Metric-tol** | 完备度量 + Banach 压缩 | 残差 < ε | ε-近似，残差可查询 | 逐位一致（见 3.11） |
| **M3 Fixed-steps** | 无（裸迭代） | 固定 n 步 | 无收敛承诺 | 逐位一致 |

**引擎现状定位**：XPBD = M3 + 残差记录（M2 的半成品：有残差可查，无容差停机）；
`eval.rs` DAG = M1 的退化（D+1 步触顶，格高非有限但 DAG 无环不需要格——
命题 3.1 已覆盖）。

### 命题 3.11（M2 的确定性）【定理】

设节点函数 `f` 与停机判据 `r(x) < ε` 均为浮点确定函数（C24：同值同字节、
跨平台位模式一致），且迭代顺序固定（如 `xpbd.rs:245` 的子步×迭代定序），
则 M2 节点的输出是其输入的**确定函数**（同输入 ⟹ 逐位同输出）。

*证明*。`x₀` 由输入确定；`x_{k+1} = f(x_k)` 归纳确定；停机时刻
`n = min{k : r(x_k) < ε}` 由序列确定（残差序列逐项确定）；输出 `x_n` 确定。
定序保证 `f` 的复合顺序不依赖调度器的线程/访存巧合。∎

**读法**。`xpbd.rs:245-246` 的「顺序固定」注释不是风格偏好，是命题 3.11 的
**前提**。**这是第二处「从实现注释提炼出数学判据」**（第一处是 tile 化的
halo ≥ r）。模式分类不是新发明，是把引擎已经隐式遵守的纪律显式化。

### 对「极少代码量」的兑现形状（第 3 轮）

内核三件套，与能力域数量无关：

1. **语义轨**：格 + 严格性 + Kleene 链（M1 的正确性来源，seek 等价的条件）；
2. **算法轨**：worklist 调度（M2/M3 通用；M2 按残差停机，M3 按定数停机）；
3. **模式元数据**：节点声明模式 + ε/n，**进签名**（接 Q2）。

各能力域的接入 = 注册「节点函数 + 依赖声明 + 模式」。XPBD 离合规只差
「把 M3 从注释提升为一等属性」——`iterations` 已在签名里，模式标签不在。

## §9 命题批四号：签名闭包移植与 seek 缺陷（第 4 轮，Q2）

### 9.0 新引擎事实

- **F6**：`ConstraintFlow` 在全仓**没有任何真实注册**——仅 `eval.rs`（求值台逻辑）、
  `movie.rs`、`dsl` 引用它。时间流机制至今未接线，只活在单元测试里。
- **F7**：`SnapshotKey = (sig, frame)`，`sig` 由调用方传入（`eval.rs:350-361`），
  求值台不校验签名是否刻画同构类。
- **F8**：`xpbd` 的 `iterations` 在 **session 层**进签名（`session.rs:250` 自述），
  求值台不知道任何节点有「收敛模式」属性。
- **F9**：`render/movie.rs:253-512` 的帧循环**每帧新建 `EvalCtx::new(0, node.id, i)`**
  ⟹ 快照库从不跨帧保留。即：DSL 影片管线里，任何 `ConstraintFlow` 节点的
  `frame > 0` 求值必然触发 4.1 的 fallback 路径。**缺陷当前无触发者（DSL 不产
  ConstraintFlow 节点，F6），但接线之日即爆炸之时**——且 movie.rs 自身的循环
  就是违反方：它把跨帧状态这件事丢掉了。修复必须两侧同时动（求值台 + 调用侧）。

### 命题 4.1（快照 fallback 的语义缺口）【定理（定义级）+ 已实例化】

`eval.rs:189` 的 `snapshot_read(...).unwrap_or(input)` 在三种情形触发：
seek 到无缓存帧 / LRU 逐出 / 缓存清空。三种情形下：

1. 输出 = 初值投影值，与首帧**逐位相同**（探针一、二）；
2. 错误状态经 `snapshot_write` 写回快照库，**自认证为合法快照**（探针三：
   帧 5 得 0.0 写回，帧 6 读它得 1.0——正确轨道应为 6.0）；
3. 全程无报错、无警告、无残差异常。

**故 `eval.rs:349` 的承诺「逐出只影响重算、不影响结果（seek 等价）」在实现层
不成立。** 这不是数值 bug，是**语义级静默错误（C20 违反）**。

**实例化**：`crates/prism-core/tests/qa_seek_snapshot_semantics.rs`，4 探针全过，
记录现状（含正确轨道对照值）。

**修正三选一**：
- **(i) 结构化报错**：`frame > 0 且 (sig, frame−1) 缺失 ⟹ P 段错误`，
  建议「从 0 帧顺序求值或显式提供初态」。引擎宪章「绝不静默」的直接应用。
- **(ii) seek = 从 0 帧重放**：调用方策略，成本显式，结果正确。可在 (i) 之上叠加。
- **(iii) 显式声明「fallback = 初值重置」**：则 `eval.rs:349` 的注释承诺**必须撤回**
  （按《严格性审查与撤回.md》纪律，假承诺留档但标撤回）。

**默认 (i)**。它与 over bug 同型：**注释承诺 vs 实现行为**——本研究第 2 个可落地缺陷。

**修复设计（两侧）**：

1. **求值台侧**（`eval.rs:184-195`）：`frame > 0` 且 `(sig, frame−1)` 缺失 ⟹
   结构化报错（新错误码 P3012，三段式：在哪=节点+帧，什么事=快照缺失/seek 断档，
   怎么改=从 0 帧顺序求值或显式提供初态）。删掉 `unwrap_or(input)` 静默路径。
   `frame == 0` 维持「图输入作初值」（首帧语义，合法）。
2. **调用侧**（`movie.rs`）：`EvalCtx` 提到帧循环外，跨帧复用同一实例
   （快照库随帧累积）。这是调用侧对「时间状态」的显式承担。
3. **测试侧**：现有 seek 探针从「记录静默行为」翻转为「断言结构化报错」；
   `snapshot_assembly_write_read_and_project`（顺序求值）不受影响（快照在）。
4. **不做的**：不在求值台内做「从 0 帧重放」——那是调用方策略，成本必须调用方可见。

### 命题 4.2（缓存正确性的签名闭包）【猜想（承重）】

节点缓存正确 ⟺ 签名键的输入通道集 ⊇ 求值影响闭包：

```
Infl(F) = { 参数, 绑定通道, 上游输出, frame, 全局种子, 采样面,
            收敛模式参数(ε / n), 快照键 } 的传递闭包
```

这是《场复用-签名等价.md》定理 4 的 Infl 概念从「光照场」移植到「求值台」。

**推论 4.2a**。M2 的 ε、M3 的 n 必须进签名（命题 3.10 已证停机依赖它们 ⟹
输出依赖它们）。XPBD `iterations` 在 session 层进签名 = 该推论的**局部实现**；
求值台层无统一执行 = 缺口。
**推论 4.2b**。当前 `(sig, frame)` 键缺通道：模式参数、采样面（若节点依赖 pixel/spp）、
上游签名传播规则（子图 sig 的构成未定义传递闭包算法）。
**推论 4.2c（与 Q1.2/Q4 合并）**。seek 等式的三个条件：(i) 写入正确性——被 4.1 破坏；
(ii) 马尔可夫性——帧 f 只依赖帧 f−1 显式状态（ConstraintFlow 跨度 = 1，现状满足）；
(iii) 无断档——LRU 未落地，落地时须强制「依赖跨度 ≤ 保留窗口」。(i) 已破，
故 seek 等价证明当前无意义——**先修 (i)，再证**。
