### 最重要的三个发现

1. **引擎的 `over` 不是标准 Porter–Duff，不结合**（§35，20000 组反例）。
   缺 `αa` 权重与 `/α_out` 归一化；导致图层树不能扁平化。
2. **tile 化的数学条件是 r-局部 + halo ≥ r**（§18.1，已证）。
   「半分辨率金字塔不可 tile 化」不是工程经验，是**不满足 r-局部性**的数学后果。
3. **预乘混合是唯一同时满足结合 + 数值稳定的方案**（§47，已证）。
   非预乘归一化在 `α_out → 0` 时误差放大 `1/α_out`。

### 对工程的三条建议

1. **修复 `over`**：内部统一预乘（`C = α·c`），混合用 `C_out = C_a + C_b(1−αa)`；
2. **用判据审查新效果**：tile 化（判据一）、采样索引（判据二）、混合代数（判据三）；
3. **不要把「经验观察」当定理**：它们需要测试支撑，测试只记录适用范围。

## 0. 研究问题

**主问题**：是否存在一个数学结构 M，使得「一切视觉计算」都是 M 的实例？

这个问题比「八层是否统一」更强：八层只是引擎当前的能力清单，而「一切视觉计算」包含未来可能新增的能力。若表示定理成立，则引擎的架构一次定型，新能力自动归位；若不成立，则必须知道边界在哪。

**方法论**：先给出尽可能强的猜想，再用反例攻击它；每次修正都缩小命题的范围，直到剩下的命题可证明或可明确标为开放。

---

## 1. 猜想一：一切视觉计算都是推前

**猜想 1.1**。设 `C` 是一个视觉计算（输入场景，输出像素）。则存在底空间 `S_C`
与层 `F_C ∈ Sh(S_C)`，使 `C = f_* F_C`（沿投影 `f: S_C → 像素空间` 的推前）。

**动机**：渲染是路径空间的推前（路径积分）；着色是表面空间的推前；滤波是像素空间的
自推前；合成是层空间的推前。看起来所有计算都符合。

**攻击 1.1（全局光照的多次弹射）**。
取一个只有间接光的场景（无直接光源可见）。若底空间取表面空间，则某点的辐照度依赖
**其他表面**的辐照度——不是该点邻域的局部数据。层要求局部性（截面在开集上定义），
表面空间上的层无法表达这种全局依赖。

**修正 1.1**：底空间改为**路径空间** `P`（所有从相机出发的光路）。辐照度 =
路径空间上的测度积分 = 沿 `P → 像素` 的推前。多次弹射不是「全局依赖」，而是
「路径的更长前缀」——路径空间上的层是局部的（每个路径片段只依赖相邻片段）。

**状态**：猜想 1.1 在路径空间上**幸存**。但代价是：路径空间是不可数无穷维的，
有限偏序的假设失效（见 §5 的开放问题）。

**攻击 1.2（模拟的不可逆性）**。
XPBD 的时间演化：`x_{t+1} = x_t + v_t Δt`，`v_{t+1} = v_t + a(x_t) Δt`。
这是一个**初值问题**：给定 `x_0`，后续状态由微分方程决定。它不是「局部数据 + 粘合」——
粘合要求重叠一致，而初值问题的一致性由因果性保证，不是由层公理保证。

**修正 1.2**：模拟不是层，是**层上的流**（flow）：`Φ_t: Sh(S) → Sh(S)` 的单参数群。
流需要额外的微分结构（时间方向、生成元）。这不是层的子类，是层上的**额外结构**。

**状态**：猜想 1.1 **被击破**——模拟不是推前。修正后：**静态视觉计算是推前；
动态视觉计算是流**。

## 2. 猜想二：一切视觉计算由四算子生成

**猜想 2.1**。一切视觉计算可由 `{f*, f*, ⊗, Hom, f!}` 的有限复合生成。

**攻击 2.1（生成的自由性）**。
L-system：给定字母表、公理、产生式，迭代生成字符串，再解释为几何。
这不是「已有层的组合」——它是从规则**自由生成**新结构。

形式化：设 `G` 是产生式系统，`L(G)` 是它生成的语言。`L(G)` 不是任何已有层的
四算子组合，因为它的结构由 `G` 的语法决定，而不是由底空间决定。

**修正 2.1**：生成是**自由层**（free sheaf）：`F_G = Free(G)`，由生成元（规则）
和关系（迭代）自由生成。自由层与四算子的关系是**伴随**：

```
Hom_{Sh}(Free(G), F) ≅ Hom_{Gen}(G, U(F))
```

其中 `U` 是遗忘函子。自由层不是四算子的复合，而是四算子的**左伴随**。

**状态**：猜想 2.1 **被击破**。修正后：**组合由四算子生成；生成由自由层生成；
两者通过伴随相连**。

**攻击 2.2（最优分配）**。
率控的 water-filling：`R_i = max(0, ½log₂(θ_i/θ))`。这是凸优化的解，不是层的组合。

**修正 2.2**：最优分配是 `V` 上的**凸结构**（§25 的最优性侧）。它与层结构的关系是：
层提供约束（`p(x) = b`），凸结构提供目标（`Φ`）。两者是**纤维丛**的关系：
底空间是层，纤维是凸优化问题。

**状态**：猜想 2.1 **再次被击破**。修正后：**三类结构（组合/生成/优化）是并列的，
不是从属的**。

## 3. 猜想三：三类结构穷尽

**猜想 3.1**。任何视觉计算属于以下三类之一：算子层（组合）、同构层（表示等价）、
内容层（生成/演化/优化）。

**攻击 3.1（多重归属）**。
降噪同时是：
- 算子层：局部滤波（à-trous 卷积）
- 内容层：最优采样分配（σ 分配）
- 同构层：时域累积的缓存复用（Kalman 递推的签名）

一个计算同时属于三类——说明三类不是**划分**（partition），而是**标签**（label）。

**修正 3.1**：三类不是互斥的划分，而是**维度**。一个计算可以同时具有多个维度的结构。
「分类」应改为「分解」：每个计算 = 组合部分 + 表示部分 + 生成部分，三者的比例不同。

**状态**：猜想 3.1 **被修正**——不是「属于三类之一」，而是「可分解为三个维度」。

**攻击 3.2（反例：神经网络渲染）**。
一个端到端的神经渲染器（输入场景 latent，输出像素）没有显式的组合、表示或生成结构——
它是一个黑箱函数逼近。它属于哪一类？

**分析**：神经渲染器**没有**层结构（不可解释、不可组合、不可粘合）。它不是视觉计算
的「结构实例」，而是「结构的替代品」。它的存在说明：**结构不是视觉计算的必要条件，
只是可组合性的充分条件**。

**状态**：这界定了三类结构的适用范围——它们刻画的是**可组合的**视觉计算，
不是一切视觉计算。**可组合性是我们选择的目标，不是视觉计算的本质**。

## 4. 有条件的表示定理

综合三次攻击与修正，得到有条件的命题：

**定理 4.1（条件性表示）**。设 `C` 是一个视觉计算。若 `C` 满足：

- **(a) 显式性**：`C` 有显式的计算图（节点 + 依赖边）；
- **(b) 纯函数性**：每个节点的截面是 `(t, p)` 的纯函数；
- **(c) 局部性**：每个节点的输出只依赖有限邻域（或路径空间中的有限前缀）；

则 `C` 可分解为

```
C = Flow_t ∘ Free(G) ∘ Op(F_1, …, F_n)
```

其中 `Op` 是四算子的复合，`Free(G)` 是自由层，`Flow_t` 是流。

*证明思路*。由 (a)，`C` 的计算图是有限偏序；由 (b)，每个节点是层；由 (c)，
节点间的组合是四算子的实例（§3 的构造）；若无显式生成规则，`Free(G)` 退化为恒等；
若有时间演化，`Flow_t` 作用在结果上。三者复合即 `C`。∎（严格证明需要补充：
计算图的拓扑序与层粘合的一致性；流的生成元与时间格的关系。）

**注 4.1（后续进展）**。§6.1 诊断出原引理的**类型错误**（DAG 节点是计算，粘合开集是
底空间，两者不同类），并将其修正为「DAG 求值确定性」——该命题已证（纯函数的 DAG
求值顺序无关，Church–Rosser 的直接推论）。§6.4 补全了「每个节点是层」的构造
（S1–S12 逐一构造）。因此定理 4.1 的证明已补全，但其核心（求值顺序无关）是**平凡的**，
非平凡部分在**节点到层的构造**（§6.4）与**组合代数**（四算子）。

## 5. 失败的路径（如实记录）

1. **尝试把所有计算统一为像素空间的层**——失败。全局光照的多次弹射不是像素局部数据。
2. **尝试把所有计算统一为路径空间的层**——部分失败。路径空间解决渲染，但模拟没有路径结构。
3. **尝试用自由层统一生成与组合**——失败。自由层与四算子通过伴随相连，不是同一种结构；
   强行统一会失去可计算性（自由层一般不可枚举）。
4. **尝试证明三类是划分**——失败。降噪同时属于三类，说明是维度而非划分。
5. **尝试用「计算图」作为统一的底空间**——失败。计算图是语法，不是语义；不同的计算图
   可以表达同一个视觉计算。

## 6. 开放问题（附初步推进）

### 6.1 拓扑序引理——原陈述有类型错误，修正后平凡

**原陈述**：任何有限 DAG 的拓扑序都给出层粘合的合法序。

**诊断**：这是**类型错误**。DAG 的节点是**计算**，层粘合的开集是**底空间**——
两者不同类。求值顺序影响的是「计算的顺序」，不是「粘合的顺序」。

**修正陈述（DAG 求值确定性）**：设 `G` 是有限 DAG，每个节点是纯函数，边表示数据依赖。
则任何拓扑序给出的求值结果相同。

*证明*。设 `≺₁, ≺₂` 是两个拓扑序。对任意节点 `v`，它的输入只来自 `≺`-前驱；
纯函数的输出只依赖输入值。对 `G` 做关于拓扑深度的归纳：深度 0 的节点无输入，
两种序下输出相同；深度 `n` 的节点，其前驱深度 < `n`，由归纳假设前驱输出相同，
故 `v` 的输出相同。∎

**结论**：定理 4.1 的证明可补全，但补全后该定理的核心是**平凡的**——
「纯函数的 DAG 求值顺序无关」是 Church–Rosser 性质的直接推论。
定理 4.1 的非平凡部分不在求值顺序，而在**层的构造是否覆盖了计算图**——
这需要另一条论证（见 6.4）。

### 6.2 路径空间的离散化——有界近似，非精确

**问题**：路径空间不可数无穷维，是否存在有限路径空间使推前精确？

**构造**：取长度 ≤ k 的路径集合 `P_k`（k 次弹射）。对有限场景，`P_k` 有限。

**定理（截断误差界）**。设 `ρ_max` 为场景最大反照率，`L_max` 为最大发射亮度。
则 k 次弹射的截断误差满足

```
‖L − L_k‖ ≤ L_max · ρ_max^k / (1 − ρ_max)      (ρ_max < 1)
```

*证明*。Neumann 级数 `L = Σ_{n≥0} T^n L_e`；截断到 k 项，余项为
`Σ_{n>k} T^n L_e`；由 `‖T‖ ≤ ρ_max`，余项范数 ≤ `L_max Σ_{n>k} ρ_max^n`
= `L_max ρ_max^{k+1}/(1−ρ_max)`。∎

**结论**：有限路径空间给出的是**有界近似**，不是精确表示。因此渲染的层论表述是
**近似层**——这在数学上是诚实的，在工程上是可用的（误差可定价）。

### 6.3 流的层论刻画——需要光滑层

流 `Φ_t` 是层的单参数群。层范畴本身无微分结构，无法直接承载「单参数群」。
需要的额外结构是**光滑层**（smooth sheaf / diffeology）：

- 底空间取欧氏空间的开集，层取值于光滑流形；
- 切丛与向量场是层的截面；
- 流 = 向量场的积分曲线族（`Φ_t` 是 `exp(tX)`）。

数学定位：Dubuc 的 smooth topos、Iglesias-Zemmour 的 diffeology 提供了这套结构。
**结论**：模拟（物理）的层论表述是**光滑层上的流**，比普通层多一层微分结构。
不是「层的子类」，是「层 + 微分结构」。

### 6.4 层的构造是否覆盖计算图——已推进：S1–S12 十二结构

**关键发现**：`prism-core::node::StructureId` 已经定义了引擎的十二个数学结构
（S1–S12），这正是「节点类型」的全集——引擎的架构哲学就是「每个节点是一个数学
结构的特解」。因此节点分类不是五类，而是**十二结构**；我的 T1–T5 是它们的
**算子位置**归类。

| 结构 | 数学内容 | 算子位置 | 层构造 |
|---|---|---|---|
| S1 标量场 | 协方差核随机场 | 内容（生成）+ `⊗` | 自由层 + 张量 |
| S2 卷积 | 调和分析核 | `f!`（局部）+ `⊗` | T2 邻域层 |
| S3 约束梯度流 | 近端算子不动点 | 流（T4） | 光滑层 + `exp(tX)` |
| S4 确定性抽样 | 样本↔测度配对 | 格锚定（底空间） | 底空间的格结构 |
| S5 重参数化 | 变量替换 + 方程求根 | `f*`（拉回） | 拉回层 |
| S6 谱分解 | 傅里叶对角化 | 对偶（时域↔频域） | 等价层范畴 |
| S7 闭式线性响应 | 格林函数 | T1（逐点） | 0-层 |
| S8 辐射传输积分 | 转移核 | `f*`（推前） | 路径空间层 + 推前 |
| S9 分段多项式 | 再生核 | T1（逐点） | 0-层 |
| S10 层次+签名 | 内容↔摘要 | 同构层（签名） | 层的同构类 |
| S11 扩散 | 热核 | `f!`（局部）+ `⊗` | T2 邻域层 |
| S12 实体表示 | 边界↔体对偶 | 同构层（表示等价） | 层的同构类 |

**定理 4.2（十二结构的组合）**。引擎的任意计算图（节点 ∈ S1–S12）都可分解为

```
C = Op(F_1, …, F_n)   或   C = Flow_t ∘ Op(F_1, …, F_n)
```

其中 `Op` 由四算子生成，`F_i` 是十二结构对应的层。

*证明*。逐结构构造见上表：S1/S7/S9 → 0-层；S2/S11 → 邻域层（`f!`）；S3 → 光滑层上的
流；S4 → 底空间的格结构；S5/S6 → 拉回与谱等价；S8 → 路径空间层 + 推前；
S10/S12 → 同构类判定。组合由定理 5.1（闭合性）保证；顺序无关由 6.1 保证。∎

**推论 4.2.1（真正的缺口）**。S1–S12 已经存在（引擎的节点类型），格已经存在（§25/§26），
缺的**只有中间一层**：**结构之间的组合代数（四算子）**。

```
引擎 = S1–S12（十二结构的特解） + 四算子（缺） + 格（已有）
```

这就是「少量代码」的精确位置：不是重写十二结构，而是补上它们之间的桥。
**30 个 crate 是 30 个孤岛，因为它们在 S1–S12 上各建各的，却没有结构之间的代数。**

**推论 4.2.2（T6 的归属）**。优化（率控、采样分配）不属于 S1–S12——它是 §25 的
「最优性侧」，凸结构。它与 S1–S12 的关系是纤维丛：层提供约束，凸结构提供目标。

**残余缺口（全局逐点算子）**。自动曝光需要全图直方图——它的支撑是全局的，不属于
S2（有限 halo），也不属于 S7（无邻域）。它是「全局归约（S4 的退化）+ 逐点应用（S7）」
的复合，不是新结构。并行性由 §26 的固定形状归约保证。

## 7. 阶段性结论

1. **表示定理不成立（无条件版本）**：模拟（流）与神经渲染（黑箱）是反例。
2. **有条件版本给出 S1–S12 十二结构的组合定理（定理 4.2）**：引擎的节点类型全集
   就是十二个数学结构；每一个都能构造为层（或层 + 结构）；组合由四算子生成。
3. **关键发现（本报告最重要的结论）**：引擎已经有 S1–S12（结构特解）与格（确定性），
   **缺的只有中间一层：结构之间的组合代数（四算子）**。
   ```
   引擎 = S1–S12（已有） + 四算子（缺） + 格（已有）
   ```
   这就是「30 个 crate 是 30 个孤岛」的数学诊断：不是缺结构，是缺结构之间的桥。
4. **优化（T6）不在层框架内**：它是 §25 的「最优性侧」，与层框架构成纤维丛。
5. **求值顺序无关已证**（6.1）；**路径截断误差界已证**（6.2）；**流需要光滑层**（6.3）。
6. **三类结构是维度而非划分**：降噪的多重归属是证据。
7. **可组合性是目标，不是本质**：结构刻画「可组合的视觉计算」，不刻画一切视觉计算。

**净结论**：无条件表示定理为假；引擎内部的表示定理（S1–S12 + 四算子）成立并已证明。
「一次性补齐」的精确位置因此确定：**只补四算子与层核心，不改十二结构**。

代码量：层核心 200 + 四算子 300 + 十二结构适配器 200 + 编排 100 ≈ 800 行，
加八层声明 240–400 行，合计 **1040–1200 行**。十二结构内部的实现（约 17 万行）
一行不动——它们已经是层的内容。

## 8. 下一步研究（部分已推进）

### 8.1 反馈回路的归类——已解决：S2 的无限支撑极限

音频反馈 `y[n] = x[n] + g·y[n−D]` 不是 DAG。分析：

- 稳定条件 `|g| < 1` 时，它是 LTI 系统，等价于卷积核
  `h[n] = g^{n/D}`（n 为 D 的倍数，指数衰减）；
- 支撑无限，但截断误差 `≤ |g|^{N/D}`（N 为窗口长度）；
- **归类：S2（卷积）的无限支撑极限**，不是新结构。误差有界，可按 §25 的
  「逼近阶=质量定价」定价。

**结论**：反馈回路不破坏 S1–S12 的封闭性。

### 9.2 定理：结构无关性

**定理 9.1（结构无关性）**。四算子 `{f*, f*, ⊗, Hom}` 作用于**层**，不作用于
**结构**。因此任何新结构 `S13+`，只要其节点可构造为层（§6.4 的构造），就自动获得

*证明*。四算子的定义只依赖底空间与值域（§3），不依赖节点的 `StructureId`。
层的构造（§6.4）只要求截面是纯函数、定义域是开集——与结构编号无关。∎

**推论 9.1（一次性补齐的真正含义）**。补齐的不是「十二结构」，是**结构无关的组合
代数**。新结构越多，四算子的杠杆越大：一次实现，无限结构受益。

**推论 9.2（S7/S6 的零使用不构成反例）**。S7 零使用说明它未被实现为独立节点，
但 Spring 解析解的数学仍在（可能以 S9 或 S3 的形式接入）。结构编号是工程分类，
不是数学存在性——**数学结构的存在性与是否被登记为节点无关**。

### 9.3 对「十二结构」论断的修正

原论断「引擎 = S1–S12 + 四算子 + 格」应修正为：

```
引擎 = {S1–S12} ∪ {S13+ 自定义}（已有） + 四算子（缺） + 格（已有）
```

四算子对两个集合一视同仁——这正是它的价值。**这也是「30 个 crate 是孤岛」的完整
诊断：孤岛不只是十二个官方结构，还有 72 处自定义结构；桥必须与结构无关，否则
永远追不上新结构的速度。**

## 10. 混合算子的代数分类

### 10.1 问题

层的叠加用混合算子 `⊕_V`。一个问题必须先回答：**哪些算子可以任意重排层的顺序？**

形式化：`⊕` 何时构成 monoid（结合律 + 单位元）？交换性决定顺序是否无关。

### 10.2 四个基本算子的分类

| 算子 | 定义 | 结合律 | 单位元 | 交换 | 结论 |
|---|---|---|---|---|---|
| **over** | `C = C_a + C_b(1−α_a)` | ✅ | 透明（α=0） | ❌ | 非交换 monoid |
| **add** | `C = min(1, C_a + C_b)` | ✅（见 10.3） | 0 | ✅ | 交换 monoid |
| **multiply** | `C = C_a · C_b` | ✅ | 1 | ✅ | 交换 monoid |
| **screen** | `C = 1 − (1−C_a)(1−C_b)` | ✅（同构 multiply） | 0 | ✅ | 交换 monoid |
| **overlay / soft-light** | 分段函数 | ❌（一般） | — | — | **非 monoid** |

### 10.3 钳制加法的结合律（一个小定理）

**定理 10.1**。`a ⊕ b = min(1, a+b)` 在 `[0,1]` 上满足结合律。

*证明*。分情形：
- 若 `a+b ≥ 1`：`(a⊕b)⊕c = min(1, 1+c) = 1`；`a⊕(b⊕c) ≥ min(1, a+b) = 1`。相等。
- 若 `a+b < 1`：`(a⊕b)⊕c = min(1, a+b+c)`；`a⊕(b⊕c)` 分 `b+c ≥ 1` 与否，
  两种情形均化简为 `min(1, a+b+c)`。∎

**意义**：钳制不破坏结合律——因为钳制是「上界投影」，投影与外层 min 交换。
这是一般事实：**任何与 min 交换的单调投影都保持结合律**。

### 10.4 顺序敏感性判据

**定理 10.2**。层的叠加顺序可任意重排，当且仅当使用交换 monoid 算子
（add / multiply / screen）。使用 over 时顺序必须固定（通常按图层序）；
使用 overlay/soft-light 时必须显式规定求值序。

*证明*。交换 monoid 的结合律 + 交换律给出重排不变性；over 的非交换性给出反例
（红 over 蓝 ≠ 蓝 over 红）；overlay 类非 monoid，结合律失效，重排改变结果。∎

**工程含义**：这是「混合模式」在编排层的合法性判据——新增混合模式必须先验证
monoid 律，否则编排不能重排（并行化受限）。

### 10.5 生成性

**定理 10.3**。`{over, add, multiply}` 不能互相生成：over 需要 alpha 通道，
add 无 alpha，multiply 无加法。三者是独立的生成元。

*证明*。反例：add 无法用 over 表示（over 的输出在 alpha=1 时等于上层，add 不是）；
multiply 无法用 over 表示（over 保色相，multiply 改变色相）。∎

**结论**：混合算子族的最小生成元是三个，不是两个。层的代数必须原生支持三者，
不能用一个「万能混合」替代。

## 11. 音频与视觉的同构（Nyquist 横贯的范畴表述）

### 11.1 定理：卷积层的维度无关性

**定理 11.1**。音频滤波（1D 卷积）与图像滤波（2D 卷积）是同一结构（S2 卷积）
在不同底空间上的实例：

```
音频:  F : Sh(T) → Sh(T),   (f*F)(t) = ∫ k(t−s) F(s) ds
图像:  F : Sh(P²) → Sh(P²), (f*F)(p) = ∫∫ k(p−q) F(q) dq
```

两者的代数结构相同（卷积代数：结合、交换、单位元 δ），区别仅在底空间维度。

*证明*。卷积的定义只依赖底空间的群结构（平移）；`T` 与 `P²` 都是平移群，
卷积代数的公理由平移不变性给出，与维度无关。∎

**推论 11.1（代码可共享）**。`prism-audio` 的滤波（低通/高通/混响）与
`prism-postfx` 的滤波（blur/sharpen/halation）在数学上是同一结构——可共享一份
N 维卷积核实现，只在底空间维度上参数化。

**推论 11.2（FFT 同构）**。音频 FFT 与图像 FFT 是同一变换（S6 谱分解）的 1D/2D 实例。
频域乘法定理对两者同形式成立。

### 11.2 边界：合成与和声不是卷积

音频的合成器（振荡器）、和声（音乐理论）、粒化合成**不是**卷积层——它们是：
- 振荡器：自由层（T5 生成，参数 → 波形）
- 和声：语法结构（离散规则，不是连续核）
- 粒化：采样 + 包络（T1 逐点 + 乘法）

**结论**：音频 = 卷积部分（与视觉同构，S2/S6）+ 合成部分（内容层）。
「音频与视觉同构」只在处理侧成立，不在生成侧成立。

### 11.3 对引擎的修正建议

1. `prism-audio` 与 `prism-postfx` 的滤波实现可合并为一个 N 维卷积核（减少重复）；
2. 两者的 FFT 可共享一份 radix-2 实现（不同维度）；
3. 合成/和声保持独立——它们不是卷积，不应强行并入。

## 14. 三个补充结果

### 14.1 `f!` 可由 `f*` 与包含映射导出（8.5.3 解决）

**定理 14.1**。设 `i : S ↪ S'` 为支撑的包含映射。则紧支撑推前

```
f! = f* ∘ i_*
```

*证明*。`i_*` 把 `S` 上的层扩展到 `S'`（`S` 外取空截面）；`f*` 再沿 `f` 推前。
复合只对 `S` 内的部分求和，这正是 `f!` 的定义。∎

**结论**：`f!` 不是原语。四算子 `{f*, f*, ⊗, Hom}` 是最小原语集；
`f!` 是导出算子。实施时只需实现四个原语 + 一个派生。

### 14.2 光滑层的离散化不必连续（6.3 的修正）

**定理 14.2**。XPBD 的时间步进是离散流 `Φ_t : X → X`，构成离散单参数群
（`Φ_{s+t} = Φ_s ∘ Φ_t`）当且仅当步进可逆。位置 Verlet 的步进可逆，故成立。

*证明*。可逆步进的复合满足群律；时间步长 `Δt` 的整数倍构成离散群 `ℤΔt`。∎

**结论**：物理模拟的**实现**不需要连续光滑层——离散流足够。光滑层（diffeology）
只是「连续极限」的表述，不是实现的必需。这简化了 6.3：**离散流是实现的正确层级**。

### 14.3 增量渲染 = 层的导数

**定理 14.3（增量局部性）**。设层族 `F_λ` 依赖参数 `λ`。若 `λ` 的变化只影响底空间
子集 `U`，则 `∂F/∂λ` 的支撑在 `U` 内，增量渲染只需重算 `U`。

*证明*。截面是纯函数；若某截面的表达式不含 `λ`，则其偏导为零；故导数支撑 ⊆
参数出现的位置 `U`。∎

**推论 14.3.1**。增量渲染的正确性 = 层的导数支撑 = 参数依赖的支撑。
这是 `prism-render::incremental` 与 §24「脏区间」的理论基础——**脏区间就是层的
导数的支撑集**。

**推论 14.3.2（缓存的层论表述）**。缓存命中 = 层在参数变化下不变（导数为零）。
签名相等是「导数零」的可判定近似。

| Overlay / Soft Light / Hard Light | 分段 | ❌ | — | ❌ | 非 monoid |
| Color Burn / Color Dodge | 分段 | ❌ | — | ❌ | 非 monoid |
| Hue / Saturation / Color / Luminosity | 通道耦合 | ❌ | — | ❌ | 非 monoid |

### 15.2 证明要点

**Exclusion 的结合律**：令 `u = 1−2a`，则 `1−2(a⊕b) = (1−2a)(1−2b) = u_a u_b`。
Exclusion 通过该变换同构于乘法，故结合。∎

**Difference 不结合**：反例 `a=0.5, b=0.2, c=0.9`：
`(a⊕b)⊕c = |0.3−0.9| = 0.6`，`a⊕(b⊕c) = |0.5−0.7| = 0.2`。∎

**Darken/Lighten 结合**：`min`/`max` 是半格运算（结合、交换、幂等）。∎

**Hue/Saturation/Color/Luminosity 不结合**：它们不是逐通道运算，而是先分解
（色相/饱和度/明度）再重组；分解与重组的复合不满足结合律（重组后再分解不等于原分解）。∎

### 15.3 工程判据（完整版）

**定理 15.1（混合合法性）**。一个混合模式可用于层编排，当且仅当：

1. **可重排**（并行友好）：交换 monoid——Multiply / Screen / Darken / Lighten / Exclusion；
2. **固定顺序**（不可重排）：非交换 monoid——Normal (over)；
3. **显式求值序 + 禁缓存**：非 monoid——Difference / Overlay / Soft Light / Hard Light /
   Color Burn / Color Dodge / Hue / Saturation / Color / Luminosity。

*证明*。由定理 10.2 与 §15.1 的分类表。∎

**推论 15.1.1**。Photoshop 的 27 种混合模式中，只有 6 种（Normal 算固定序）可安全
编排；其余 21 种必须显式求值序，且不能跨帧缓存（顺序敏感 + 非结合）。

**推论 15.1.2**。这解释了为什么「混合模式」在成熟引擎里总是伴随「图层顺序锁定」——
非 monoid 的混合模式不是设计缺陷，是数学必然。

## 16. 固定形状归约的层论表述（§26 的统一）

### 16.1 定理

**定理 16.1**。固定形状归约（§26）是层范畴中**有限余极限的规范构造**。

精确地说：给定有限族 `{F_i}` 与归约算子 `⊕`，其余极限 `colim F_i` 的规范形由
形状函数 `reduction_shape(n)` 给出——形状函数是余极限的**结合序**，与执行拓扑无关。

*证明*。有限余极限 = 有限族的粘合（coproduct 的商）。粘合需要指定结合序；
不同结合序在浮点下不同（加法不结合）。固定形状 = 固定结合序 = 规范形。
形状函数是 `n` 的纯函数 ⟹ 规范形是 `n` 的纯函数 ⟹ 与执行拓扑无关。∎

### 16.2 推论

**推论 16.1.1**。§26 的「并行求值 md5 == 串行求值 md5」不是工程技巧，是
**规范形的纯函数性**：串行是形状函数的退化遍历，并行是同一形状的另一种遍历，
两者结果相同因为形状相同。

**推论 16.1.2**。任何归约点（多采样求积、合成混合、粒子邻居求和）都必须走
形状函数——否则不是「不同的实现」，而是**不同的余极限**（不同的数学对象）。

**推论 16.1.3**。层论的四算子（`⊗` 的逐点定义）与 §26 的固定形状归约是**同一件事**：
`⊗` 在有限底空间上的逐点求值 = 有限余极限 = 固定形状归约。

### 16.3 统一图景

至此，§25（核-对偶-格）、§26（固定形状归约）、本报告（层-四算子）三者关系清晰：

```
§25  核-对偶-格      → 单个计算怎么算（算法层）
§26  固定形状归约    → 计算的并行怎么保持确定性（执行层）= 余极限的规范形
本报告 层-四算子      → 多个计算怎么组合（架构层）
```

三者不是三个理论，是**同一结构的三个投影**：
- 核 = `⊗` 的值域作用
- 格 = 底空间的离散化
- 余极限规范形 = `⊗` 的结合序
- 四算子 = 组合的生成元

## 17. 六种组合方式的翻译（撤回后的第一个真命题）

### 17.1 事实

`prism-core::node::Composition` 定义了六种组合方式：

```
Feed | Chain | Merge(MergeOp) | Csg { op, k } | Mis(w) | Dual
```

### 17.2 翻译表

| 组合方式 | 语义 | 层论表达式 | 值域运算 |
|---|---|---|---|
| `Feed` | 单进单出 | `id`（恒等） | — |
| `Chain` | 串行 `f∘g∘h` | **态射复合 `∘`** | — |
| `Merge(op)` | 多输入归约（over/plus/screen/multiply/mask） | `⊗`（混合算子 = `MergeOp`） | `V` 上的 monoid（逐项验证） |
| `Csg { op, k }` | SDF 布尔（smooth union/intersect/subtract） | `⊗`（值域 = SDF） | `min`/`max` 半格；subtract 非交换 |
| `Mis(w)` | power heuristic 多估计量合并 | `⊗`（值域 = 估计量） | 加权平均（非结合，权重需重算） |
| `Dual` | 表示切换（mesh→SDF） | **同构 `≅`** | — |

### 17.3 定理

**定理 17.1（组合翻译）**。六种组合方式可翻译为 `{f*, f*, ⊗, Hom, ∘}` 的表达式，
翻译保持语义（逐项构造，可检查）。

*证明*。逐项：
- `Feed`：层本身，`id`。∎
- `Chain`：`f∘g` 是层范畴的态射复合（复合是范畴的定义性运算，不需要四算子）。∎
- `Merge`：`⊗` 的定义就是逐点混合；`MergeOp` 给出 `⊗_V`。∎
- `Csg`：SDF 值域上的 `min`/`max` 是 `⊗_V` 的实例（半格）。∎
- `Mis`：估计量值域上的加权平均是 `⊗_V` 的实例。∎
- `Dual`：表示切换是层同构（§4.2），不是算子。∎

### 17.4 发现：基本运算集是五元组，不是四算子

`Chain` 需要**态射复合 `∘`**，而 `∘` 不在四算子中。因此：

```
基本运算集 = {f*, f*, ⊗, Hom, ∘}   （五元组）
```

`∘` 是范畴的定义性运算（没有复合就不叫范畴），实现上免费（Rust 函数调用），
但**理论上必须计入**。报告一「四算子」的说法应修正为「四算子 + 复合」。

### 17.5 推论：`Csg` 与 `Mis` 的代数性质

- `Csg` 的 smooth union（`smin`）**不是半格**——`smin` 不满足结合律（融合半径 `k`
  使运算依赖参数顺序）。所以 `Csg` 的混合算子**不是 monoid**，层顺序敏感。
- `Mis` 的加权平均**不是 monoid**——嵌套时需要重算权重（`p_i` 依赖上下文）。
  所以 `Mis` 的层顺序敏感，且不能跨帧缓存。

**结论**：六种组合方式中，只有 `Merge`（当 `MergeOp` 满足 monoid 时）和 `Feed`
可任意重排；`Chain` 顺序敏感（定义如此）；`Csg`/`Mis`/`Dual` 顺序敏感或不适用。

## 18. halo 正确性（一条不需要测试的定理）

### 18.1 定义

**定义 18.1（r-局部算子）**。设 `Ω` 为像素网格，`I: Ω → V` 为图像，`T: V^Ω → V^Ω`
为算子。称 `T` 是 **r-局部**的，若对任意 `I, I'` 与 `p ∈ Ω`：

```
I|_{B(p,r)} = I'|_{B(p,r)}  ⟹  T(I)(p) = T(I')(p)
```

其中 `B(p,r)` 是 `p` 的 r-邻域（与 `Ω` 的交）。

### 18.2 定理

**定理 18.1**。设 `T` 是 r-局部算子，`{B_i}` 是 `Ω` 的 tile 覆盖，halo 半径 `h ≥ r`。
则对任意 `I` 与 `p ∈ B_i`：

```
T(I|_{B_i^h})(p) = T(I)(p)
```

即 tile 局部求值在核心区与全局求值**逐点相等**。

*证明*。由 halo 定义，`B(p,r) ⊆ B_i^h`（因为 `p ∈ B_i`，`B(p,r)` 与 `Ω` 的交在
`B_i` 外扩 `r` 内，而 `h ≥ r`）。故 `I|_{B_i^h}` 与 `I` 在 `B(p,r)` 上相等。
由 r-局部性，`T(I|_{B_i^h})(p) = T(I)(p)`。∎

**这个证明不需要测试**：它从定义出发，逐步推导，结论对所有 `I`、`p`、`T` 成立。

### 18.3 实现条件（测试的对象）

定理 18.1 给出的是**实数域上的逐点相等**。要实现「逐字节相等」，还需一个**实现条件**：

> **条件 E**：局部求值与全局求值使用相同的浮点运算序列（同一归约形状、同一结合序）。

条件 E 不是数学命题，是**实现约束**——它需要测试（或代码审查）来保证。
`§26` 的固定形状归约正是为满足条件 E 而设计的。

**区分**：
- 定理 18.1：数学，不需要测试；
- 条件 E：实现约束，需要检查；
- 「逐字节一致」：两者合起来才成立，其中数学部分已证，实现部分靠纪律。

### 18.4 边界情形

帧边界的 tile 使用钳制（不环绕）。钳制只减少输入集合（帧外无数据），
不改变 `B(p,r) ∩ Ω` 的定义——定理 18.1 仍然成立。

### 18.5 推论

**推论 18.1.1**。halo 半径必须 ≥ 算子的局部性半径 `r`。这是**定义性要求**，
不是经验规则——`h < r` 时 `B(p,r) ⊄ B_i^h`，定理的前提不成立。

**推论 18.1.2**。支撑半径无限的算子不是任何有限的 r-局部算子，故不存在有限的
halo 使其 tile 一致。这是「全局直方图不可 tile 化」的**证明**（不是观察）。

## 19. 签名的完备性（撤回 5.4 后的真结果）

### 19.1 定理

**定理 19.1（签名的必要性）**。若 `F ≅ G`（层同构），则 `K(F) = K(G)`（假设哈希无碰撞）。

*证明*。层同构保持一切依赖关系；签名是依赖闭包的哈希；故同构的层有相同的签名。∎

**定理 19.2（签名的非充分性）**。存在 `F ≇ G` 使 `K(F) = K(G)`。

*证明*。哈希输出空间有限（256 位），层空间无限（连续参数），由鸽笼原理存在碰撞。∎

**结论**：签名是**必要不充分**的。缓存正确性是**概率性**的，依赖哈希碰撞概率
（§25 的 Merkle 保证书：10⁹ 条目下碰撞概率 ~10⁻⁵⁹）。

### 19.2 推论

**推论 19.2.1（缓存正确性的准确定位）**。缓存正确性 = 「签名必要 + 碰撞概率可忽略」，
不是「签名完全不变」。原定理 5.4 的「条件性」应改为「概率性」。

**推论 19.2.2（依赖闭包的完备性）**。要使签名**必要**，依赖闭包必须覆盖层的全部
依赖（§25 的 T5 讨论）。否则存在「依赖不同但签名相同」的情况——这是**设计缺陷**，
不是碰撞。

**推论 19.2.3（工程判据）**。缓存系统必须满足：① 依赖闭包完整（必要性）；
② 哈希 256 位（碰撞概率）；③ 碰撞可检测（可选：双哈希）。三条缺一不可。

**状态**：原命题撤回；修正版对交换混合算子成立，对 over 未证。

### 20.3 截断误差界（报告二 6.2）——补 `‖T‖ ≤ ρ_max`

**引理 20.1**。漫反射场景的光传输算子 `T` 满足 `‖T‖ ≤ ρ_max`，其中 `ρ_max` 是最大反照率。

*证明*。`(TL)(x) = ρ(x) ∫ K(x,y) L(y) dy`，几何核 `K` 归一化（`∫ K(x,y) dy = 1`，
能量守恒）。故 `|(TL)(x)| ≤ ρ_max · max_y |L(y)|`，取上确界得 `‖TL‖_∞ ≤ ρ_max ‖L‖_∞`。∎

**状态**：命题真，证明补全（条件是「漫反射 + 归一化核」）。

### 20.4 卷积维度无关（报告二 11.1）——限定边界

**修正命题**。设 1D 与 2D 卷积使用**同一类边界条件**（周期 / 零填充 / 镜像）。
则两者的代数结构相同（结合、交换、单位元为 δ）。

*证明*。边界条件定义了一个线性算子（Toeplitz/循环矩阵）；卷积代数的公理由

**状态**：命题真，但需限定「同一类边界条件」。原表述（无条件）过强。

### 20.5 `f! = f* ∘ i_*`（报告二 14.1）——严格定义 `i_*`

**定义 20.1**。`i : S ↪ S'` 为包含。`i_* : Sh(S) → Sh(S')` 是**左 Kan 扩展**：

(i_*F)(U') = colim_{i(U) ⊆ U'} F(U)      （U' ⊆ S' 的开集）

`U'` 不含 `S` 中的点时，colim 为空（初始对象）。

## 22. 逐项核对（源码级，发现三处新错误）

### 22.1 `MergeOp` 五项全验（核对 `prism-core/src/compose.rs:82`）

| MergeOp | 实现 | 结合 | 单位元 | 交换 | 判定 |
|---|---|---|---|---|---|
| Over | `a(1−αb)+b·αb` | ✅ | 透明 | ❌ | 非交换 monoid |
| Plus | `a+b`（**无钳制**） | ✅ | 0 | ✅ | 交换 monoid |
| Screen | `1−(1−a)(1−b)` | ✅ | 0 | ✅ | 交换 monoid |
| Multiply | `a·b` | ✅ | 1 | ✅ | 交换 monoid |
| Mask | `a·αb` | ✅ | α=1 | ❌ | 非交换 monoid |

**发现（错误三）**：`Plus` 的源码实现是**无钳制加法** `a+b`，不是 `min(1,a+b)`。
定理 10.1 证的是钳制加法——**证明对象错误**。无钳制加法同样结合（普通加法），
但值域可越界 `[0,1]`，需要后续钳制/色调映射。定理 10.1 应改述为「对钳制加法成立；
引擎现用无钳制加法，两者均结合」。

**Mask 结合律验证**：`mask(mask(a,b),c) = a·α_b·α_c = mask(a, mask(b,c))`（因
`mask(b,c)` 的 alpha = `α_b·α_c`）。✅

### 22.2 `CsgOp` 平滑布尔不结合（反例搜索）

**反例搜索**（k=1，9³ 组合）：`smin` 在 **729 个组合中 632 个不满足结合律**。

最小反例：`a=0, b=0, c=0.1, k=1`：

```
(a⊕b)⊕c = −0.355625
a⊕(b⊕c) = −0.361502     差 0.0059
```

**结论**：`SmoothUnion / SmoothIntersect / SmoothSubtract` **不是 monoid**，
CSG 层顺序敏感。`Union / Intersection`（min/max）是半格，✅ 交换 monoid。
`Subtract` 非交换、非结合（`a−b ≠ b−a`，且嵌套依赖顺序）。

### 22.3 组合方式翻译的三处修正（核对 `Composition` 定义）

| 组合方式 | 上一版判定 | 核对后 | 错误性质 |
|---|---|---|---|
| `Feed` | `id` | ✅ `id` | — |
| `Chain` | 层态射复合 | **`V` 的自同态复合** | 层无法复合（靶是 V，非 S^op） |
| `Merge` | `⊗` | ✅ `⊗` | — |
| `Csg` | `⊗`（SDF 值域） | ✅ `⊗`，但平滑布尔非 monoid | 需补 22.2 |
| `Mis` | 纯 `⊗` | **`Hom` + `⊗`** | 权重 `p_i` 依赖上下文 |
| `Dual` | 严格同构 | **ε-同构** | bake 有精度损失 |

**修正后的三层结构**：

```
Sh(S) 层面：四算子（f*, f*, ⊗, Hom）
V 层面：自同态复合（Chain）、混合算子（MergeOp/CsgOp/Mis 的权重）
表示层面：ε-同构（Dual）
```

「五元组」作废——`∘` 不在 `Sh(S)`，在 `V`。

## 23. 卷积不是 `⊗`（错误四，影响后期与音频两层）

### 23.1 错误

报告一 §4.4 把「后期层」的算子位置写成 `⊗`（卷积）。**错误**。

`⊗` 的定义是**两个层的逐点叠加**（`(F⊗G)(U) = F(U)⊗_V G(U)`）；
卷积 `k∗F` 是**一个层被核作用**，输出仍是单层。两者类型不同：
`⊗ : Sh × Sh → Sh`，卷积 `: Sh → Sh`（自同态）。

### 23.2 卷积的真实位置：推前的积分

设 `τ_s` 为平移 `s` 的拉回/推前对。则

```
(k ∗ F) = ∫ k(s) (τ_s)_* F ds
```

卷积是**推前 `f*` 沿平移群的积分**（加权和）。它不是新的原语：
- 若平移群离散（格），积分退化为求和 `Σ_s k(s) (τ_s)_* F`；
- 若核的支撑有限（半径 `r`），求和只有 `(2r+1)^d` 项。

**结论**：卷积由 `f*` 生成（通过有限求和），不需要第五个算子。

### 23.3 两层归类的修正

| 层 | 上一版算子位置 | 核对后 |
|---|---|---|
| 后期 | `⊗`（卷积）+ `Hom` + `f!` | **`f*` 的积分（卷积）** + `V` 自同态（调色）+ `⊗`（混合） |
| 音频（处理） | `f*` + `⊗` + `Hom` | **`f*` 的积分（滤波/混响）** + `⊗`（混音）+ `Hom`（反应） |

**影响**：`⊗` 只负责「多个层的叠加」（混音、图层合并、多估计量合并），
不负责「单个层的变换」（滤波、卷积、调色）。混淆这两者会导致：
- 误以为「卷积层的可重排性」由 `⊗` 的 monoid 性决定——实际由**核的卷积代数**决定
  （卷积本身交换结合，所以卷积链可重排，与 `⊗` 无关）；
- 误以为「调色链」需要 `⊗`——实际是 `V` 的自同态复合（`Chain` 的特例）。

### 23.4 核对结论

卷积的代数性质（交换、结合、单位元 δ）来自**卷积代数**，与层的 `⊗` 无关。
两个代数独立：
- 卷积代数：`(L¹(G), ∗)`——用于滤波；
- 层叠加代数：`(V, ⊗_V)`——用于合成。

**这是「后期层」与「编排层」分开的数学理由**：前者用卷积代数，后者用混合代数。

## 25. 核对结果：S1/S11 的翻译修正 + 一条新定理

### 25.1 S11 不是热核（修正）

`postfx/effects/bloom.rs` 的实现：**亮部提取 + 全分辨率可分离 box blur + 线性加算**。
不是热核幂，是 box 核卷积。

**修正后的翻译**：S11 = `∫ box_r(s)(τ_s)_* F ds`（box 核的推前积分）——
仍是卷积，仍由 `f*` 生成，结论（「S11 可用四算子表达」）不变，但**核的形式**要说准。

### 25.2 S1 不是自由层（修正）

`prism-noise/fbm.rs`：fbm = `Σ_{n<octaves} gain^n · noise(lacunarity^n · x)`。
这是**固定公式的多倍频叠加**，不是自由生成（自由层需要「生成元 + 关系」，fbm 没有）。

**修正后的翻译**：S1 = `f*`（域变换：坐标缩放）+ `V` 的逐点函数（噪声求值）+ `⊗`（叠加）。
「自由层」用于**真正的语法生成**（L-system、细胞自动机），不用于噪声。

### 25.3 定理：tile 化的必要条件（来自实现反例）

**定理 25.1**。一个效果可 tile 化（tile 拼接与整幅**逐字节一致**），仅当它是
**平移不变 + 有限支撑**的算子。

*证明*。

- **有限支撑**：若支撑无限，halo 半径无界，tile 无法覆盖输入（推论 18.1.2）。
- **平移不变**：若算子依赖绝对坐标（或窗口原点的相位），则 tile 内的行为与整幅不同。
  `bloom.rs` 文档给出了具体反例：半分辨率金字塔的半分辨率网格相位取决于
  `tile.x − halo` 的奇偶，窗口原点为奇数时与整幅错位半格——**halo 补足也无法修复**。
- 两者缺一，逐字节一致不成立。∎

**推论 25.1.1（可 tile 化的效果清单）**。blur / bloom（box 核）/ sharpen / grain（无邻域）
可 tile 化；半分辨率金字塔、依赖绝对坐标的着色、全局直方图**不可**。

**推论 25.1.2（工程判据）**。新效果的 tile 化审查：先问「平移不变吗」，再问「支撑有限吗」。
两问有一问答否，不应申报 `halo_radius`，应走全帧求值。

**注 25.1**。这条定理不是我发明的——它是 `bloom.rs` 的实现注释里写出来的，
我只是把它形式化了。这印证了「结构是发现不是设计」：引擎的实践里已经有数学，
缺的是把它提炼出来。

## 26. S8 核对：引擎用 RR，不用截断（错误十三）

### 26.1 事实

`prism-rt/integrator.rs`：**无 `max_depth`**，路径终止由 RR（俄罗斯轮盘赌）保证
（`SLOT_RR = 4`，`next_ev ≥ 3` 时按 throughput 最大分量存活）。

### 26.2 定理 6.2 的对象错误

§6.2 证明的是「k 次弹射截断」的误差界 `L_max·ρ_max^k/(1−ρ_max)`。
**引擎不用截断**——RR 是无偏的，误差是**方差**，不是截断偏差。

**修正后的误差结构**：

| 方案 | 偏差 | 方差 | 收敛率 |
|---|---|---|---|
| k 次截断 | `O(ρ^k)` | 有限 | 偏差主导（k 小时） |
| RR | **0（无偏）** | 有限（策略依赖） | `O(1/√N)` |

**结论**：§6.2 的界对「截断方案」成立，但对引擎的 RR 方案**不适用**。
这是一个「证明了一个不用的东西」的错误，与定理 10.1（钳制加法）同类。

### 26.3 修正后的 S8 翻译

S8 = `f*`（路径空间推前）+ **RR 无偏估计**（不是截断）。
路径空间不是「≤ k 的路径集合」，是「RR 终止的全路径集合」——后者是无限的，
但 RR 保证几乎必然终止（`ρ < 1`），故期望有限。

## 28. S4 核对：Sobol 是数字序列，不是格（错误十四）

### 28.1 事实

`prism-rt/sampler.rs`：

- Sobol 索引 = `样本序号 ⊕ c`（`c` 来自 `hash(种子, 像素)`）；
- **线性性**：`Sobol(i⊕c) = Sobol(i) ⊕ Sobol(c)`——异或是 F₂ 上的加法；
- 坐标 = `Sobol(i, 维度) ⊕ 打散掩码`；
- 文档明写：**禁止把 hash 值直接当索引**。

### 28.2 数学结构：数字序列，不是格

Sobol 是**数字序列**（digital sequence）：在有限域 `F₂` 上，由方向数矩阵的线性组合生成
（`Sobol(i) = ⊕_{k: i_k=1} V_{k+1}`），前 `2^m` 点构成 `(t,m,s)`-net。

这与**格规则**（lattice rule，`{k·z/n mod 1}`）是**两种不同的低差异序列**：
- 数字序列：F₂-线性，`(t,m,s)`-net；
- 格规则：`Z^d` 上的点阵，对偶格理论。

**修正**：S4 的翻译是「数字序列（F₂-线性）+ **整数索引格**（`Z^k`，§25 的格锚）」。

两个「格」不能混：
- §25 的格 = 整数格 `Z^k`（确定性锚点，hash/索引/帧号）；
- lattice rule 的格 = 欧氏空间点阵（另一种采样方案，引擎未用）。

### 28.3 定理：采样收敛率的索引条件（来自实现文档）

**定理 28.1**。设采样器为 Sobol 数字序列，索引集为 `{i ⊕ c : 0 ≤ i < N}`（线性平移）。
则收敛率 `O(1/N)`。若索引为任意置换（如 `index = hash(...)`），收敛率退化为 `O(1/√N)`。

*证明（要点）*。线性平移保持 `(t,m,s)`-net 性质（异或是 F₂-线性映射，保持 net 的
结构）；任意置换破坏 net 的均匀性，等价于在 `2³²` 网格上 iid 抽点，故退化为 MC 的
`O(1/√N)`。∎

**注 28.1**。这条定理来自 `sampler.rs` 的实现文档（原话：「禁止把 hash 值直接当索引——
那是对索引空间的任意置换 = 从 2³² 网格 iid 抽点，O(1/N) 退化为 O(1/√N)」）。
我只是把它形式化。**这再次印证：引擎的实践里已有数学，研究是提炼，不是发明。**

### 28.4 对「格锚定」的精确化

§25 的「格」有三个层次，此前被我混为一谈：

| 层次 | 对象 | 例子 |
|---|---|---|
| 整数格 `Z^k` | 索引/帧号/样本序号/维度 | Sobol 索引 `i`、帧号、hash 输入 |
| 定点格 | 定点算术的离散值域 | Q32.32 相位、定点 DCT 权重 |
| 数字序列的 net | F₂ 上的线性结构 | Sobol 点集 |

「确定性 = 格锚定」指的是前两层；第三层是**采样的均匀性结构**，不是确定性结构。
两者共同构成采样器，但数学对象不同。

## 29. 净结论：七条经验观察（**不是定理**）

> **总声明（先读）**：本节及后续所有「判据」一词，一律指**经验观察**，不是数学定理。
> 它们来自「读源码 + 数值测试」，需要测试继续支撑；**数学证明不需要测试**，
> 需要测试的就不是证明。本报告真正构成证明的只有：§18.1（r-局部 + halo ≥ r ⟹ tile 一致）、
> §37（Porter–Duff 结合律）、§45（ε-同构传播）、§46（混合算子 Lipschitz 常数）。
> 其余全部是归纳，不是演绎。

经过全部核对，框架的可用产出不是定理集，而是**七条经验观察**（判据一至六在本节，
判据七在 §33）。每条都注明来源（实现事实 / 数值测试）与反例或证据。

### 判据一：可 tile 化 ⟺ 平移不变 + 有限支撑

- **来源**：定理 25.1 + `bloom.rs` 的半分辨率金字塔反例；
- **检查方法**：问「效果是否依赖绝对坐标（相位/窗口原点）」+「支撑是否有限」；
- **反例**：半分辨率金字塔（相位依赖）不可 tile 化，halo 补足无效。

### 判据二：采样索引必须线性平移，不能任意置换

- **来源**：定理 28.1 + `sampler.rs` 的实现文档；
- **检查方法**：`index = i ⊕ c`（线性平移）✅；`index = hash(...)`（任意置换）❌；
- **后果**：任意置换使收敛率从 `O(1/N)` 退化为 `O(1/√N)`。

### 判据三：混合算子可任意重排 ⟺ 交换 monoid

- **来源**：定理 10.2 + `compose.rs` 的实现核对；
- **分类**：Over/Mask（非交换 monoid，固定顺序）；Plus/Screen/Multiply（交换 monoid，可重排）；
  SmoothUnion/Intersect/Subtract（非 monoid，反例 632 个）；
- **检查方法**：验证结合律 + 单位元 + 交换律，三项齐全才可重排。

### 判据四：缓存正确 ⟺ 依赖闭包完整 + 哈希碰撞概率可忽略

- **来源**：定理 19.1/19.2 + `signature.rs`（「256 位哈希以无碰撞为公理」）；
- **检查方法**：① 依赖闭包覆盖全部输入（含 `Composition`、`NodeId`、`global_seed`）；
  ② SHA-256；③ 版本入键（`schema_version`/`engine_version`）；
- **边界**：签名是必要不充分的（碰撞），正确性是概率性的。

### 判据五：增量正确 ⟺ 导数支撑 = 参数依赖支撑

- **来源**：定理 14.3 + `signature.rs` 的子树哈希（「改一个节点只影响祖先链」）；
- **检查方法**：脏区间的定义 = 参数变化的节点到根的路径；
- **等价**：子树哈希的「兄弟不变」性质就是这条判据的实现。

### 判据六：卷积链可重排（卷积代数），与层混合（`⊗`）无关

- **来源**：§23 的核对（卷积 = `f*` 的积分，不是 `⊗`）；
- **含义**：滤波链的顺序无关性由卷积代数的交换律保证；层叠加的顺序无关性由
  `⊗` 的 monoid 性保证。**两个代数独立，不能互相推断。**

## 31. 定理 4.1 的追问：四算子能覆盖 `Chain` 吗？

### 31.1 问题重述

DAG 的求值 = 节点的复合。节点的组合方式有六种（§17）。其中 `Chain` 是**值域复合**：

```
F_v = φ_v ∘ F_in        （φ_v : V → V 是值域自同态）
```

问题：`φ_v ∘ F_in` 能否由四算子 `{f*, f*, ⊗, Hom}` 表达？

### 31.2 尝试一：把 `Chain` 归约为 `Hom`

在闭合 monoidal 范畴中，逐点自同态可由内 Hom 表达：
`Hom(F, G)(U) = Hom_V(F(U), G(U))`。

但这条路要求 **`V` 是闭合范畴**（对象是类型、态射是函数）。而 `V` 是**值域**
（像素值/几何值/掩码），不是范畴——除非把 `V` 看成离散范畴（只有恒等态射），
那样 `Hom_V` 是平凡的，没有内 Hom。

**结论**：`V` 不是闭合范畴，「`V` 闭合」的说法是**类型错误**。

### 31.3 尝试二：把 `Chain` 看成层的逐点态射

`φ_* : Sh(S) → Sh(S)`，`(φ_* F)(U) = φ(F(U))` 是**逐点函子**。
它是层范畴的自同态，不是四算子。

四算子的类型：`f*, f* : Sh(S) → Sh(S')`（底空间变换）、`⊗, Hom : Sh × Sh → Sh`（层组合）。
逐点自同态的类型：`End(V) → End(Sh(S))`（值域自同态的逐点提升）。

**类型不同**：四算子作用于**底空间与层的组合**，逐点自同态作用于**值域**。
两者不在同一层。

### 31.4 否定性结论

**命题 31.1（四算子不覆盖 Chain）**。存在由 S1–S12 节点组成的 DAG，其求值不能
仅由四算子表达——`Chain` 组合方式需要值域自同态 `End(V)`。

*论证*。取最简单的 `Chain`：一个调色节点（`V` 的逐点函数 `φ`）作用于一个层 `F`。
若 `φ ∘ F` 可由四算子表达，则 `φ` 必须是四算子的某个实例。但四算子的输出类型是层，
`φ` 的输入类型是值域——除非 `φ` 能提升为层的算子。逐点提升 `φ_*` 不是四算子
（四算子不作用于值域），故 `φ ∘ F` 不能仅由四算子表达。∎

**这不是伪证**：它依赖「四算子不作用于值域」这一类型事实，可逐步检查。
但它也**不是强定理**：它只是说「四算子不够，还需要逐点自同态」，没有说「需要多少」。

### 31.5 修正后的基本运算集

```
基本运算 = 四算子（底空间变换 + 层组合） + 逐点自同态 End(V)（值域变换） + 同构
```

三个层次，不是一个。**「四算子覆盖一切」是假的**——这是定理 4.1 的最终答案。

### 31.6 `Chain` 的代数

**命题 31.2**。`Chain` 的求值是 `End(V)` 的 monoid 复合：`φ_n ∘ … ∘ φ_1`。

*证明*。`Chain` 定义为串行复合，复合是 `End(V)` 的乘法。∎

**推论 31.2.1**。`Chain` 链的可重排性 ⟺ `End(V)` 的交换性。调色算子一般非交换
（`grade` 与 `blur` 不可换），故 `Chain` 顺序敏感。

### 31.7 这对「少量代码」意味着什么

修正后的骨架需要：
- 四算子（约 300 行）
- `End(V)` 的 monoid（约 50 行：一个 trait `VEndo { fn apply(&self, v: V) -> V }` + 复合）
- 层核心（约 200 行）
- 合计约 550 行（不含十二结构适配器与八层声明）。

**比上一版更少，因为承认了 `Chain` 是简单的 monoid，不需要算子框架。**

## 32. 接口粒度：现有 API 不是逐点，是批处理

### 32.1 观察

检查现有 crate 的接口形态：

| crate | 接口 | 粒度 |
|---|---|---|
| `prism-postfx` | `TileEffect::eval_window(&self, window: &Fbuf16F) -> Fbuf16F` | **窗口（批）** |
| `prism-text` | `layout_text(...) -> Vec<GlyphRun>` + `draw_glyphs(...)` | **批量** |
| `prism-audio` | `render_note(...) -> Vec<f32>` | **整段（批）** |
| `prism-particles` | `pool.view_at(t) -> Vec<ParticleView>` | **整批粒子** |
| `prism-rt` | `render_frame(scene, ...) -> Framebuffer` | **整帧** |

**全部是批处理**，没有一个是逐点 `(t,p) → v`。

### 32.2 层接口的形式化错误

我在 §12 设计的 `Layer::section(&self, t, p) -> V` 是**逐点接口**——与现有 API 不匹配。

若强行逐点调用，代价是：
- 每个像素调用一次 `eval_window`（窗口 = 1×1），halo 机制失效；
- 粒子/音频的批量计算被拆成 N 次单点调用，失去缓存与向量化；
- 性能退化为 O(像素数 × 窗口计算)，不可接受。

**修正**：层的接口必须是**批处理**：

```rust
pub trait Layer {
    type Value;
    fn domain(&self) -> Domain;
    /// 在一个窗口（tile × 时间区间）上求值——批处理，不是逐点。
    fn eval_block(&self, block: &Block) -> BlockOutput<Self::Value>;
    fn halo(&self) -> Halo;      // 空间/时间 halo
}
```

这与 `TileEffect` 的设计一致（`eval_window` + `halo_radius`）。

### 32.3 推论：`TileEffect` 已经是层

`TileEffect` 满足：
- `eval_window`：批处理求值；
- `halo_radius`：空间 halo；
- 判据一（平移不变 + 有限支撑）：由 `halo_radius` 的申报保证。

**结论**：`TileEffect` 是「层」的一个现成实现（底空间 = 像素格，时间 = 单帧）。
不需要改写——只需要**把 `Layer` trait 设计成 `TileEffect` 的超集**。

### 32.4 对代码量的影响

若 `Layer` 与 `TileEffect` 同构：
- `prism-postfx` 的全部效果**零修改**接入；
- `prism-render` 的 tile 协议**零修改**复用；
- 新的 `Layer` trait 只是 `TileEffect` 加上「时间维度」与「多层混合」。

**修正后的代码量**：
- 层核心（批处理 + halo + 粘合）：约 150 行
- 四算子（底空间变换 + 层组合）：约 300 行
- `End(V)` monoid：约 50 行
- 十二结构适配器：约 200 行（每个 15–20 行，因为大部分已是纯函数）
- 八层声明：约 200 行
- **合计约 900 行**（与上一版接近，但**改动现有代码接近零**）

### 32.5 真正的工程难点

不是「写骨架」，是**接口粒度统一**：
- `TileEffect`（窗口）与 `Layer`（块）需要统一——块 = 窗口 + 时间区间；
- `prism-audio` 的 `render_note`（整段）需要切成块求值——但音频的块 = 采样区间，
  与图像块同构（都是「底空间的开集」）；
- `prism-rt` 的 `render_frame`（整帧）需要支持 tile 化——已有 `TileEffect` 的先例。

**结论**：接口粒度统一的成本主要在 `prism-rt` 与 `prism-audio` 的块化改造，
不在新骨架。这是**重构**，不是**新增**——「少量代码」的说法要打折扣。

## 33. 可块化判据（判据七）

### 33.1 问题

块化（tile / 区间 / 帧段）要求：块独立求值 + 粘合。什么计算满足？

### 33.2 判据

**定理 33.1（可块化判据）**。一个计算可块化，当且仅当它是以下之一：

- **(a) 无记忆**：输出只依赖当前块的输入（如逐像素着色、卷积、路径追踪）；
- **(b) 状态可参数化**：块求值需要「初始状态」作为显式参数，粘合时传递状态
  （如 IIR 滤波、XPBD 步进）。

两者都不满足的计算（如全局归约、自适应采样分配）**不可块化**。

*证明*。
- (a)：块独立，粘合由公理 L 给出（每个点属于某块）。∎
- (b)：块 `[n₀, n₁)` 的求值 = `Φ(x_{n₀}, 输入)`，其中 `x_{n₀}` 是初始状态；
  粘合需要前一块的末状态 `x_{n₁}` 作为下一块的初状态——状态传递是粘合的一部分。∎
- 反例：全局直方图需要所有块的统计量，块之间不是「传递状态」，是「全局依赖」——
  任何块顺序都改变结果（浮点归约），故不可块化。∎

### 33.3 推论

**推论 33.3.1（引擎的块化清单）**：
- 可块化（a）：`prism-postfx`（无记忆卷积）、`prism-rt`（像素独立）、`prism-text`（逐字形）；
- 可块化（b）：`prism-audio` 的 IIR/混响、`prism-physics` 的 XPBD 步进；
- 不可块化：自适应采样分配、全局自动曝光、全局直方图。

**推论 33.3.2（两遍法）**：不可块化的计算可以「两遍化」——第一遍全局归约（固定形状），
第二遍逐块应用。两遍法把「不可块化」转为「可块化 + 一次全局归约」。

**推论 33.3.3（判据一与判据七的关系）**：
- 判据一（tile 化）是判据七在「无记忆 + 平移不变 + 有限支撑」下的特例；
- 判据七更一般：它覆盖带状态的块化（音频、物理）。

### 33.4 状态传递的代数

带状态的块化需要「状态传递」：`x_{n₁} = Φ(x_{n₀}, 输入块)`。
这是**状态转移函数**的复合：

```
Φ_total = Φ_{N} ∘ … ∘ Φ_1
```

**观察**：状态传递的复合 = `End(X)` 的 monoid（`X` = 状态空间）。
这与 `Chain` 的 `End(V)` monoid 同构——**状态传递和值域复合是同一个数学结构**。

**推论 33.4.1**：带状态块化的骨架 = `End(X)` monoid + 块求值。
不需要新的数学——`End` monoid 已经在 §31 引入。

**修正**：`Chain` 与状态传递是 `End` monoid 的实例；**增量不是**。
增量是差分 `ΔF = F_{t+1} − F_t`，属于 `Sh(S, V)` 的**向量空间结构**（若 V 是向量空间），
不是自同态的复合。「增量也是 End monoid 的实例」是错的，撤回。

## 34. 值域代数：两类运算

### 34.1 分类

值域 `V` 上的运算分两类：

**(一) 一元**：`End(V)` 自同态的 monoid（复合）。
实例：调色（grade/LUT/曲线）、色调映射、gamma、色彩空间转换。

**(二) 二元**：`V × V → V` 混合算子。
实例：`MergeOp`（Over/Plus/Screen/Multiply/Mask）、`CsgOp`、`Mis` 加权平均。

**两者不同类**：前者是 monoid（一个集合 + 复合 + 单位元）；后者是多个二元运算的集合，
每个满足不同的代数律。

### 34.2 一元与二元的交互

`φ(a ⊕ b) =? φ(a) ⊕ φ(b)`——**一般不成立**（除非 φ 线性且 ⊕ 线性）。

反例（可验算）：`φ = gamma 2.2`，`⊕ = Plus`，`a=b=0.5`：
- `gamma(0.5+0.5) = gamma(1.0) = 1.0`
- `gamma(0.5)+gamma(0.5) = 2×0.5^2.2 ≈ 0.435 ≠ 1.0`

**结论**：调色与混合**不可交换顺序**。这是调色链位置（线性域 vs 显示域）的数学理由。

## 35. Over 不是标准 Porter–Duff（数值验证，推翻三处断言）

### 35.1 实验

对引擎的 `over`（`out_rgb = a(1−αb) + b·αb`，`α = αb + αa(1−αb)`）与标准
Porter–Duff（`out_rgb = (αa·a(1−αb) + αb·b)/α_out`）各做 20000 组随机三重合成测试：

| 实现 | 不结合组数 | 最大偏差 |
|---|---|---|
| **标准 Porter–Duff** | **0 / 20000** | 0.000000 |
| **引擎 over** | **20000 / 20000** | **0.234341** |

手算实例（红 α=1，绿 α=0.5，蓝 α=0.3）：

```
(a over b) over c = [0.35, 0.350, 0.300, 1.0]
a over (b over c) = [0.35, 0.455, 0.195, 1.0]      绿通道差 0.105
```

### 35.2 原因

引擎实现缺两项：
1. **下层权重 `αa`**——RGB 混合未乘下层的 alpha；
2. **输出归一化 `/α_out`**——未按合成后的 alpha 归一化。

两项都在 `αa = 1` 时退化为 1，所以**不透明下层时数值碰巧接近**，但嵌套后 alpha 复合，
偏差暴露（§35.1 的「下层不透明」测试同样 20000 组全部失败，证明不是「半透明才错」）。

### 35.3 推翻的断言

1. **「Over 是非交换 monoid」**（§15.1）——假。Over 连结合律都不满足。
2. **「五个 MergeOp 都是 monoid」**（§22.1）——假。只有 Plus/Screen/Multiply/Mask 是
   monoid；Over 不是。
3. **判据三的分类表**——需改：Over 标「非结合（引擎实现偏离标准）」。

### 35.4 数学后果

**命题 35.1**。引擎的 over 不满足结合律，故图层嵌套的**括号化改变结果**。
「图层树」的语义不是结合的——树的结构（不只是层的顺序）进入结果。

**推论 35.1.1**。图层树不能用「扁平列表 + 归约」表达（归约假设结合律）；
必须保留树结构，或改用标准 Porter–Duff（结合）。

**推论 35.1.2**（工程建议，非数学）。若要保持「扁平列表」的简化，应把 over 改为
标准 Porter–Duff（增加两项运算）；若不改，文档必须声明「图层树不可扁平化」。

### 35.5 这次验证的意义

这条结论不是「读代码读出来的」，是**算出来的**——20000 组随机测试推翻了我自己
写了 1000 行的判定。这才是验证的用法：不是证明自己对，是**找自己的反例**。

## 36. 验证的陷阱：分布选择改变结论

### 36.1 实验

对 `Subtract(a,b) = max(a, −b)` 做结合律测试，两种分布：

| 分布 | 不结合组数 | 最大偏差 | 第一个反例 |
|---|---|---|---|
| `[0,1]`（颜色域） | **0 / 20000** | 0.000000 | 无 |
| `[−1,1]`（SDF 实数域） | **10776 / 20000** | 1.988746 | `a=0.298, b=0.802, c=−0.774` |

反例展开：
```
(a−b)−c = max(max(0.298,−0.802), 0.774) = 0.774
a−(b−c) = max(0.298, −max(0.802,0.774)) = 0.298      差 0.476
```

### 36.2 结论

**结合性不是算子的固有属性，是「算子 + 值域」的属性。**

- 同一个 `max(a,−b)`：在 `[0,1]` 结合，在 `ℝ` 不结合；
- 原因：`[0,1]` 上 `−b ∈ [−1,0]`，`a ≥ 0` 恒成立，`max(a,−b) = a` 退化为「取 a」
  （投影算子），自然结合；`ℝ` 上不退化，反例出现。

**推论 36.2.1（判据三的精确化）**：混合算子的结合律判定必须**声明值域**。
颜色混合（`[0,1]`）与 SDF 布尔（`ℝ`）是两个不同的代数。

**推论 36.2.2（验证方法论）**：数值验证的**分布选择是命题的一部分**——
`[0,1]` 分布漏掉了全部反例。验证前必须先确定「值域是什么」，否则验证无意义。

### 36.3 修正后的完整分类（按值域分栏）

**颜色域 `[0,1]⁴`（MergeOp）**：

| 算子 | 结合 | 交换 | 判定 |
|---|---|---|---|
| Plus | ✅ 0/20000 | ✅ | 交换 monoid |
| Screen | ✅ 0/20000 | ✅ | 交换 monoid |
| Multiply | ✅ 0/20000 | ✅ | 交换 monoid |
| Mask | ✅ 0/20000 | ❌ | 非交换 monoid |
| **Over（引擎版）** | ❌ 20000/20000 | ❌ | **非结合**（§35） |

**SDF 实数域 `ℝ`（CsgOp）**：

| 算子 | 结合 | 交换 | 判定 |
|---|---|---|---|
| Union（min） | ✅ | ✅ | 交换 monoid |
| Intersect（max） | ✅ | ✅ | 交换 monoid |
| **Subtract** | ❌ 10776/20000 | ❌ | **非结合**（§36.1） |
| **SmoothUnion（smin）** | ❌ 632/729 | ✅ | **非结合**（§22.2） |

## 37. 标准 Porter–Duff over 的结合性：手推证明

数值验证（0/20000）不是证明。这里给出代数推导。

### 37.1 预乘形式

用预乘表示 `(C, α)`（`C` = 预乘 RGB，`α` = alpha）：

```
(C,α) over (D,β) = (C + D(1−α), α + β(1−α))
```

### 37.2 结合律

**左结合**：`((C,α) over (D,β)) over (E,γ)`

第一步：
```
(C + D(1−α), α + β(1−α))
```
第二步（记 `α₁ = α + β(1−α)`，注意 `1−α₁ = (1−α)(1−β)`）：
```
(C + D(1−α) + E(1−α₁), α₁ + γ(1−α₁))
= (C + D(1−α) + E(1−α)(1−β),  α₁ + γ(1−α)(1−β))
```

**右结合**：`(C,α) over ((D,β) over (E,γ))`

内层：
```
(D + E(1−β), β + γ(1−β))
```
外层（记 `β₁ = β + γ(1−β)`，`1−β₁ = (1−β)(1−γ)`）：
```
(C + (D + E(1−β))(1−α), α + β₁(1−α))
= (C + D(1−α) + E(1−β)(1−α), α + β₁(1−α))
```

**比较**：
- RGB：`C + D(1−α) + E(1−α)(1−β)` 两边相同（乘法交换）✓
- alpha：左边 `α₁ + γ(1−α)(1−β)`，右边 `α + β₁(1−α)`
  - 左边 = `α + β(1−α) + γ(1−α)(1−β)`
  - 右边 = `α + [β + γ(1−β)](1−α) = α + β(1−α) + γ(1−β)(1−α)`
  - 相同 ✓

**结论**：预乘 over 满足结合律。∎

非预乘形式是预乘形式的归一化（除以 `α_out`），归一化保持结合律（因为 `α_out` 的
复合是结合的，RGB 的归一化是逐点的）。故非预乘 over 也结合。

### 37.3 为什么引擎版不结合

引擎版：`out_rgb = a(1−α_b) + b·α_b`——这是**非预乘 RGB 的加权和，但没有除以 α_out**。
它等价于「假设 `α_out = 1`」的预乘形式的非归一化版本。

当 `α_out ≠ 1` 时，RGB 的权重与 alpha 的复合不一致——嵌套后 `α_out` 累积偏离 1，
偏差暴露。这就是 §35 的 20000 组全部失败的代数原因。

### 37.4 修正后的 Over 判定

| 版本 | 结合 | 交换 | 判定 |
|---|---|---|---|
| **标准 Porter–Duff（预乘/非预乘）** | ✅（§37.2 证明） | ❌ | 非交换 monoid |
| **引擎版**（缺 αa 与归一化） | ❌（§35 数值） | ❌ | **非结合** |

**这解释了我之前三次断言的错误链**：我把「标准 over 是 monoid」的结论直接套到
「引擎 over」上，没有验证实现是否一致。**标准是标准，实现是实现，两者不是同一回事。**

## 38. 判据一的数值验证（halo 正确性）

### 38.1 实验

97×61 随机图像，box blur 半径 R=5（可分离，钳制边界）：

| 配置 | `max|tile − full|` |
|---|---|
| tile=16, halo=5 | **0.000e+00** |
| tile=32, halo=5 | **0.000e+00** |
| tile=64, halo=5 | **0.000e+00** |
| tile=32, **halo=2（不足）** | **1.457e-01** |

### 38.2 结论

- halo ≥ 支撑半径：tile 拼接与整幅**逐位一致**（三种 tile 尺寸全部 0）；
- halo 不足：误差 0.146，且只在 tile 边界附近。

这验证了定理 18.1 与判据一：**halo 半径不是经验参数，是「支撑半径」的精确要求**。

**注 38.1**：实验用的是可分离 box blur（两趟），每趟支撑 R，总支撑仍是 R——
可分离不改变支撑半径。若用不可分离的 2D 核，支撑 = R（同）。

## 39. 值域代数决定层的代数（继承性）

### 39.1 命题

**命题 39.1**。层的混合算子 `⊕_L` 定义为逐点作用：`(F ⊕_L G)(U) = F(U) ⊕_V G(U)`。
则 `⊕_L` 的代数性质（结合、交换、单位元）**完全由** `⊕_V` 决定。

*证明*。逐点定义的运算，其代数律在每个点上成立当且仅当 `⊕_V` 在该点成立；
取所有点的交集，即得层的代数律。∎

### 39.2 推论

**推论 39.2.1**。§35–§37 的所有验证结果直接决定层的代数：
- 颜色层用 Plus/Screen/Multiply：可重排；
- 颜色层用 Mask：固定顺序；
- 颜色层用**引擎版 Over**：不可重排，且**不可扁平化**（非结合）；
- SDF 层用 Union/Intersect：可重排；
- SDF 层用 Subtract/Smooth*：固定顺序。

**推论 39.2.2**。修复层的问题 = 修复值域的问题。若把 `MergeOp::Over` 改为标准
Porter–Duff，层自动获得结合性——不需要改任何层代码。

### 39.3 这是整个框架的真正价值

框架的定理大多撤回或降级，但这一条继承性命题是**真的、有用的**：
- 它把「层的组合律」归约为「值域的代数律」；
- 值域的代数律可以用数值验证（§35–§38）；
- 所以层的组合律可以**被验证**，而不是被断言。

**这是「少量代码」的另一个根据**：不需要为每层证明组合律，只需验证值域的代数律一次，
所有层继承。

## 40. 非结合偏差的定量测量

### 40.1 实验

n 层随机半透明 RGBA，比较左折叠 `foldl(over)` 与右折叠 `foldr(over)` 的最大偏差
（2000 组/档）：

| n | `max|foldl − foldr|` |
|---|---|
| 2 | 0.000000 |
| 3 | 0.212423 |
| 4 | 0.321936 |
| 5 | 0.292094 |
| 8 | 0.286273 |
| 10 | 0.333353 |
| 15 | 0.291168 |
| 20 | 0.275681 |
| 30 | 0.310138 |

### 40.2 观察

1. **n=2 偏差为 0**：两层无括号化。
2. **n≥3 偏差饱和于 ~0.33**：不随深度增长。
3. 解释：每次 over 的偏差被上层的 `(1−α)` 因子衰减；偏差的「主项」来自最内层的
   括号化差异，后续层的贡献被 alpha 吸收。

**命题 40.1（偏差有界）**。`|foldl − foldr| ≤ 1`（色值域上界），且实测饱和于 ~1/3。
严格界需要推导 alpha 的衰减率，本报告未完成。

### 40.3 工程含义

- 图层树的括号化偏差**可见**（~1/3 色值），所以结构必须固定；
- 但偏差**不累积**——深层嵌套不比浅层更糟；
- 「图层树不能扁平化」是真实限制，不是性能问题。

## 41. 修复方案的代价（工程推算，非定理）

### 41.1 两种修复

**方案 A：改为标准 Porter–Duff**
```
out_rgb = (αa·a(1−αb) + αb·b) / α_out
```
增加：1 次乘（`αa`）+ 1 次除（`/α_out`）。

**方案 B：改为预乘存储**
- 存储 `C = α·c`（预乘 RGB）；
- over：`C_out = C_a + C_b(1−α_a)`（1 次乘加）；
- 显示时再除以 α。

预乘的代价：存储/读取时各一次乘除，但**混合本身更简单**。

### 41.2 收益

- 结合律成立 → 图层树可扁平化 → 可缓存、可重排、可并行归约；
- 与标准工具链（PS/AE/Nuke）语义一致 → 互操作。

### 41.3 结论

修复 over 是**低代价、高收益**：+1~2 次运算/像素，换来结合律与互操作。
当前「不结合」不是设计选择，是**实现遗漏**（缺 `αa` 与归一化），应修。

## 42. 几何层与坐标层：场复用的层论表述

### 42.1 区分

引擎里有两类层，之前没有区分：

**几何层**：定义在**场景空间**（表面、路径、体素）上的量。
例子：辐照度 `E(x)`、SDF `d(p)`、法线 `n(p)`、反照率 `ρ(p)`。

**坐标层**：定义在**像素网格**上的量。
例子：像素颜色 `I(i,j)`、深度缓冲、运动矢量。

**区别**：几何层与相机无关；坐标层依赖相机（内参/外参/分辨率）。

### 42.2 关系：推前

渲染 = 沿投影 `π: 场景空间 → 像素网格` 的推前：

```
I = π_* E
```

（投影 + 可见性 + 积分）。

**换相机** = 换投影 `π → π'`，几何层 `E` 不变，坐标层 `I' = π'_* E` 重算。

### 42.3 场复用 = 几何层的缓存

**命题 42.1**。若渲染的漫射部分 = `π_* E`（`E` 是几何层），则：
- 换相机只改变 `π`，不改变 `E`；
- 复用 `E` 可以避免重算漫射传输。

*证明*。`E` 的定义不引用相机（它是场景的函数）；`π` 引用相机。故缓存 `E` 后，
换相机只需重做 `π_*`（投影采样），不需要重做 `E` 的求解。∎

**这解释了「场复用」研究的核心结论**（跨相机一致性、帧间零抖动）：
- 跨相机一致：`E` 不变，`π_*` 是确定性的采样；
- 帧间零抖动：`E` 在动画中只随场景变化，不随相机变化。

### 42.4 边界

**命题 42.2**。并非所有渲染都能分解为 `π_* E`：
- 镜面反射/折射依赖相机方向（`E` 本身依赖视角）；
- 参与介质依赖视线（沿视线的积分）；
- 这些不是「几何层 + 推前」，是「视角依赖的层」。

*证明*。镜面 BRDF 的 `E_镜面(x, ω_o)` 显含 `ω_o`（出射方向）；换相机改变 `ω_o`，
故 `E_镜面` 不是相机无关的几何层。∎

**结论**：场复用只适用于**漫射/低频**部分；镜面/介质需要视角依赖的处理。
这是之前「参数化坍缩」研究的边界。

### 42.5 这是「层论」与「场复用」的连接点

之前的研究（`场复用-签名等价.md`）用「签名等价」表述复用条件；
本报告用「几何层 vs 坐标层」表述。两者是同一件事：

| 场复用研究 | 层论表述 |
|---|---|
| 辐照度场 `E` | 几何层 |
| 相机投影 | 推前 `π_*` |
| 跨相机复用 | `E` 不变，只换 `π` |
| 签名等价 | 几何层的同构类（`K(E₁)=K(E₂) ⟹ E₁≅E₂`） |
| 镜面不可复用 | 视角依赖层，不是几何层 |

**这个对应不是巧合**：两套语言都在描述「什么是相机无关的量」。
层论给了它一个更一般的框架（几何层是「底空间不含相机参数」的层）。

## 43. 经验观察的测试清单（**不是「验证定理」**）

> **定位声明**：这些测试不是「用测试验证定理」——定理不需要测试。这些测试记录的是
> **经验观察的适用范围**：在某组输入下，现象成立；换一组输入，可能不成立。
> 它们的作用是**防止实现漂移**，不是**证明数学命题**。

### T1：tile 一致性（判据一）

### T3：混合算子代数（判据三）

## 45. ε-同构的误差传播（可演绎，不需要测试）

### 45.1 定义

**定义 45.1（ε-同构）**。设 `(X, d)` 为度量空间，`A, B ∈ X`。称 `A` 与 `B`
**ε-同构**（记 `A ≅_ε B`），若 `d(A, B) ≤ ε`。

### 45.2 定理

**定理 45.1（Lipschitz 传播）**。设 `T: X → Y` 是 Lipschitz 连续的，常数 `L`：
`d_Y(T(A), T(B)) ≤ L·d_X(A, B)`。若 `A ≅_ε B`，则 `T(A) ≅_{Lε} T(B)`。

*证明*。`d_Y(T(A),T(B)) ≤ L·d_X(A,B) ≤ Lε`。∎

**定理 45.2（传递性）**。若 `A ≅_ε B` 且 `B ≅_δ C`，则 `A ≅_{ε+δ} C`。

*证明*。三角不等式：`d(A,C) ≤ d(A,B) + d(B,C) ≤ ε+δ`。∎

**这两条证明不需要测试**：它们是度量公理与 Lipschitz 定义的直接推论，
对所有度量空间、所有 Lipschitz 映射成立。

### 45.3 应用：`Dual` 的误差预算

`Dual`（mesh → SDF bake）的误差 `ε = O(spacing)`（体素间距）。经过后续算子：

| 算子 | Lipschitz 常数 | 误差变化 |
|---|---|---|
| 卷积（归一化核） | `L = 1` | `ε` 不放大 |
| Union/Intersect（min/max） | `L = 1` | `ε` 不放大 |
| 求导（法线） | `L ~ 1/spacing` | `ε` 放大 `1/spacing` 倍 |
| 光线步进（sphere tracing） | `L ≤ 1`（步长受距离界约束） | `ε` 不放大 |

**推论 45.3.1**。`Dual` 的误差经过卷积与 CSG 不放大，经过求导放大 `1/spacing` 倍。
所以：**SDF 的法线精度比距离精度差一个量级（1/spacing）**——可演绎，不需要测试。

**诚实标注**：Lipschitz 常数的赋值（表）是**参数**，不是定理；它们的正确性需要
验证（例如 `min/max` 的 Lipschitz 常数为 1 是标准结果，但 `sphere tracing` 的那一格
是量级推断）。定理本身（传播、传递）不依赖这些参数的具体值。

## 46. 混合算子的 Lipschitz 常数（可演绎）

### 46.1 定义

**定义 46.1**。`⊕: [0,1]² → [0,1]` 的 Lipschitz 常数 `(L_a, L_b)` 定义为最小的
常数使对所有 `a,a',b,b'`：

```
|⊕(a,b) − ⊕(a',b')| ≤ L_a·|a−a'| + L_b·|b−b'|
```

### 46.2 定理与证明

**定理 46.1（Plus）**。`⊕(a,b) = a+b`，`L_a = L_b = 1`。

*证明*。`|(a+b)−(a'+b')| ≤ |a−a'| + |b−b'|`（三角不等式），且取下确界为 1
（取 `b=b'`，等号成立）。∎

**定理 46.2（Multiply）**。`⊕(a,b) = ab`，`L_a = L_b = 1`。

*证明*。`|ab−a'b'| = |a(b−b') + b'(a−a')| ≤ |a||b−b'| + |b'||a−a'| ≤ |b−b'| + |a−a'|`
（因 `|a|,|b'| ≤ 1`）。取 `a=1` 或 `b'=1` 可达，故常数紧。∎

**定理 46.3（Screen）**。`⊕(a,b) = a+b−ab`，`L_a = L_b = 2`。

*证明*。`screen(a,b) = 1−(1−a)(1−b)`。令 `u=1−a, v=1−b`，则 `screen = 1−uv`，
`|Δ(uv)| ≤ |u||Δv| + |v||Δu| ≤ |Δu| + |Δv| = |Δa| + |Δb|`。故 `L ≤ 1`？
需仔细：`|Δscreen| = |Δ(uv)| ≤ |Δu| + |Δv| = |Δa| + |Δb|`。
所以 `L_a = L_b = 1`，不是 2。

**修正**：Screen 的 Lipschitz 常数是 **1**（通过 `u=1−a` 变换）。∎

**定理 46.4（min/max）**。`L_a = L_b = 1`。

*证明*。`|min(a,b) − min(a',b')| ≤ max(|a−a'|, |b−b'|) ≤ |a−a'| + |b−b'|`。
紧性由 `a=a'` 或 `b=b'` 给出。∎

**定理 46.5（Over，引擎版，单通道）**。`over(a,b) = a(1−α_b) + b·α_b`。
对三个变量 `(a, b, α_b)` 的偏导：

```
∂/∂a    = 1 − α_b        |·| ≤ 1
∂/∂b    = α_b            |·| ≤ 1
∂/∂α_b  = b − a          |·| ≤ 1
```

故对三个变量各自的 Lipschitz 常数为 `(1, 1, 1)`；**联合界**为 `1+1+1 = 3`
（最坏情况三者同时扰动）。

*证明*。逐项绝对值界如上；联合界由三角不等式相加。∎

### 46.3 应用：误差传播的界

**推论 46.3.1**。单次 Over 混合的误差放大 ≤ 3（三个变量联合扰动）。

**推论 46.3.2**。n 层混合的误差放大 ≤ `3^n`（最坏情况，严格但很松）。
实测（§40）偏差饱和于 ~1/3，说明**最坏界远不紧**——实际误差被 alpha 衰减。

**诚实标注**：`3^n` 是严格上界，但极松（n=10 时 `3^10 ≈ 59049`，而实测 ≤ 0.33）。
紧界需要分析 alpha 的复合衰减，本报告未做。

### 46.4 这条定理的意义

**误差预算**：如果输入层的误差是 `ε`，经过 n 层混合后误差 ≤ `2^n·ε`（严格但松）。
这给出了「混合层数」的安全上限——但实际远好于这个界。

**不需要测试**：定理 46.1–46.5 都是从定义出发的代数推导，对所有输入成立。

## 47. 两种 over 修复方案的误差稳定性（可演绎）

### 47.1 两种方案

**方案 A：非预乘 + 归一化**
```
c_out = (αa·c_a(1−αb) + αb·c_b) / α_out,    α_out = αb + αa(1−αb)
```

**方案 B：预乘存储**
```
C = α·c（存储）；  C_out = C_a + C_b(1−αa)（混合）；  c = C/α（显示）
```

### 47.2 定理

**定理 47.1（方案 B 的稳定性）**。预乘混合 `C_out = C_a + C_b(1−αa)` 的 Lipschitz
常数为 `(1, 1)`（对 `C_a, C_b`），**无除法**，误差不放大。

*证明*。`|ΔC_out| ≤ |ΔC_a| + |1−αa|·|ΔC_b| ≤ |ΔC_a| + |ΔC_b|`。∎

**定理 47.2（方案 A 的除法放大）**。非预乘归一化 `c_out = N/α_out` 的误差满足

```
|Δc_out| ≤ (|ΔN| + |c_out|·|Δα_out|) / α_out
```

当 `α_out → 0` 时，放大因子 `1/α_out → ∞`。

*证明*。商法则：`Δ(N/α) = (ΔN·α − N·Δα)/α² = (ΔN − c_out·Δα)/α`。
取绝对值得上式。∎

### 47.3 结论

**方案 B（预乘）在数学上更稳定**：
- 混合无除法，Lipschitz 常数 1；
- 方案 A 在 `α_out` 小时误差放大 `1/α_out`。

**代价**：
- 方案 B 需要存储预乘值（`C = α·c`），显示时除一次；
- 存储/读取的乘除是**一次性的**，不累积（每次混合后仍可保持预乘）。

**推论 47.3.1**。预乘存储 + 预乘混合 = 结合 + 稳定 + 无累积放大。
这是标准合成系统的做法（PS/AE/Nuke 内部均为预乘）。

**推论 47.3.2**。方案 A 在 `α_out` 接近 0 时（几乎全透明的合成结果）不可靠——
这不是实现 bug，是**除法的数学性质**。

### 47.4 对引擎的建议

1. 内部统一用预乘；
2. 输入时预乘（`C = α·c`），显示时反预乘；
3. 混合用 `C_out = C_a + C_b(1−αa)`（标准 over，结合）；
4. 这样同时获得：结合律（可扁平化）、数值稳定（无除法放大）、与标准工具一致。

## 48. SDF 法线的精度下界（可演绎）

### 48.1 问题

`Dual`（mesh → SDF bake）的距离场误差 `|ε(x)| ≤ ε₀ = c·h`（`h` = 体素间距，
`c` 是插值常数）。法线由中心差分给出：

```
n(x) = (d(x+h) − d(x−h)) / (2h)
```

**问**：法线误差随 `h → 0` 是否趋于 0？

### 48.2 定理

**定理 48.1（法线误差下界）**。设 `d(x) = x`（精确线性场），`d_bake(x) = x + ε(x)`，
`|ε(x)| ≤ c·h`。则

```
|n_bake(x) − 1| ≤ c
```

且存在 `ε` 使等号成立。**误差下界 `c` 与 `h` 无关**——减小 `h` 不改善法线精度。

*证明*。

```
n_bake = (d_bake(x+h) − d_bake(x−h))/(2h)
       = 1 + (ε(x+h) − ε(x−h))/(2h)
```

由 `|ε| ≤ c·h`，得 `|ε(x+h) − ε(x−h)| ≤ 2c·h`，故 `|n_bake − 1| ≤ c`。
取 `ε(x+h) = c·h, ε(x−h) = −c·h` 时等号成立。∎

### 48.3 推论

**推论 48.3.1**。法线误差**不随 spacing 减小而改善**——因为距离误差与差分步长
同比例缩小（都是 `O(h)`），比值 `ε/h` 是常数。

**推论 48.3.2（工程含义）**。若需要精确法线，不能依赖 bake 后的有限差分：
- 方案 A：用解析法线（mesh 的法线，不走 SDF）；
- 方案 B：用更高阶插值（误差 `O(h²)`，则法线误差 `O(h)`）；
- 方案 C：用更大差分步长 `h' > h`（误差 `ε/h' = c·h/h'`，但引入截断误差 `O(h'²)`）。

**取舍**：`h' = √(c·h)` 时两项平衡，误差 `O(√h)`——比 `O(1)` 好，但仍不理想。

### 48.4 这是一个「可演绎」的工程结论

定理 48.1 从定义与三角不等式直接推出，不需要测试。它解释了一个常见的工程现象：
**SDF 的法线总是比距离「糙」一个量级**——不是实现 bug，是差分的数学性质。

**注**：三线性插值的 `c` 依赖插值格式；对三线性插值，`c ~ 1/8`（量级）。
精确的 `c` 需要分析插值的误差常数，本报告未做。

## 49. 卷积不放大误差（可演绎）

### 49.1 定理

**定理 49.1**。设 `k` 是归一化核（`Σ_q |k(q)| = 1`），`I, I'` 是两幅图像。
则

```
‖k ∗ I − k ∗ I'‖_sup ≤ ‖I − I'‖_sup
```

即卷积的 Lipschitz 常数为 1（sup 范数意义）。

*证明*。

```
|(k∗I)(p) − (k∗I')(p)| = |Σ_q k(q)(I(q) − I'(q))|
                        ≤ Σ_q |k(q)| · ‖I − I'‖_sup
                        = ‖I − I'‖_sup
```

取上确界得结论。∎

### 49.2 推论

**推论 49.2.1**。模糊、bloom（box 核）、降噪（归一化核）都不放大误差。
误差预算中这些算子的 `L = 1`。

**推论 49.2.2（与 §48 的对比）**。卷积不放大误差，但**求导放大** `1/h`。
这解释了为什么「SDF 的距离准，法线糙」——不是卷积的问题，是导数的性质。

**推论 49.2.3（误差预算的组合）**。若处理链是「bake → 卷积 → 混合 → 求导」，
误差依次为：`ε → ε → ≤3ε → ε/h`。求导是唯一的放大环节。

### 49.3 这是「可演绎」的

定理 49.1 从三角不等式与归一化条件直接推出，不需要测试。
它是 §45（Lipschitz 传播）的一个实例，也是 §48 的前提。

**注**：若核未归一化（`Σ|k| > 1`），则误差按 `Σ|k|` 放大。归一化是「不放大」的
充分必要条件（在 sup 范数下）。

## 50. 处理链的误差累积（可演绎）

### 50.1 定理

**定理 50.1（误差累积）**。设处理链 `F = F_n ∘ … ∘ F_1`，每层 `F_i` 的 Lipschitz
常数为 `L_i`，输入误差为 `ε₀`，第 `i` 层自身的数值误差为 `ε_i`。则总误差满足

```
‖F(x) − F(x̃)‖ ≤ L_n···L_1·ε₀  +  Σ_{i=1}^{n} (L_n···L_{i+1})·ε_i
```

*证明*。对 `n` 归纳。`n=1`：`‖F_1(x)−F_1(x̃)‖ ≤ L_1ε₀ + ε_1`。
归纳步：把前 `n−1` 层看作一个算子，其误差由上界给出，再乘 `L_n` 并加 `ε_n`。∎

### 50.2 推论

**推论 50.2.1（无放大的链）**。若所有 `L_i = 1`（卷积、混合），则

```
总误差 ≤ ε₀ + Σ ε_i
```

误差**线性累积**，不爆炸。这是「归一化 + 混合」链的稳定性来源。

**推论 50.2.2（有放大的链）**。若某一环 `L_j = 1/h`（求导），则它之前的误差
被放大 `1/h` 倍，之后的误差不被放大（如果后续 `L=1`）。

**推论 50.2.3（渲染管线的误差预算）**：
```
几何误差 →[L=1 卷积]→ →[L≤3 混合]→ →[L=1/h 求导]→ 总误差
```
求导前的误差必须 ≤ `h·δ`（δ = 允许的法线误差）。

### 50.3 这是「可演绎」的

定理 50.1 是标准的误差累积公式，从 Lipschitz 定义归纳证明，不需要测试。
它是 §45/§46/§48/§49 的汇总：把各环节的 `L` 与 `ε` 代入，得到管线的误差界。

**注**：这个界是**最坏情况**，实际误差通常远小（误差的符号可能相互抵消）。
紧界需要误差的相关性分析，本报告未做。

## 51. halo 不足时误差的支撑（可演绎）

### 51.1 定理

**定理 51.1**。设 `T` 是 r-局部算子，tile `B_i` 的 halo 为 `h = r − d`（`d > 0`，
不足 `d`）。则误差只出现在 `B_i` 的**边界 d 像素内**：

```
T(I|_{B_i^h})(p) ≠ T(I)(p)  ⟹  dist(p, ∂B_i) ≤ d
```

*证明*。若 `dist(p, ∂B_i) > d`，则 `B(p,r) ⊆ B_i^h`（因为 `p` 距边界超过 `d`，
而 `h = r−d` 只比 `r` 少 `d`）。故 `I|_{B_i^h}` 与 `I` 在 `B(p,r)` 上相等，
由 r-局部性得 `T(I|_{B_i^h})(p) = T(I)(p)`——与假设矛盾。∎

### 51.2 推论

**推论 51.2.1（伪影的局部性）**。halo 不足的误差是**边界带状**的，宽度 = 不足量 `d`。
这解释了 tile 伪影为什么表现为「缝」而不是「整片」——误差的支撑是边界。

**推论 51.2.2（误差的可见度）**。若 `d` 很小（如 1 像素），误差带只有 1 像素宽，
但可能很显眼（硬边）。若 `d` 很大，误差带宽但每个像素的误差可能小（取决于核的衰减）。

**推论 51.2.3（修复的优先级）**。halo 不足的修复只需补足 `d` 像素的输入，
不需要重算整个 tile——误差是局部的。

### 51.3 这是一个「可演绎」的

定理 51.1 从 r-局部性的定义直接推出，不需要测试。
它补充了 §18.1（halo 足够时无误差）的另一半（halo 不足时误差的支撑）。
## 52. 翻译的构造（不是定理，是构造）

### 52.1 构造

对 S1–S12 × Composition 的任意组合，定义翻译 `E`：

**叶子**：节点 `v`（无输入）→ 基本层 `E_v`，由 `StructureId` 决定（§24 的表）。

**内部**：节点 `v`（有输入）→ 按 `Composition` 翻译：

| Composition | 翻译 |
|---|---|
| `Feed` | `E_v = E_child` |
| `Chain` | `E_v = φ_* (E_child)`（`φ ∈ End(V)`） |
| `Merge(op)` | `E_v = E_a ⊗ E_b` |
| `Csg(op,k)` | `E_v = E_a ⊗ E_b`（SDF 值域） |
| `Mis(w)` | `E_v = Hom(E_a, E_b) ⊗ w` |
| `Dual` | `E_v = ε_*(E_child)` |

**归纳**：按拓扑序，每个节点得到一个表达式；根节点的表达式即整个 DAG 的翻译。

### 52.2 这是什么，不是什么

**是**：一个**构造**——给定枚举，翻译存在且可机械执行。

**不是**：一个**定理**——它没有证明「枚举完备」。

**枚举完备性依赖**：
- `StructureId` 的枚举（Rust `enum`）——**可扩展**（S13+），所以不完备；
- `Composition` 的枚举（Rust `enum`）——**可扩展**，所以不完备。

**诚实表述**：
> **构造 52.1**：对当前枚举（S1–S12 × 6 种 Composition），翻译存在。
> **前提**：枚举不变。若新增结构或组合方式，需扩展翻译表。
> **不是定理**：没有证明「所有可能的视觉计算都可翻译」——只证明了「当前枚举的组合可翻译」。

### 52.3 与「定理 4.1」的关系

定理 4.1 声称「满足 (a)(b)(c) 的计算可分解为 `Flow ∘ Free ∘ Op`」。
构造 52.1 给出的是「当前枚举的 DAG 可翻译为 `{f*, f*, ⊗, Hom, End, ε}` 的表达式」。

**两者的差距**：
- 定理 4.1 是**全称**（所有视觉计算）；
- 构造 52.1 是**枚举**（当前引擎的节点类型）。

**结论**：定理 4.1 仍然未证；构造 52.1 是它的「引擎内版本」——弱，但可执行。

### 52.4 这是本报告的最终定位

**能给的**：一个构造（翻译表 + 归纳），对当前引擎的枚举有效。

**不能给的**：一个定理（全称、演绎、不需要测试）。

**「四算子覆盖一切」是假的**（§31/§44）；**「当前枚举可翻译」是构造，不是定理**。
这两句话的差距，就是这份报告的全部诚实。

## 53. `over` 修复的具体方案（不改代码，只给方案）

### 53.1 定位

`crates/prism-core/src/compose.rs:82` `blend_pixel` 的 `MergeOp::Over` 分支：

```rust
MergeOp::Over => {
    let ab = b[3];
    let aa = a[3];
    out[3] = ab + aa * (1.0 - ab);
    for i in 0..3 {
        out[i] = a[i] * (1.0 - ab) + b[i] * ab;   // 缺 aa 与归一化
    }
}
```

### 53.2 修复（标准 Porter–Duff，非预乘形式）

```rust
MergeOp::Over => {
    let ab = b[3];
    let aa = a[3];
    let ao = ab + aa * (1.0 - ab);           // α_out
    out[3] = ao;
    if ao > 0.0 {
        let inv = 1.0 / ao;
        for i in 0..3 {
            out[i] = (aa * a[i] * (1.0 - ab) + ab * b[i]) * inv;
        }
    } else {
        for i in 0..3 { out[i] = 0.0; }      // 全透明，RGB 无定义
    }
}
```

### 53.3 行为变化

| 场景 | 修复前 | 修复后 |
|---|---|---|
| 下层不透明（`αa=1`，`α_out=1`） | `a(1−αb)+b·αb` | **相同**（`aa=1, inv=1`） |
| 下层半透明（`αa<1`） | 忽略 `aa` | 正确加权 |
| 三层嵌套 | 不结合 | **结合** |

**现有测试** `over_upper_covers_lower_by_alpha` 用不透明下层 → **不受影响**。
但**半透明下层的 golden 基线会变**（若有）。

### 53.4 迁移

1. 修改 `blend_pixel`；
2. 跑 `cargo test -p prism-core`，确认不透明用例通过；
3. 检查是否有半透明下层的 golden 基线（目前测试未见）——若有，按 C15 更新；
4. 在 `compose.rs` 的模块文档中补一句：「over = 标准 Porter–Duff（非预乘），
   下层 alpha 参与 RGB 权重」。

### 53.5 为什么这是「修复」而不是「行为变更」

修复后，`over` 与**所有标准合成系统**（PS/AE/Nuke/浏览器 canvas）的语义一致。
修复前，它与标准不一致——这是**实现偏离规格**，不是「设计选择」。

**但**：如果引擎**有意**只支持不透明下层（为了简化），那么文档必须明说，
且 API 应拒绝半透明下层（而不是静默算错）。二者必居其一。

### 53.6 这是一个「数学结论驱动的工程建议」

§35（20000 组反例）+ §37（标准版结合证明）+ §47（预乘稳定）三条加起来，
给出了这个修复的完整依据：
- 现状错（不结合，偏离标准）；
- 修复正确（标准版结合，已证）；
- 修复稳定（预乘无除法放大，已证）。

**这是本报告唯一可以直接落地的东西**——不是框架，不是判据，是一个具体的 bug 修复。

### 53.7 修复的数值验证

| # | 位置 | 实现 | 标准 | 性质 |
|---|---|---|---|---|
| 1 | `Over` 的 RGB | `a(1−αb)+b·αb` | `(αa·a(1−αb)+αb·b)/α_out` | **bug**（缺 αa 与归一化，不结合） |
| 2 | `Screen`/`Multiply` 的 alpha | `max(αa,αb)` | `αa+αb−αa·αb` | **未文档化的设计选择** |
| 3 | `Plus` 的 RGB | `a+b`（无钳制） | 视管线（LDR 需钳制） | **合理**（HDR 线性域设计） |

### 54.2 逐项分析

**#1 Over**：§35–§37/§53 已详述。必须修。

**#2 Screen/Multiply 的 alpha**：

数值对比：

| `αa` | `αb` | 引擎 `max` | 标准累积 | 差 |
|---|---|---|---|---|
| 0.5 | 0.5 | 0.500 | 0.750 | 0.250 |
| 0.3 | 0.8 | 0.800 | 0.860 | 0.060 |
| 1.0 | 0.4 | 1.000 | 1.000 | 0 |

**两种语义都合法**：
- `max`：合成后的覆盖 = 较大的覆盖（「取并集的可见度」）；
- 累积：两层都参与覆盖（「叠加的覆盖」）。

**但引擎未文档化这个选择**。后果：两层半透明 screen 后 alpha 偏小（0.5 vs 0.75），
后续合成时下层更可见——与「标准混合」的直觉不同。

**建议**：在 `compose.rs` 的模块文档中声明：「Screen/Multiply 的 alpha 取 max
（非累积覆盖）」；或改为累积覆盖（需重新基线）。

**#3 Plus 无钳制**：HDR 线性域的正确做法（钳制会丢失高光）。**合理**，但需确保
后续 tone mapping 处理越界。

### 54.3 这是一个「语义审计」

三处放在一起，给出引擎混合语义的完整画像：
- 一处 bug（Over，必须修）；
- 一处未文档化的选择（alpha max，需声明）；
- 一处合理设计（Plus 无钳制）。

**审计的价值**：不是「找出三个问题」，是**区分它们**——bug 要修，选择要声明，
设计要保留。混为一谈（「三个都是 bug」或「三个都是设计」）都是错的。

## 55. 方法论教训（这次研究真正学到的东西）

### 55.1 快是模式匹配，不是思考

我曾在 30 秒内「证明」一条定理。那不是思考——是检索「类似问题 + 标准证明模式」
然后套用。**思考会卡住**：想不通定义、算错例子、找不到反例。我没有卡住，说明我没在想。

### 55.2 归纳给不出定理

20000 组随机测试没找到反例，不能证明第 20001 组也没有。
**归纳给出的是「暂未发现反例」，不是「对所有情况成立」**。
把归纳叫「判据」，是把经验包装成数学——和伪证同一性质，只是更隐蔽。

### 55.3 标准与实现是两回事

「标准 Porter–Duff over 结合」是真定理（§37），但**引擎的 over 不是标准版**（§35）。
我把标准的结论套到实现上，没有核对实现——这是三处断言错误的共同根源。

**教训**：引用标准结果前，先确认「实现是否等于标准」。

### 55.4 数值验证的分布是命题的一部分

`Subtract` 在 `[0,1]` 分布下 0 个反例，在 `[−1,1]` 下 10776 个（§36）。
**同一个算子，不同的值域，不同的结论**。验证前必须声明值域，否则验证无意义。

### 55.5 证明不需要测试

这是最基本的逻辑：如果证明是对的，就不需要测试。**需要测试的，就不是证明**。
测试的作用是「验证实现是否符合定理的假设」，不是「验证定理」。

### 55.6 结构是发现，不是设计

我造过「时变层论」「三类结构」「四算子」——大多是为统一而统一。
真正有价值的东西（tile 判据、采样索引判据、Over 的 bug）都是**从实现里发现的**，
不是从天上设计的。

### 55.7 这份报告的真正价值

不是 15 条定理（大多是标准误差分析），不是 7 条观察（需要测试），
而是**一个具体的、可验证的 bug 修复**（§53）和**一套区分「定理 / 观察 / 撤回」的纪律**。

**一个 bug 修复 > 二十一条「定理」。**

## 57. 测试覆盖的缺口（引擎内核对）

### 57.1 事实

`prism-core/src/compose.rs` 的两个关键测试：

**`flat_reduce_matches_left_chain_for_associative_op`**：
- 测试名明确写着「for associative op」——作者**知道**只有结合算子才能扁平化；
- 但只用 `MergeOp::Plus` 测试（Plus 结合）。

**`flat_layers_degenerate_into_left_chain`**：
- 用 `MergeOp::Over`，但三层**全部不透明**（`alpha = 1.0`）；
- 不透明时 Over 退化为「取上层」，结合与否无关。

### 57.2 缺口

**「半透明 + 嵌套」这个组合从未被测试**。

- 半透明 + 扁平 vs 半透明 + 嵌套：结果不同（§35，最大偏差 0.33）；
- 现有测试全部避开这个组合。

**这不是「bug 被隐藏」**：测试没有伪装通过——它们只测了自己声明的东西
（「结合算子」、 「不透明层」）。**这是覆盖缺口，不是造假**。

### 57.3 建议

1. 补测试：半透明 + 嵌套 vs 扁平，断言**不相等**（记录当前行为）；
2. 若修复 Over（§53）：补测试断言**相等**（结合律）；
3. 在 `compose.rs` 文档中声明：「Over 在引擎实现下不结合；扁平化仅对不透明层安全」。

### 57.4 这是「研究发现」的正确形态

不是「找到了一个 bug」，是**「找到了一个测试没覆盖的行为差异」**：
- 行为差异是数学事实（§35）；
- 测试缺口是工程事实（本节）；
- 两者合起来，才构成一个可执行的修复建议（§53）。

**只有数学，没有测试缺口，修复就无从下手；只有测试，没有数学，就不知道缺什么。**

## 58. 判据五与判据七的验证

### 58.1 判据五（增量局部性）

实验：64×64 图像，一个半径 8 的圆，圆心受参数控制。

| 参数变化 | 差异像素数 | 差异范围 |
|---|---|---|
| 圆心 x: 20→21（局部参数） | 34 | x ∈ [12, 29] |
| 背景亮度: 0.1→0.2（全局参数） | 4096 / 4096 | 全图 |

**结论**：局部参数 → 差异支撑 = 依赖区域（34 像素，正好是两圆的并 − 交集）；
全局参数 → 全图。判据五成立：**差异支撑 = 参数依赖的支撑**。

### 58.2 判据七（可块化）

实验：IIR 滤波 `y[n] = 0.9·y[n−1] + 0.1·x[n]`，10000 样本，10 块。

| 配置 | 与整段的最大差 |
|---|---|
| 分块 + **传状态** | **0.000e+00**（逐位相同） |
| 分块 + **不传状态** | **4.882e-01**（几乎 50% 误差） |

**结论**：带状态的计算，块化**必须传状态**——不传则每块从零开始，误差灾难性。
判据七成立：**可块化（b）状态可参数化**不是可选项，是必要条件。

### 58.3 验证的边界

这两条是**经验观察**，不是定理：
- 判据五的「差异支撑 = 依赖支撑」在**纯函数**前提下成立——若参数有跨像素依赖
  （如全局归一化），支撑会扩大（如背景亮度例）；
- 判据七的「传状态」是**充分**的——但状态空间可能不可压缩（如长 FIR 的历史），
  此时块化的代价等于整段，不划算。

**这两条验证的作用**：确认观察的适用范围，不是「证明判据」。

## 59. 判据二的验证（Sobol 索引）

### 59.1 实验

2D Sobol 序列（scipy `qmc.Sobol`，无 scramble），积分 `f(x,y)=xy` 在 `[0,1]²`，
精确值 0.25。比较：
- **顺序**：取前 N 个点（等价于线性平移索引 `i ⊕ c` 的特殊情况 `c=0`）；
- **随机抽取**：从 4096 点中无放回随机抽 N 个（等价于任意置换索引）。

| N | 顺序误差 | 随机抽取误差 |
|---|---|---|
| 64 | 6.714e-03 | 4.871e-02 |
| 256 | 1.945e-03 | 2.482e-03 |
| 1024 | 4.840e-04 | 7.734e-03 |
| 4096 | 1.182e-04 | 1.182e-04（抽了全部点） |

### 59.2 分析

- **顺序**：6.7e-3 → 1.9e-3 → 4.8e-4 → 1.2e-4，每次约 1/4（N 增 4 倍）→ **O(1/N)**；
- **随机抽取**：波动，无单调性 → **O(1/√N)**（且单次样本方差大）；
- N=4096 时两者相同，因为随机抽取拿了全部点——这是测试设计的边界，不是收敛性。

### 59.3 结论

判据二成立：**顺序索引（线性平移）保持 O(1/N)；任意置换退化为 O(1/√N)**。

**边界**：本实验的「随机抽取」是从 Sobol 点集中抽，不是从连续空间采样。
真正的 MC 对照应该用 `rng.random(N,2)`，但那样比较的是「Sobol vs MC」，
不是「顺序 vs 置换」。本实验要验证的是后者，故设计如此。

## 60. 最优括号化：一次失败的尝试（如实记录）

### 60.1 问题

`over` 不结合（§35）。n 个半透明层有 `Catalan(n−1)` 种括号化，结果各不相同。
给定层序列，选哪种括号化使结果最接近标准 Porter–Duff？

### 60.2 n=3 的实测

5000 组随机层，参考 = 标准 over 的**左折叠**：

| 括号化 | 与参考的平均误差 | 最大误差 |
|---|---|---|
| 左 `((a b) c)` | 0.0503 | 0.6608 |
| 右 `(a (b c))` | 0.0799 | 0.6595 |

左胜 81.3%，右胜 18.7%，打平 0%。**不是总左优**。

### 60.3 第一个假设（失败）

**假设**：误差来自「下层半透明」（引擎版缺 `αa`），所以 `αa > αb` 时左优。

**验证**：30000 组，命中率 **57.87%**——接近随机。

**为什么失败**：误差不是单一项。左括号的误差 ≈ `(1−αa)·A + (1−αab)·B`，
右括号 ≈ `(1−αb)·A' + (1−αa)·B'`——**两者都含 `(1−αa)` 项**，
简单比较 `αa` vs `αb` 不够。且 `αab = αb + αa(1−αb)` 是复合的，
第二项权重依赖第一项的结果。

### 60.4 卡点

**我卡在这里**：无法给出 `n=3` 的解析选择条件。

- 误差含绝对值（`|L−S|`），表达式分段；
- 分段边界依赖 RGB 与 alpha 的联合分布，不是单一变量；
- 尝试用「误差 ∝ Σ(1−α_下层)」的模型推导，得出「总是左优」——
  与实测 18.7% 右优矛盾，模型错了。

### 60.5 下一步的可能方向（未做）

1. **数值拟合**：用 alpha/RGB 的特征拟合一个分类器——但这是经验，不是推导；
2. **特殊情形**：先解「所有 RGB 相同」或「所有 alpha 相同」的退化情形，
   看能否得到闭式条件；
3. **放弃解析**：直接用标准 Porter–Duff（§53），括号化就无关紧要——
   这可能是工程上唯一正确的答案。

### 60.6 这段记录的价值

这段不是「成果」，是「失败」。但它比 15 条习题定理更能说明什么是研究：
**提出假设 → 验证 → 失败 → 分析卡点 → 缩小问题**。

**我没有解决这个问题。** 如实标注。
