## 1. 单文件形态（A5 / D-27 / B3）：资产内容哈希锁定

### 做了什么

- `crates/prism-dsl/src/film.rs`（新增模块）：
  - `AssetKind{Exr,Font,Audio}` / `AssetSource{External,Inline,HashOnly}` / `AssetDecl` /
    `AssetPlan`；声明语法 `asset "<name>" kind exr|font|audio hash "<16hex>" [external "<相对路径>" | inline "<hexbytes>"]`。
  - **内容哈希锁定**：`AssetPlan::canonical_bytes()` 只混入 `(name, kind, content_hash, inline 字节)`，
    **永不混入路径字符串**；内容哈希由 `prism_core::eval::hash_mix_bytes`（既有 splitmix64 基元，
    零 libm / 零线程 / 零系统时间）派生；`mix_artifact_hash` 扩链进 F-8 产物哈希。
  - **外部引用为主、内嵌可选**：`External`（主形态，语言层零 IO）、`Inline`（字节写进单文件，
    自包含、空环境可出片）、`HashOnly`（纯内容哈希声明）。
  - **语言层零文件 IO**：`scan_film` 只读声明；真正的外部资产字节由
    `AssetResolver` trait 注入（`NullResolver` / `DirResolver`），在 `verify_external_assets`
    里校验「存在 + 内容哈希一致」。因此「当前工作目录下有没有这个文件」只影响
    **校验通过与否**（一致 / 结构化报错），产物字节恒由声明哈希决定 ⇒
    **资产路径不是隐式环境状态**（D-27 确定性破口的治本解）。
  - **行式扫描 + 遮罩**：`scan_film` 把顶层 `asset`/`channel`/`asset_ref` 行清空为空行
    （与 W3 `scan_finish` 同款），行数 / 行号逐字不变，再交 W1 冻结的 LL(1)+Pratt 前端，
    零改动 W1 解析器。
- `compile_film`（`lib.rs`）统一编译侧：按版本头分派 → 旧文件 `plan` 恒空（零损失）→
  命名通道降级进既有 `CompileV2Output.channels`（不新增任何结构字段）。
- `cmd_render.rs`（CLI）：`verify_external_assets` 用片子文件父目录（非 cwd）做解析根，
  缺失/不符 ⇒ `P9508`/`P9509` 三段式带声明行号，退出码 1、不落盘半成品。

### 判据数字

| 项 | 实测 |
|---|---|
| 资产种类覆盖 | EXR / 字体 / 音频 **3/3** |
| 内容哈希锁定 | `hash_mix_bytes` u64 / 16 hex；`inline` 内容与声明哈希自洽校验（P9504） |
| 路径不是隐式环境状态 | 换 `external` 路径（同 kind/hash）⇒ `canonical_bytes()` **逐字节相同**、产物哈希 **0 差异**；路径文本零字节进产物 |

## 2. 统一顶层入口 + 一条命令出片（§7 #9）

### 做了什么

- 新增 `[[bin]] name = "prism"`（`crates/prism-app/src/prism.rs` 薄入口），把
  `prism render <file.prism>` 字面兑现；出片实现**只有一份** `cmd_render::run`
  （与 `prism-app render` 完全同源），独立源文件避免 "same main.rs in multiple bin targets"
  歧义，且不挂进 lib、不污染 wasm `cdylib`。`autobins = false` 显式声明两个 bin。
- `prism render` 从冷启动到成片：`compile_film` → `render_movie` → 内置
  `write_mp4_jpeg_color`（MP4/MJPEG），退出码 0、无中间手工步骤、无外部依赖目录。
- **空环境（无 ffmpeg / 无 GPU）冷启动仍出片**：`--fast` 走 `CpuRefBackend`（纯 CPU
  Lambert，无 GPU）；`--codec mjpeg` / H.264 探测不到 ffmpeg 明确降级内置 MJPEG
  （不重开 C2，V2.5 已结清）。`scripts/w4_cold.sh` 以 `env PATH=""` 复现。

### 判据数字

| 项 | 实测 |
|---|---|
| 统一入口 | `prism render <file.prism>` 与 `prism-app render` 两 bin 全可用、行为逐字节一致 |
| 空环境冷启动退出码 | **0**（`PATH=""` 无 ffmpeg / `--fast` 无 GPU） |
| 出片链路 | 180 帧 / 32×24 / MP4 `ftyp` / 92,192 B / 内置 MJPEG / 152.661 ms |
| 无外部依赖目录 | `examples/films/` 仅 `.prism` 文件，资产全 `inline` 自包含 |
| 双档两跑逐字节 | analytic 92,192 B、crafted 92,063 B，各 `cmp` 逐字节一致 |

## 3. 任意参数时序驱动（A7）

### 做了什么

- `ChannelPlan`：`channel "<target>" { expr "..." | key <t>s <v> linear … }`，
  `expr` 走既有 `prism_anim::Expr::parse`、`key` 走既有 `prism_anim::Track`，
  采样走既有 `PropertyChannel::sample_ctx`（与 W2 `resolve_frame` 同一求值入口，
  红线 1 不重实现数学）。
- `target` 是**任意参数路径**：W2 的 L3 核心项（`R-2.roughness` 等）、
  观感六族痕迹强度（`w3.motion.strength` 等）、或任意自定义参数名。
- `compile_film` 把命名通道降级成既有 `NamedChannel`（名字 `w4.drive.<target>`）追加进
  `CompileV2Output.channels`；`movie.rs::wiring_frame_values` 末尾
  `apply_timed_channels` 在**渲染前、生成源头**把逐帧采样值写进 `WiringFrame`，
  对 `w3.<族>.strength` 同步按 W3 同一公式重算 `w3.<族>.signal`（不新造噪声、不贴皮）。
- 无 `w4.drive.*` 通道时覆盖层**立即恒等返回** ⇒ 旧文件 / analytic / W1-W3 全部样例逐字节零损失。

### 判据数字

| 项 | 实测 |
|---|---|
| 驱动面 | 观感六族 `w3.motion.strength` / `w3.material_light.strength` + W2 L3 `R-2.roughness` + 任意参数 |
| 逐帧值可断言 | frame 0 vs 120 六族强度 / L3 参数**值不同**；与 `Expr::sample(t)` **逐位对拍一致** |
| 两跑逐字节 | `frame_values` 两跑 BTreeMap 全等（固定序） |
| 通道降级 | crafted **3/3**、analytic **2/2** 全进 `compile.channels`（`w4.drive.*`） |
| 真进渲染链 | `apply_timed_channels` 把 `w3.motion.strength` 写进 `WiringFrame`，值与声明通道逐帧对拍逐位一致 |
| analytic 零噪 | analytic 档零 `w3.*` 驱动（编译期 P9514 门禁），覆盖层对 analytic 恒等 |
