### 2.2 M 级问题（6 项，应修）

#### M-1 — P3 变异体 B-M2 是无效变异体（负资产）

- **位置**：`:913-914`（B-M2）。
- **描述**：B-M2 称「切分平列时取最后一个最小代价桶 ⇒ 平列构型下结构随输入序
  漂移 ⇒ 置换签名不同」。本轮通读 `best_sah_split`（`bvh.rs:617-672`）确认：
  桶界经 `Aabb::grow`（min/max，精确、序无关）、桶计数为整数求和、前缀/后缀扫描
  按固定桶索引序、代价为定式表达式、argmin 为固定扫描序下的严格 `<`——**整个
  切分选择是图元集合的函数**（文档自己的 m7 修正与 ③-3「桶直方图本身已序无关」
  就是这样断言的）。把「首最小」改成「末最小」产生的是**另一棵同样确定、同样
  序无关**的树：A1 置换签名测试杀不死它（10 置换仍 → 1 签名），SAH 总代价也
  不变（平列 = 代价相等）。即：**没有任何已计划的测试能杀死 B-M2**——按「杀不死
  任何变异的测试是负资产」标准，它是无效条目，且其文字与文档自己的 ③-3 自相
  矛盾。
- **修正建议**：二选一——① 删除 B-M2；② 保留但改铸为**黄金结构 fixture 测试**
  的动机项：固定种子场景的参考结构签名固化入库，任何切分/tie-break 改动立刻红
  （当前测试计划缺这一类，见 §3.4 需补测试 T-4）。
- **证据**：`bvh.rs:617-672` 源码逐行；文档 `:762-766`（③-3 自述序无关）与
  `:913-914`（B-M2 声称序漂移）互相矛盾。

#### M-2 — P3 内容摘要是归纳法证明链中唯一的概率环节，且非抗碰撞

- **位置**：`:742-747`（内容键定义）、`:803-804`（归纳法第③步「摘要抗碰撞」）、
  `:1918`（exp13 索引「无碰撞」）。
- **描述**：证 3 归纳法的第③步「key 相等 ⇒ 位相同」依赖**摘要抗碰撞**假设：
  若两个不同内容的图元摘要有碰撞（且 Morton 码、质心位型均同），排序视其为
  「相等」，相对序回退到稳定排序 = 输入序 ⇒ 该对图元交换后 winding 累加序列
  改变（f32 非结合）⇒ **置换不变性被击穿**。本轮核验：引擎既有整数 hash 是
  PCG RXS-M-XS（`prism-noise/src/pcg.rs:31-48`，`permute` 含非常量右移，非双射、
  非抗碰撞设计）；exp13 实验实际用 FNV-1a（同样可构造碰撞）。自然资产下碰撞
  概率可忽略（10^6 图元 ≈ n²/2^65 ≈ 2.7e-8，exp13-T4 独立复跑：不同内容同摘要
  **0 次**），但**引擎在 P1 已把对抗输入（恶意 JPEG）纳入设计范围**，USD/mesh
  资产同样是可以被构造的数据——此处标准应一致。
- **修正建议**：det-canon 模块（U6）收拢时把内容摘要改为 **prism-core 既有
  SHA-256**（`signature.rs` 在用，截断 128 bit 亦可；代价 ~数百 ns/图元，
  相对 SAH 建树可忽略），或在文档显式声明「非对抗资产假设」并量化残余风险
  （二者取一，不允许像现在这样把概率假设藏在括号里）。
- **证据**：`prism-noise/src/pcg.rs:31-48`；exp13 脚本 `content_digest` 为
  FNV-1a；本轮独立复跑 exp13-T4（0 次不同内容碰撞，支持「自然资产安全」但不
  支持「抗碰撞」）；P1 `:174-197` 证明引擎已把对抗输入当设计输入。

#### M-3 — P5「新增字段忘记入哈希 ⇒ lint 测试必须红」在 Rust 里无机械机制

- **位置**：`:1228-1230`（③-2 闭包 lint 测试）、`:1306-1309`（A1「mock 新增字段」）。
- **描述**：Rust 无运行期反射（文档 n2 已承认这一点），手工字段扫描只能对

#### M-4 — P2 的 A1 断言口径未分「语义级分歧」与「字节级分歧」

- **描述**：文档自己的诚实声明（`:520-529`）与 B-M4（`:653-655`）都认定：

#### M-5 — 三个「跨平台/跨端 MD5 分歧」变异体判据在单平台 CI 不可执行

- **描述**：三条变异体的杀死判据都写成「跨平台 MD5 分歧」/「跨端 MD5 分歧」——

#### M-6 — P6 的 RQ-2 统计验收协议尚未写入验收标准，贴边风险无门禁化

### 2.3 m 级问题（9 项，建议修）

- **m-1（P1，派生值卫生三处）**。位置 `:185`、`:195`、`:203-204`。① 「16-bit
  最坏定理界 |S2| ≤ 1.510e23（超 i64 约 **1639×**）」——独立复算
  1.510e23/9.2234e18 = **1.64e4×**，文档小 10×（与已修的 B1 同类错误换个位置
  复活：派生倍数未复算）；② 「Stage2 改 i128 累加（余量 **5.08e15×**）」基准
  不明——该数对应 16-bit **对抗块** 3.352e22；对 8-bit 定理界是 2.9e17×、对
  16-bit 定理界是 1.13e15×，文档把它紧挨定理界摆放，易被误读；③ 「配对
  派生值 max|D| ≤ 8191（**上取整表述 8192**）」是 off-by-one 陷阱——
  8192·2^16 = 2^29 恰超阈一个单位（文档自己括号里刚警告过 `2^29` 本身超界，
  又把 8192 列为可接受表述，自相矛盾）。结论均不受影响（i128 或快慢分流不变），
  但本报告的核心教训（B1）正是「派生常量必须复算」，这三处应按同标准修正：
  改 1.64e4×、注明 5.08e15× 的基准、删去「上取整表述 8192」或改为「≤ 8191
  （8192 即超界）」。
- **m-2（P6，实验口径与理论口径叠用）**。位置 `:1386`、`:1453-1456`。exp9 的
  「CV=1」是 **lognormal 参数**（脚本自报「σ 的 CV=1.31，理论 63.2%」），实测
  中位 55.5%；文档「CV=1 时中位 55.5%」+「CV=1 时恰为 50%」把参数口径、σ 口径、
  理论值、实测值四者叠用。建议改为「lognormal cv=1（σ 的 CV≈1.31）：理论
  63.2%、实测中位 55.5%（差来自整数分配 + n≥1 钳位 + 20 抽抽样）」——结论
  （中位过线、IQR 贴边）不变，但读数不再混淆。
- **m-3（P7，A4 断言缺直接实证）**。位置 `:1813-1814`。A4 断言「同目标 4 段链
  vs 折叠闭式差 ≤ 2 LSB」，但 exp11-T3 只测了 **2 段**链（20000 组 max 1 LSB）。
  4 段链有 3 次中间舍入，worst-case 3 LSB——≤2 的断言要么补实验（4 段全网格），
  要么放宽到 ≤3。另：折叠闭式 `W_u = W1+W2−W1·W2/256` 自身的舍入次数也应计入
  界。
- **m-4（P3，B-M3 定位失准）**。位置 `:915-916`。B-M3「SAH 桶累加改 f64」——
  `best_sah_split` 的桶累加是 min/max + 整数计数，**没有 f32 求和可改**；真正
  的 f32 累加是 winding 聚合（`bvh.rs:313-324` 的 `area_sum/n_sum/ac_sum`）与
  `half_area` 链。变异体杀得死（f32/f64 两遍 winding 不同 ⇒ 签名不同）但定位
  描述须改为「winding 聚合或 half_area 链改 f64」，否则实施者找不到下手点。
- **m-5（P3，证 2 措辞与 m7 修正不同步）**。位置 `:776-777`。证 2 仍把
  `bvh.rs:313-324` 的 winding 聚合称作「桶累加」——与 best_sah_split 的桶
  混淆（m7 只改了 ① 的问题叙述）。建议统一术语：「SAH 桶（计数/边界，序无关）」
  与「winding 聚合（f32 求和，序敏感）」分开命名。
- **m-6（P4，水位求解有更优算法形态）**。位置 `:1023-1024`。`R_i =
  max(0, ½log₂(θ_i/θ))` 在 **log 域是分段线性**的：排序 L_i = log₂θ_i 后，
  对活跃集大小 k 有闭式 `l = (Σ_{j≤k}L_(j) − 2B)/k`，扫描取首个自洽 k 即得
  **精确解**（无迭代、无容差、|ΣR−B| 从 1.1e-13 降到一次舍入量级）。同数学、
  更简单：消掉 200 步二分与 A1 的 1e-9 容差断言，det_log2 调用量同为 n 次。
  建议评估后替换（不阻塞，bisection 版已实证可用）。
- **m-7（P2，引用精度）**。位置 `:564-565`。「parity 测试网已存在
  （`integrator.rs:22-26`、`wavefront.rs:825-943`）」——本轮核验：
  `integrator.rs:22-26` 是估计量结构**文档注释**不是测试；测试网实际在
  `wavefront.rs:825-943` 内联（E5 parity 系列）+ `tests/qa_probe_wavefront_parity.rs`。
  结论（无需新建）成立，引用应更正。
- **m-8（P3，实验与文档的哈希选型不一致）**。位置 `:744-746`、`:1918`。exp13
  用 FNV-1a，文档指向「prism-noise 既有整数 hash」（PCG）。两者都非抗碰撞
  （见 M-2），但实现时应钉死一个并补 Rust 侧对拍；若采纳 M-2 的 SHA-256 路线，
  本项自动消解。
- **m-9（P7，证 3 卖点无测试承载）**。位置 `:1708-1711`（证 3）、`:1740`（⑥
  效果「CPU/GPU 转场逐位一致」）。证 3 是 P7 的核心卖点之一，但测试方案
  A1–A4/B-M1–M6 中**没有 GPU parity 条目**（A1 是 CPU vs f64 参考）。当前
  GPU 合成路径尚未排期，可接受延迟，但应在测试方案里以 `#[ignore]` 占位或把
  ⑥ 该条改口径为「设计性质，待 GPU 合成路径落地时验收」，避免「效果已交付」

## 4. 降维打击检索专章

### 4.0 检索方法与否证标准

对每个提案先独立回答「这个问题的数学本质是什么」，再检索三类更强构造：
① 解决整个问题族的更底层结构/定理/变换；② 跨提案统一工具；③ 现框架是否某更强
框架的特例。检索候选全部文献级（快速 DCT 家族、LBVH/HBVH、工业码控、Neyman
分配、Kalman/SVGF、Porter-Duff、精确整数几何、类型论机械枚举）。**证明标准与
既有提案一致：没有证明的降维打击是幻觉**——工程层提案的「证明」如实标注为
类型论保证而非数值证明。

### 4.1 逐提案数学本质判断

**P1 — 本质：在 ℤ 上精确实现 ℝ 上的正交线性变换（误差有界 + 位确定）。**
现设计（DCT 正交性 + 权重折归一化的两阶段整数变换）就是该约束下的标准解：
把 ¼·c(u)c(v) 折进 W 表后全部运算落入整数格」。已检索候选：① **AAN/Loeffler 快速
DCT**（每 1D 5–11 乘）——架构师第二轮已独立比对，三条否决理由（破坏表共享、
蝶形中间量界需重推、收益主轴是确定性非速度）全部成立，本轮确认无翻案；
② 晶格量化视角——现两阶段缩放即其标准构造；③ 精确有理公共分母——不存在
（K 为代数数，无有限公分母）。**结论：无更优已知构造。**

**P2 — 本质：有限集上全序 argmin 的置换不变性（序无关由全序结构保证）+ 浮点
归约的误差预算（残余差异有界）。** 已检索候选：① **精确整数交点**
（fixed-point MT + slab，WGSL 整数运算无 fma 收缩 ⇒ 可给真正的 bit-exact
GPU/CPU parity）——**这是唯一未被文档检索记录覆盖的候选**（文档 ⑧ 以「GPU 侧
禁 fma 不可行（编译器自由）」否决了 FP 路线，但该理由管不到整数路线）。否决
理由（如实留痕）：D-3 已定案「GPU 不追求逐位确定，双门禁是正确框架」（负面
清单 #4 明确「不提案，且反对」）；fixed-point 的位宽/动态范围分析（质心
2^21 + t 到远平面 ⇒ 中间量需 i64/i128，WGSL i64 可用性随后端）+ GPU 整数除
吞吐 + 大场景擦边命中的精度损失，三项代价换一个架构已裁决放弃的目标。**在
D-3 框架内现设计已是最优；框架外的整数路线被架构定案排除，不提案。**
② 随机式 OIT（Wyman–McGuire 一脉）——破坏确定性目标，否决。③ 全序 argmin
即标准答案（任何 tie-break 都是全序选取，问题只在与 CPU 规则一致）。

**P3 — 本质：输出必须是图元多重集的纯函数 ⇒ 输入规范化 + 规范形上纯函数计算。**
现设计（内容键全序 + 归纳法）是该问题的完整解：排序键三组分（Morton 码定空间
序、质心位型破共码、内容摘要兜底真重复）都是图元自身数据的纯函数。已检索
候选：① **精确整数累加 winding**（把序敏 f32 求和换成精确结合运算——确实能
消除序敏点）——但它不解决叶内排列，也不产出规范槽位（P2 的 tie-break 依赖），
被现方案完全覆盖且更贵（要动几何累加器类型）；② Hilbert 曲线（架构师已比对，
否决理由成立）；③ 多重集 Merkle 哈希——与内容键排序等价的信息量。**结论：
无更优；残留问题只有摘要碰撞的概率假设（M-2），那是工程选型不是数学缺口。**

**P4 — 本质：可分凸资源分配（单纯形约束 + 下界）⇒ KKT/水填充，就是该问题族
的规范解。** 已检索候选：① λ-域搜索——同一 KKT 对偶变量，等价（文档已判）；
② **log 域分段闭式**——同数学的更优算法形态（消二分迭代与容差，见 m-6），
但不是不同的数学；③ 逐帧 RDO——需编码器在线支持，超出 MJPEG/PRMV 自研路径
（文档已正确划界）；④ 传播系数矩阵——已列为后续增强。**结论：无新数学；
现设计即规范解。**

**P5 — 本质：缓存正确性 ⟺ 键是输出依赖闭包的充分统计量（信息论下最紧形式）。**
已检索候选：① 全量输入序列化哈希——平凡充分解，浪费命中率（文档已审否决）；
② Merkle 树分级键——实现优化（文档已识别）；③ 内容寻址 asset CID——等价强度
的工程选型。**结论：数学层无更优；但「闭包的人工枚举」这个工程问题族有结构性
更优解——见 P8。**

**P6 — 本质：方差最优预算分配（Neyman 1934）+ 线性最优估计（Gauss–Markov）；
两者是「逆方差加权」同一原理的设计时/运行时两面。** 已检索候选：① σ^α 连续
标定——α=1 是 MSE 最优唯一定点（拉格朗日一阶条件刚性），文档已判否决；
② **Q>0 完整 Kalman**——动态场景严格更优，已列为后续（先落 Q=0 零回退版
是对的次序）；③ 按区域 CV 自适应切换——CV 信息已隐含在闭式（√λ 自动处理），
冗余；④ 变换域（小波/梯度）分层——分层定义不同但分配律不变，不触及本质。
**结论：无新数学；现设计即规范解。**

**P7 — 本质：保留分数乘法半群（t↦ln(1−t) 同构于 (ℝ,+) 非正部分）+ 凸组合 +
整数格舍入。** 已检索候选：① **Porter-Duff 预乘 alpha 结合代数**——合成操作
的一般理论；但不透明 u8 场景下凸组合即其特例，文档的凸权重向量框架已覆盖
推广形态（四转场统一 + 新转场零成本继承），再上层化无增益；② 精确有理权重
——已入设计（u32 ≤3/u64 ≤4）；③ dithering——破坏 seek 重放确定性，文档已判。
**结论：无更优；凸权重半群就是该问题族的正确抽象。**

### 4.2 跨提案统一工具检索

**数学层：无新的统一定理。** §0-A 的双支柱（规范化 5 项 + 最优性 2 项）是正确
分解——P1/P2/P3/P5/P7 的全部困难确实是「非规范输入穿透输出」，P4/P6 的全部
困难确实是「建模错误取代最优性」。没有覆盖七者的第三块基石。

**工程层：两项收拢 + 一条框架锐化。**

1. **P4×P6 共用「带下界的对偶闭式求解器」**（架构师 U6 已提议 gate harness，
  但漏了求解器本身）：P4 的 `R_i = max(0, ½log₂(θ_i/θ))` 与 P6 的
   `n_i = max(1, σ_i/√λ)` 是同一形状（主动支对偶闭式 + 钳位支 KKT 互补松弛），
   可收拢为一个 ~30 行小模块（对偶函数 + 逆函数 + 二分/分段求水位），两提案
   各传一个 3 行闭包。证明不变（各自的 KKT 充分性），实现面减半。属工程收拢，
   不计入新提案。
2. **§0-A 锐化为「泄漏诊断法则」**（有预测力，建议写入框架节）：
   **「任何在非精确结合运算（f32 加法是典型）上对集合的归约，都是确定性泄漏
   点；解药只有两种——换成精确结合的代数结构（整数格/定点/全序 min/哈希），
   或把运算序列规范化（规范形排序）。」** 该法则 retrospective 解释全部既有
   发现（P2 归约 ⇒ 统计门禁；P3 winding ⇒ 规范序；P1/P7 ⇒ 换整数格后泄漏
   消除），且 **predictive 预警三个尚未排期的路线图项**：V2.0-RQ-2 阶段二
   SVGF 空域混合（f32 邻域求和）、V2.0-AU-1 多轨混音总线（≥8 轨 f32 求和，
   轨序/并行归并序须钉死）、V2.0-PE-1 分布式渲染合并（跨机部分和合并序）。
   建议把该法则写进这三项的验收清单。

### 4.3 新提案 P8（工程层「降维打击」：缓存键的编译器强制字段枚举）

> 定位声明：本提案**不是新数学**——P5 的充分统计量定理原样保留；它换掉的是
> 「π 的构造方式」：从「人工枚举 + 测试守护」到「类型系统机械枚举」。其证明是
> **类型论保证 + 金丝雀测试**，不是数值证明——如实标注，按工程提案标准呈报。

**① 问题现状**。P5 的键正确性依赖手工 `to_hash_bytes` 的闭包完备；闭包完备靠
人。第一轮自审实证：闭包清单漏 2 项（`global_seed`、scene 签名）——同类错误
可再犯，且失败模式是 silent wrongness（不崩溃、只是错）。Rust 无运行期反射，
「新增字段忘记入哈希 ⇒ lint 测试必须红」无机械机制（M-3）：手工字段扫描只能
守护已存在字段，对将来字段静默失效。

**② 数学结构**。无新数学。变化的是可靠性论证的类型：P5 证 1（π 覆盖 Dep(F)
⇒ 健全）不变；新增一层**机械完备性**——π 对 RenderParams 部分的覆盖由编译器
保证而非人的清单。

**③ 算法设计**。用 `macro_rules!`（**无需新 proc-macro crate**，不破 D-15 的
运行期零第三方——宏是构建期第一方件）定义参数结构体：宏同时展开出 ① struct
定义；② `impl ToHashBytes`——按声明序逐字段写入位型（整数 to_be_bytes、
f32/f64 to_bits、bool 单字节）；③ `FIELD_COUNT` 常量与哨兵构造器。显式排除
用属性清单（仅当某字段被**证明**不影响输出——fail-safe 方向不变：宁过勿欠）。
lint 测试改为：每字段哨兵敏感性断言（宏生成）+ 金丝雀测试（宏内嵌一个演示
struct 带 skip 字段，断言 skip 生效、非 skip 字段全敏感）。

**④ 证明**。① **完备性**：宏在 use site 看到的结构体定义即全部字段，展开对
每个字段生成入哈希代码 ⇒ 「漏字段」从每字段的人为疏失变成宏本身的一次性 bug
（可测、可审查，且写完不再复发）；② **金丝雀**：演示 struct 证明 skip 机制与
敏感性断言有效（测试的测试）；③ **与 P5 证 1 合成**：π 机械覆盖 RenderParams
全部字段 ⊇ Dep(F) 中属于 RenderParams 的部分 ⇒ 健全性保持；其余闭包分量
（sampler 种子、scene_sig、frame）仍人工，但面从「每字段」缩到「每结构体」。
**诚实边界**：skip 清单本身是新的手工面——由金丝雀测试 + review 纪律看守，
其大小比全字段枚举小一个量级。

**⑤ 工作量杠杆**。消灭 silent-wrongness 根因类中最大的一块（字段漂移）；宏
~30 行一次成本；P5 其余设计（键结构、schema bump、fail-safe 方向）不动。

**⑥ 效果提升**。「键相等 ⇒ 逐字节一致」从「定理 + 人可能犯错」升级为「定理 +
编译器背书」；新增渲染参数零心智成本（lint 测试自动继承敏感性）。

**⑦ 风险反证**。① f32 位型入键：-0.0/NaN 的 to_bits 确定 ⇒ 确定性保持，且
多失效不少错（fail-safe 方向）；② 字段重排改变键 ⇒ schema_version bump 既有
语义消化（宪章 C13/D-28）；③ 宏降低 struct 可读性/IDE 支持 ⇒ 用声明式宏保持
展开可 inspect，struct 定义仍是普通语法；④ 与文档「禁 derive 黑盒」纪律的
冲突——回应：字段枚举 derive 不是黑盒（展开逐字段显式、可打印审查），被禁的
应是「语义不透明的自动 derive」。
