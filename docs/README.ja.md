## これは何か

Prism Engine は Rust で書かれたサードパーティコード依存ゼロのメディアエンジンである。画像の読み込み、レイアウト、画面の描画、
タイムラインの編集、完成品の出力まで、すべてを単一の決定論的エンジンで完結させる。110 個の実行時依存
（ほかに 20 個のテスト依存）はすべて本リポジトリの `path` 依存である——ネットワークに依存せず、パッケージマネージャも要らず、
サプライチェーンリスクもない。

**単一ファイルソース配布**を採用している。エンジン全体（642 ファイル、28 個の crate）を 1 つの UTF-8
テキスト `prism-engine-v2.1-source.txt` に統合。このファイルさえあれば、リポジトリと完全に同一の
ディレクトリツリーをローカルで復元できる。

## エンジンにできること

ひとことで言えば：**画像はある瞬間の画面の姿であり、動画はある期間にわたる画面の連なりの姿である**——
同じシーン記述でも、ある一点で固定すれば単一フレーム、連続的に進めて記録すれば動画になり、静止画と動画は同じ能力を共有する。
以下では「やりたいこと」ごとに 5 つのブロックに分けて述べる：**読み込む → 組み立てる → 描く → 完成させる → 自分のツールチェーンに組み込む**。

### 何を読むか（入力）

- **統一デコードファサード**：単一の `decode_image(bytes, ext)` エントリが静止画を振り分ける——PNG（非インターレース 8/16bit）、
  ベースライン JPEG（固定小数点 IDCT、クロスプラットフォームでビット単位まで決定的）、**マジックナンバー優先・拡張子フォールバック**（拡張子を間違えてもデコードできる）。
  対応範囲外、あるいは外部連携が必要な形式はすべて三段式でエラー報告（どこで / 何が / どう直す）し、ffmpeg との連携案を示す。
  **決して静かに失敗しない**。
- **アニメーション画像 / 音声 / コンテナ**：GIF、APNG をネイティブにフレーム単位でデコード（`prism-media`）。WAV は内蔵デコーダ、mp3/aac/FLAC
  は ffmpeg の検出パスを使用（`prism-audio`）。MP4-MJPEG の読み戻し（`decode_mp4_video`）。
- **EXR フルセット**：読み書き、圧縮、DWA に対応し、公式 OpenEXR との**実装間ビットストリーム突き合わせ**を実施（自作実装の自己完結ではない）。
- **カメラ RAW**：ベースライン RAW デコード。**境界**：実在する DNG の `Compression=7`（lossless JPEG）は未実装であり、
  実機のカメラが出力した DNG は読めない——「正直な境界」に書いてあり、隠していない。
- **3D アセット**：glTF / OBJ のインポート、USD（`.usda`）の解析と MaterialX パラメータパック、mesh はレンダリングシーンに投入できる。
- **外部フォント**：`load_font_file` でサードパーティ製 TTF/OTF を直接ロードし、フォールバックチェーンを段階的に解決。
  字形が欠けている場合は豆腐（□）ではなく明確な診断を返す。

### 何を組み立てるか（制作文法）

- **DSL v2 の全ブロック文法**：1 つの `.prism` で「何が欲しいか、どう配置するか、どう動かすか、どんな見た目か、
  何に書き出すか」を記述し、コンパイル結果はノードグラフ + プロパティチャンネル + タイムラインになる。
- **5 つのコンビネータ**：`title_card` / `lower_third` / `split_screen` / `ken_burns` /
  `morph_between` という高水準コンビネータがノードグラフへ展開され、「90 秒の完成品」はシーンコードの手書きから組み立てへと変わる。
- **トランジションと morph**：Fade / Wipe / Dissolve / Push をすべてパラメータ化（長さ、イージング、方向）。
  Morph はポリライン変形で、シーンシーケンスは任意の時刻でサンプリングできる。
- **数式組版**：`math_ast` + `math_layout` で上付き・下付き / 分数 / 根号 / 大型演算子 /
  行列を組む。DSL の `formula` ブロックで直接組版でき、本文とベースラインを揃える。

### 何を描くか（レンダリングとシミュレーション）

- **オフラインのフォトリアルレンダリング**：パストレーシング + 物理的に正確な BSDF（拡散 / 鏡面 / ガラス / 金属）。
  ガラスと金属は Neumann 級数モンテカルロによる確率的逆算で扱い、ボリューム媒質とサブサーフェス散乱にも対応する。
- **曲面プリミティブの 4 系統**：円柱 / 円錐 / トーラス / 回転曲面。すべて解析的に交差判定する（四次方程式は
  Ferrari の閉形式解で厳密根を得る）。任意の三角 mesh + SAH-BVH に対応し、2 経路のパリティ突き合わせを行う。
- **GPU compute**：デバイス非依存の compute セマンティクス層 + Vulkan dispatch + 手書きの最小 SPIR-V。
  Mesa lavapipe のソフトウェア ICD 下では GPU 非搭載プラットフォームでも完全に動作する（headless で検証可能）。
- **物理とパーティクル**：XPBD 統合ソルバ（剛体 / 軟体 / クロス / ジョイント / 流体 / 破壊）、
  煙の FLIP、パーティクルシステム（AudioReactive が音声エンベロープと連動）。
- **ジェネラティブアートとポストエフェクト**：フローフィールド / L システム / セルオートマトン / 反応拡散 / フラクタル / Voronoi；
  blur / bloom / halation / フィルムグレイン / NPR 4 スタイル（toon / watercolor / halftone / oil）/ 3 in 1 デノイズ。
- **カラーグレーディングとベクター**：セカンダリカラー補正（HSL 選択 + RGB カーブ）、cinematic / film / anime 風プリセット、
  下書き / 標準 / 映画の 3 段階画質（画質はパラメータであり、勘所ではない）。ベクターパスのラスタライズ、パスの draw-on と morph。
- **音声処理**：ラウドネス正規化（loudnorm）、ビート検出、スペクトル解析、エンベロープ抽出——
  映像と連動できる（パーティクルの AudioReactive が音声エンベロープに追従する）。
- **CPU リファレンスバックエンドは第一級の市民**：GPU のないマシンでも正しい画像を出力でき、同時に GPU の正解判定基準ともなる。

### 何を出すか（納品）

- **`render_movie` への直行**：DSL v2 のコンパイル結果を 1 回の呼び出しで「フレームごとの評価 → tile レンダリング →
  納品」まで通し、`.prism` から単一コマンドで完成品を出力（`prism-app render demo.prism`）。未対応のノードは正直にエラーを返し、黙って近似しない。
- **プレビューの閉ループ**：`prism-app preview` でプレビューサービスを起動。エディタは Draft モード（幾何パターンでフレームレートを維持）/
  Real モード（低 spp の実レンダリング、非同期更新）の 2 段階プレビュー。
- **自社開発エンコーダ + レート制御**：I/P フレームの JPEG 領域時間方向エンコーダが独自の `PRMV` コンテナ（v2/v3 の 2 世代
  schema）を使用。water-filling レート制御 + qpel サブピクセル動き推定（実測 PSNR +2.577 dB、
  サイズ −21.6%）。
- **ffmpeg 連携チェーン**：ffmpeg があれば → stdin の rawvideo パイプ経由で H.264/HEVC に変換。
  ffmpeg がなければ → 自動的に MJPEG へ降格し、**エンジンは常に映像を出力できる**。バイナリは一切同梱しない。
- **EXR シーケンス納品**：フレームシーケンスを直接 EXR で書き出し、ポストプロダクションパイプラインへ渡す。
- **分散レンダーファーム**：フレーム単位の分散 + N プロセスの worker + 決定論的マージ——並列 MD5 == 逐次 MD5 であり、
  中断からの再開にも対応する。

### どう統合するか（エコシステム）

- **MCP ツール面**：stdio JSON-RPC の 3 ツール——`scene_check`（コンパイル + 試しレンダリング + フレーム数見積り）、
  `render_submit`（決定論的な job id + フレームごとの MD5 ダイジェスト）、`diagnose`（三段式のエラー特定）。
- **ノード SDK**：セマンティックバージョニングのネゴシエーション（0.x の特例を含む）。パッケージにはサンプルノードパッケージを同梱
  （`examples/sdk-nodes/cinematic-basic/`、コンパイル可 / ロード可 / ネゴシエーション可）。
- **ハードウェアエンコード検出の骨組み**：`prism-ffi-hwenc` の 3 プラットフォーム（VideoToolbox / NVENC / VAAPI）
  検出チェーン + feature gate マトリクス。プラットフォームが合わなければ非対応と明確に報告する。

> 詳細な能力境界（何が**できないか**）は、展開後の `开发者指南.md` の「正直な境界」節を参照——
> そこには現時点の実際の状態が記録されている（曲面プリミティブは CPU のみ、GPU 加速比は対象ハードウェアでの実測が必要、
> ハードウェアエンコードは対象プラットフォームごとに接続…）。本書は全体像を示すだけであり、誇張はしない。

## エンジン内部の特殊能力（機能一覧の外側）

「読む／組む／描く／出す／統合する」の一覧に収まらない能力——それはエンジンの深層資産です。この章で本編の一覧をすっきり保ちます。

### 音声：内蔵 DAW カーネル

`prism-audio` は「WAV が読める」程度の周辺モジュールではなく、作曲からミックスまでの全工程を持つ**決定論的 DAW カーネル**です。すべての関数はパラメータの純関数（同一入力ならプラットフォーム間でビット一致）です。

- **合成**：PolyBLEP アンチエイリアス発振器群 + 閉形式 ADSR エンベロープ + 4 種のムードプリセット；
- **楽理**：スケールライブラリ（長短調／五音音階／教会旋法）、12-TET 音高↔周波数、和声進行の**機能文法ステートマシン** + 声部進行；
- **シーケンス**：アルペジエーター（パターン／レート／オクターブ）、ステップドラムマシン、小節・拍グリッドのスコア編曲；
- **素材**：手書き SMF パーサ（MIDI インポート）、SFZ サンプラー、グラニュラー合成；
- **サウンドデザイン**：物理モデリング、空間パンニング、エフェクトチェーン；
- **ミックス**：マルチトラック線形ミックス + フェード + ピークリミッティング；
- **解析と連動**：ビート／オンセット検出、FFT スペクトル、エンベロープ抽出、AudioReactive ベイク（N フレーム目は固定窓を読む。フレーム単位の純関数で seek 等価）、ラウドネス正規化。

> 境界：AAC/mp3 は自研しません（特許の歴史と工数）。汎用音声は外部 ffmpeg 経由です。

### 定義可能なカーネルライブラリ（特解レジストリ）

各ノード種別は「カーネル + 格子 + 双対」の三つ組に対する**特解**です。第三者（またはあなた）は `registry!` で新しい特解を登録でき、エンジン中核を変更する必要はありません。

- 静的一括登録（マクロは定義側 crate 内で展開。`inventory`／proc-macro 禁止、依存ゼロ）；
- 登録時の**三問検証**（カーネル形式／格子／双対）。答えが欠ければ三段式エラーで拒否；
- 公式特解とカスタム特解は同じレジストリを共有し、実行時に区別なし；
- 数学的には作用素方程式 `f = g + Kf` の六つの反転戦略——厳密／確率／局所／正則化／反復／スペクトル。能力追加は三つ組の宣言であり、レンダリングループへの継ぎ当てではありません。

### 決定論と再現性の基盤

- **署名閉包**：ノードグラフ／キャッシュキー／スナップショットキー／フレーム署名を「四次元構成ハッシュ」に統一。パラメータを変えればキーが変わり、誤再利用が起きません。反復ノードは `(ε, n)`、ストリームノードはフレーム番号をキーに含めます；
- **バイト不動点**：USD は export→import→export でバイト一致。WAV 16/24/32 bit は往復一致。EXR は公式実装とビット単位で対比；
- **単一ファイル配布の決定性**：同じソースは二回パックしても SHA-256 が一致。展開ラウンドトリップは全ファイルをバイト単位で照合。

### GPU バックエンド（正直に分述）

- **Vulkan**：compute とレイトレースシーンの両パイプラインが実動作（lavapipe ソフトウェア ICD なら GPU なしで検証可能）。`render_scene` の出力は CPU 参照と**バイト一致（差分ピクセル 0）**。`is_available()` は compute ∧ render の二重セルフテスト；
- **Metal**：同型移植 + コンパイルゲートのみ。**実機未検証・点灯なし**（`is_available()` は常に false）；
- **WebGPU**：実現可能性の結論のみ（4〜6 人日）。レンダリング経路は未実装。

### 偽グリーン防止ゲート

ローカルゲート 4 本（依存ゼロ、`node` のみ）：ゴースト書き込み防御（逆向き自己証明つき）、オープンソース衛生スキャン、コンプライアンス自己検査（9/9、逆向き自己証明 8/8 レッド）、パッケージのラウンドトリップ検証。ゲートの結果は「合格」か「レッド」のみ。「たぶん大丈夫」は認めません。**偽グリーンは失敗より危険です。**

## なぜ単一ファイル配布なのか

- **監査可能**：1 つのテキストファイルであり、人の目で読め、`diff` が取れ、ハッシュ検証ができる。公開された時点で凍結される。
- **再現可能**：パッケージングは決定論的——同じ入力で 2 回パッケージすれば SHA-256 が完全に一致する。
- **可搬性**：巨大なリポジトリを clone する必要はなく、1 つのファイルをメールやチャットで送るだけでよく、オフラインでも復元してビルドできる。
- **トレードオフの説明**：単一ファイル配布は「GitHub 上で直接コードを閲覧できる」利便性を手放す代わりに、「1 つのファイルで全部を持ち帰り、しかもバイト単位で検証できる」決定性を得ている。展開後に得られるのは通常の Cargo workspace であり、一般的な Rust プロジェクトと変わらない。

## クイックスタート

前提：[Rust](https://www.rust-lang.org/)（`cargo` を含む）と [Node.js](https://nodejs.org/) 18+ をインストールしておく。

```bash
# 1. リポジトリ内の prism-engine-v2.1-source.txt をダウンロードし、ローカルファイルとして保存
# 2. テキストエディタで開き、"UNPACK SCRIPT BEGIN" と "UNPACK SCRIPT END"
#    の間にある Node.js スクリプトを同じディレクトリの unpack.cjs として別名保存
# 3. 展開を実行（数秒で 642 ファイルを復元）
node unpack.cjs
# 4. 復元されたディレクトリ（workspace ルート）で全テストを実行
cargo test --workspace --release
# 想定：3929 passed / 0 failed
```

展開後は標準的な Cargo workspace（`src/` 配下に 28 個の crate）が得られ、以降の `cargo` コマンドは一般的な Rust プロジェクトと同じである。

> モバイル端末での wasm 検証手順：`rustup target add wasm32-unknown-unknown`、続いて `cargo build -p prism-core --target wasm32-unknown-unknown`。

## ビルドとテスト

```bash
# リポジトリ全体のスモーク（release、推奨）
cargo test --workspace --release
# 等価なエイリアス
cargo xtest
# 単一 crate のクイック検証
cargo test -p prism-core --release
```

- 全量テスト：**3929 passed / 0 failed / 0 ignored**（リポジトリ内で release 実走：179 テストスイート、全コア並列 171.5 秒。パッケージはリポジトリとバイト単位で一致し、デモ crate のみ除外）
- CI：**6 個の job**——ゴースト書き込み防御（ghost-guard）/ コンパイル + 全量テスト（native）/ wasm32 ビルド（wasm）/
  WGSL 静的検査（wasm-verify）/ 公式 OpenEXR との実装間ビットストリーム突き合わせ（interop）/ node ホストのクロス判定（lint）。
- ローカルゲートスクリプト 3 個（すべて依存ゼロ、`node` のみ使用、下記）+ パッケージングスクリプト 1 個。
  うちコンプライアンス自己診断は **9/9 通過**、逆方向の自己証明は **8/8 で赤判定**。

ローカルでゲートを実行する（Node 18+ が必要）：

```bash
node tools/ghost_guard.mjs --check        # ゴースト書き込み防御：G1 重複定義/G2 厳密な上位集合/G3 行頭ドキュメント/G4 コンパイル
node tools/hygiene_scan.mjs               # オープンソース衛生：残存する内部用語を 1 件ずつ列挙（ファイル:行番号）、ヒットすれば exit 1
node tools/compliance_check.mjs           # コンプライアンス自己診断：9/9 通過すべき
node tools/compliance_check.mjs --self-test   # 逆方向自己証明：赤判定となるべきで、判定基準に識別力があることを証明する
```

> **オープンソース衛生スキャンには、現時点でも既存のヒットが残っている**：リポジトリには初期の内部用語が残留しており、そのうち
> **パッケージに同梱されるドキュメント層はゼロになっている**（README / 開発者ガイド / Compliance）。残りは**配布パッケージ内のソースコメント**
> と**配布パッケージに含まれないリポジトリのファイル**にあり、事実に基づいて分類したうえで独立した整理項目としている。スクリプトの存在意義は、
> 残留を**可視化し、1 件ずつ片付けられる**ようにすることであり、きれいなふりをすることではない——「ヒット数が 0 でない」ことを
> ゲートの失効と解釈しないでほしい。

## コンプライアンス

エンジンは**サードパーティコード依存ゼロ**を約束し、自己診断で検証している：

- **C1 サードパーティコード依存ゼロ**：全 130 個の依存（110 個の実行時 + 20 個のテスト）が本リポジトリの `path` 依存。`build.rs` はなく、ネイティブリンク指示もなく、`Cargo.lock` は本リポジトリの 29 パッケージを固定している。
- **C2 アセット登録の完備**：5 項目のアセット主表はフィールドが揃い、自社開発化の状態は統制語彙に収まっている。OFL 1.1 のフォントライセンス全文はフォントとともに `src/prism-text/font_data/LICENSE` に置かれている。
- **C3 第三者帰属表示**：`Compliance/THIRD-PARTY-NOTICES.md` が存在し、「データアセット ≠ コード依存」を明確に区別している。

> 注：本リポジトリが配布するのは**ソースコード**である。フォントアセット（Prism Sans SC のサブセット）は SIL OFL 1.1 でライセンスされ、**ライセンス全文はフォントとともに置かれている** `src/prism-text/font_data/LICENSE`。アセットの出典とライセンス登録は `Compliance/assets/资产登记.md` を参照。
