## 2. 算法实现（C1 的四根柱子）

### 2.1 立体角测度与极点相消

行 `j` 覆盖极角带 `[θ_j, θ_{j+1}]`，立体角取**精确球冠**（不是 `sinθ·Δθ·Δφ` 的梯形近似）：

```text
Ω_j = 2π(cos θ_j − cos θ_{j+1})        j = 0 与 j = H−1 同式，无极点特判
Ω_ij = Ω_j / W                          行内 φ 均匀
```

采样取 `p_ij ∝ L_ij·Ω_ij`、行内位置均匀 ⇒ `pdf_ω = p_ij/Ω_ij = L_ij / Σ(L·Ω)`。
分子分母的 `sinθ` **精确相消**，`pdf_ω` 与 `θ` 无关，极点不发散。
常数环境（`L ≡ 1`）退化为 `pdf_ω ≡ 1/4π` —— 这正是 V5 的靶子。

### 2.2 前缀和全程整数（§1.2 求和顺序红线）

`L·Ω` 按 `2^40/max` 量化为 **u64**，前缀和整数累加，`u128` 精确归一化到 u32 存储。
整数加法可交换 ⇒ **求和顺序无关**（比"固定顺序"强一档）：SIMD 重排、分块归约都不改一个字节。
运行期只做整数二分 + 两次 f32 除法。`build_is_bitwise_deterministic` 钉住"同纹素两次构建逐字节相同"。

量化尺度的余量：`W ≤ 8192` 时行内累计 `≤ 2^53`，u64 留 11 位，不被归一化吃掉精度。

### 2.3 亮斑列表 + 残差两级拆分

单一 CDF 里太阳 texel 的权重比天空大 5~6 个数量级，u32 分辨率会被吃干净（尾部 texel 变成 0 宽 = 永不采样）。
两级拆分把分布写成混合：

```text
p(ω) = P_s·(w_k/W_S) + (1−P_s)·(w_k/W_R)   k ∈ S / k ∈ R
     ≡ w_k / (T·Ω_k)                         （代数恒等）
```

**拆分只改采样路径，不改目标密度**，`pdf_ω` 仍是 `L_ij/Σ(L·Ω)`。
残差支路用自己的总量归一化 ⇒ 全 u32 分辨率留给"非太阳"的部分。

**判据用中位数不用均值**（`env.rs:255-262` 的注释是同一条推导）：设 `N` 个 texel 里 `k` 个太阳、
亮度 `S`、其余 1，均值判据 `S·Ω_total/N > 64·kS/N` 化成 `Ω_total > 64k`，**与 `S` 无关**，
`4π < 64` ⇒ 无论太阳多亮都判不出来（即"均值判据永不触发"）。
中位数对少数离群值免疫，判据退化为"比天空亮 64 倍"，正是要抓的东西。

### 2.4 双线性取值、不预过滤

`radiance(dir)` = `dir → uv` → 双线性（`u` 平铺 wrap、`v` clamp），只取 lod 0；
`sample(u1,u2)` = 边际反演行 → 条件反演列 → `texel_dir(j,i,fv,fu)` 在 texel 内线性插值。
**没有**预过滤 cubemap、**没有** `F·L` 分离、**没有** LOD 三线性混合 —— 代价是每样本一次二分
（十几步整数比较），收益是无近似（V1/V3 的余量就是它换来的）。

### 2.5 MIS：NEE 臂与逃逸臂逐位互补

```text
NEE（CDF 策略）  w_nee  = power_heuristic(pdf_env, pdf_bsdf)
逃逸（BSDF 策略） w_bsdf = 1 − power_heuristic(pdf_env, pdf_bsdf)
```

两式同参同序 ⇒ `w_nee + w_bsdf ≡ 1` 是**结构性**成立，不是数值巧合（V1 用 532,480 对样本钉住）。
`prev_specular`（相机段 / 镜面链）取 `w = 1`：镜面方向是 δ 分布，CDF 策略对它测度为零。

### 2.6 场景装配

* `Scene::add_environment(w, h, pixels) -> u32`：注册贴图 + 装 `Light::Environment` + 建 CDF，**一步原子**；
* `Scene::rebuild_env_cdf()`：手工装配 `lights`/`textures` 后补建；
* `Scene::env_cdf: Option<EnvCdf>` 是**公开只读字段**（与 `curve_bvh`/`instance_bvh` 同口径，
  私有字段会让跨 crate 结构体字面量构造 E0451）；
* `validate_layout` 新增两条硬错：有 `Environment` 灯但 CDF 为空 / CDF 句柄与灯不一致；
  以及 `Light::Ambient` 与 `Light::Environment` **互斥**（两者都描述逃逸背景）。

**§13.7-A 的落实情况**：`translate_scene` 在 HEAD 就**不** push `Light::Ambient`（`git show HEAD:…` 可验），
故无需"移除"；`ambient_background` 在没有 `Ambient` 灯时返回 0，**不伪造 0.08**。
`prism-gpu/src/lib.rs:539` 的 `let ambient = Vec3::splat(0.08)` 是 `CpuRefBackend`（口径 a 的兜底渲染器）
自编的光，不属于 `prism-rt` 的环境语义、也不来自 `SceneRenderRequest`；动它等于改产品通路观感并会破坏
V2 的 `differing_pixels = 0` 死线，**本波不动**（W0 §13.7-A 的原文也只要求"若 W0-B 期间加了 Ambient 就要在 W2 移除"）。

### 2.7 GPU 侧 blob ABI

24 字头部 + 七段（`cond` / `marg` / `res_cond` / `res_row_off` / `spot_prefix` / `spot_texels` / `texels`），
用 `array<f32>` 承载 u32 位模式，单输入 dispatch。实测 32×16 环境 = 1,502 字（6,008 B），
头部/表/texels 三段与 CPU 状态**逐位一致**（`v6_blob_is_the_cpu_table`）。

## 3. 验收 V1–V6（阈值照抄，未放宽）

### 3.1 V1 白炉

常数环境 `L=1` + 白漫反射 `albedo=1`，8 弹射，64 像素 × 2048 spp。

【实测】最差 `|L−1| = 1.932e-3`（阈值 `1e-2`）；MIS 532,480 对 `(pdf_env, pdf_bsdf)`，
`w_nee + w_bsdf` **逐对比特级 == 1.0**，`w_nee ∈ [1.571e-2, 1.000]`。

### 3.2 V2 方向锚定

亮斑以**纹素中心**对齐（`ci=64, cj=16`，`cu=(ci+0.5)/128`），镜面球反射方向必须命中。

【实测】中心像素 `L = 10.000000`（亮斑 10.0，差 `0.000e0` ≤ 1 LSB = `0.003922`）；
亮区质心 `(4.000, 4.074)`，期望 `(4, 4)`；左上角（非亮区）`L = 1.000e-3`。

> 上一轮质心曾偏到 `(3.088, 4.949)`：亮斑以 uv **网格点**为中心（半纹素偏置）+ 3×3 `<2` 阈值把边缘算进亮区。
> 改成纹素中心对齐 + `<=1` 环后归位。**判据没动，改的是测试的取样口径**（原口径把半纹素偏置当成算法误差）。

### 3.3 V3 无偏

MIS 全开 8192 spp vs 1e6 点均匀球面暴力积分（同一场景、同一相机、0.2° 小 fov，见下）。

【实测】最差相对误差 `1.116e-4`（0.011%，阈值 0.5%）。

> 逐点对拍必须用小 fov：1×1 像素 + 大 fov 时像素足迹覆盖大半个球，参考点积分的"点值"与像素均值
> 差 2.2×（第二轮实测），那是**口径错**不是实现错。0.2° 下足迹侧向 3.5e-3。

### 3.4 V4 与解析灯互校

同辐亮度、同立体角的环境亮帽 vs `Light::Sphere`（远距小锥）。立体角用**实测**等效角对齐
（`sinθ_eff = √(E_env/(πL))`），两侧目标辐照度逐位一致。

【实测】环境 `0.053581 ± 2.95e-5` vs 球光 `0.053569 ± 1.86e-6`，`θ_eff = 14.997°`，
`Δ = 1.242e-5 = 0.023%`，`z = 0.42`（阈值 1%，3σ）。

### 3.5 V5 pdf 一致性

【实测】2,097,152 个 texel（1024 行**全覆盖**，不是抽样），`max|pdf_w·Ω_texel − 1| = 9.936e-5`（阈值 `1e-3`）。

> 最初用 4096 点 MC 估 `pdf·4π`，在 40:0.1 对比度下给出 3.7% 的**假偏差**（方差，不是实现错）。
> 改成逐 texel 精确和 `Σ pdf_w·Ω_texel` —— 精确和的偏差才是真偏差。

### 3.6 V6 确定性（口径 b：CPU ↔ WGSL，**无 SPIR-V wavefront**）

3. **SPIR-V wavefront 缺位**：仓库里没有路径追踪通路的 SPIR-V 发射器（`spirv_rt.rs` 发的是 megakernel），
   口径 b 本来就只给两方判据。**不伪称三后端**。

**4 弹射 vs 8 弹射差异**：**未测** —— 该比对要求整条 wavefront 跑起来（`WF2_MAX_BOUNCES = 4` vs CPU 8），
前提就是第 2 条。不拿探针数据冒充。

### 3.7 EXR → 场景端到端（接线实测，补充）

【实测】太阳 texel 读回值与场景 `texels` **逐位一致**（Float 直通，不经 f16）；

参考值不是"再来一遍采样"，而是确定性求积：
`L_out = sky·∫_H f·cos + (S−sky)·∫_cap f·cos`，第二项以太阳中心为极轴做极坐标中点求积
（边界与 `θ_sun` 精确重合），第一项用 GGX-NDF 采样（常数环境权重极平）。

参考自身的收敛（两项的粗细求积互校）：roughness 0.05 / 0.20 / 0.45 / 0.80 分别为
`0.08918%` / `0.01782%` / `0.00093%` / `0.00080%` —— 参考误差 ≪ 1%，判据不会被参考噪声吃掉。

## 5. 成像级判据（路线图 §4.2 W2 行：PSNR ≥ 40 dB）

W0 §3.2 的 V1–V6 判的是**估计器性质**；"成像 PSNR"判的是**给定预算下画面与收敛画面的接近程度**。
两者可以互相独立（可以全绿而有偏，也可以全红而无偏），故单列。

**口径（写在测试文件头部，先钉死）：**

| 项 | 取值 |
|---|---|
| 环境 | 128×64 等距柱状：天际梯度 `0.35~1.40` + 3° 太阳 `L=400`（对比 ~1000:1） |
| 材质 | 半径 1 金属球，`metalness=1`、`roughness=0.12` |
| 相机 | `eye=(0,0,4)`、`look=原点`、`fov=35°`、32×32 整幅 |
| 参考 | **4096 spp**（W0 §1.1「≥4096 spp 均匀」），种子 `(2026,11,3)` |
| 被测 | **256 spp**，种子 `(2026,11,2)`（不同种子 ⇒ 噪声独立） |
| PSNR 域 | 逐通道 Reinhard `x/(1+x)` → MSE → `10log10(1/MSE)`，MAX = 1 |
| 判据窗口 | 球心 16×16（全部像素命中球面）——背景是解析值、零方差，计入会把判据抬成自证 |

**为什么必须在显示域算**：HDR 域 `MAX` 取谁都能吵 —— 取峰值 400 ⇒ 40 dB 允许 RMSE 4.0（暗部真值 0.35 错 4.0
早已不是"成像一致"）；取 1.0 ⇒ 亮斑的量化台阶就能把 PSNR 压到 20 dB 以下。Reinhard 压缩后两档落在同一把尺子上，
`40 dB` 才对应一句人话：**压缩域 RMSE ≤ 1%**。

【实测】`256 spp` vs `4096 spp` 参考：窗口 PSNR = **`43.987 dB`**（判据 ≥ 40）；
整幅 `49.392 dB`（含零方差背景，仅作参考）；窗口内 HDR 辐亮度 `0.4356 ~ 51.1063`；
HDR 域相对 RMSE `1.600e-3`（不参与判据）。

**负控（判据非恒真）**：同一度量在 **16 spp** 下 = `33.617 dB` < 40 dB，测试**断言它必须 < 40**。
没有这一条，就无法证明"40 dB"不是这把尺子的地板。

## 6. 跨后端根因记录：lavapipe 内建 `acos` 的 5e-5 偏差

这是本轮唯一一次"对拍红了又绿"的完整事故，写下来备查。

### 6.1 症状

首跑 `pdf_w(wi)` 相对差 `9.968e-1`（W 倍级）、辐亮度相对差 `1.347e-3 / 9.921e-4`，
其余指标（方向、采样 pdf、texel）都是 0。**红的是"离散分类"而不是"连续数值"**。

### 6.2 定位

探针加两个诊断槽（`uv` 与 `spot_index`）后逐查询打印，定位到 `i=165` 一个查询：
GPU 判"非亮斑"、CPU 判"亮斑"，且 `uv` 的 `v` 分量差 `1.56e-5`。
拿 f64 当裁判量三件东西：

| 函数 | CPU（`det_trig`）对 f64 偏差 | lavapipe 内建对 f64 偏差 |
|---|---|---|
| `acos` | `3.2e-8` | **`4.96e-5`**（换成 `θ` 是 `1.56e-4`） |
| `atan2` | — | `1.2e-7`（与 `det_trig::atan2` 之差） |

`v = acos(y)/π` 偏 `1.56e-5` ⇒ 落在亮斑边界附近的查询被分到另一支 ⇒ `pdf_w` 差一个 `W` 倍
（亮斑臂与残差臂的分母不同）。辐亮度的 `1e-3` 级差是同一根因（双线性权重偏移）。

### 6.3 修法

`rt_env.wgsl` **全面改用 `det_trig` 的逐式镜像**，一个阈值没动：

* `env_atan2` —— 与 `det_trig::atan2` 同特例、同分支、同归约顺序（`ENV_TAN_PI_8 = 0.41421357`）；
  WGSL 禁递归，`atan_pos` 展开成显式两层；
* `env_acos(x) = env_atan2(√((1−x)(1+x)), x)` —— 与 CPU 同式（不用内建 `acos`）；
* `env_uv_to_dir` / `env_texel_dir` / `env_row_omega` 的 `cos/sin` 全部换 `rt_common::cos_sin`
  （mod 2π → 象限 → π/4 Maclaurin），不用内建 `cos/sin`。

修后 512 查询 × 2 环境全部指标 = **0**，含极点带。

### 6.4 为什么不放宽容差

容差放宽度量的是"两台机器算得不一样"，而这里的问题是"**同一份规格没有逐式实现**"。
首跑的实际差值是 `9.968e-1`（近 2×）—— 这不是 `1e-1` 容差能盖住的量级；要盖住它得放到 `1.0`，
那等于取消判据。**判据是尺子，不是调参旋钮。**

## 8. 未测 / 未接线清单（如实）

> **本节在 W2 收口后已被补测**：§8.1 的绑定前缀冲突已解、4 vs 8 弹射已实测，

### 8.1 整条 wavefront 未接 env blob ⇒ 未测（W2 收口时点的现状）

`rt_wavefront.wgsl` 的 `shade`/`extend` 要额外一组绑定承载 CDF blob；group(0) 的 {0,1,2} 已被
slots/params/accum 占满，而宿主 ABI 要求每个 entry 的绑定集是**连续前缀** ⇒ 接线必须同步改
`web/abi.rs` 的 group 表与浏览器宿主。本轮**未做**。

因此：

* **4 弹射 vs 8 弹射的画面差异：未测**（前提是整条 wavefront 跑起来）；
* 本轮 V6 的"确定性"是**探针级**（四条链路逐值对拍），已在 §3.6 逐条声明，不冒充整条通路。

### 8.1-bis 接线实录（补测）：env CDF 挂到 `group(2) @binding(5)`

**冲突的真正约束不是"要新开一组"，而是"`maxBindGroups = 4`"**。WebGPU 的默认
`maxBindGroups` 是 **4**，group 索引只能取 0..3；`rt_wavefront.wgsl` 的 `shade` 已经用到
group(0) `{slots, params, accum}`、group(1) `{sobol, scene_buf}`、group(2) 场景资源，
group(3) 是相机。**再开 group(4) 直接越界**，不是"改个数字"能解决的。

解法：把 env blob 挂在**场景组尾部** —— `@group(2) @binding(5)`。宿主的唯一硬约束是
"每个 entry 的绑定集必须是连续前缀 `{0..n-1}`"，`shade` 的引用集从 `{0..4}` 变成 `{0..5}`，
仍是前缀；`extend` / `generate` 各自仍是更短的前缀（它们不引用 env）。

**同步改的浏览器宿主**（`crates/prism-gpu/src/web/abi.rs`）：

* `t_gpu_rt_wavefront_multi` 的 `sh_g2` 从 5 绑定补到 **6 绑定**
  `[scene_params, materials, prim_mat, tris, lights, env_blob]`（第 6 个是 1 元占位缓冲）；
* `Scratch` 新增 `wf2_env: [u8; WF2_ENV_BYTES]`；
* narrative 文案与 COVERAGE 台账同步（`shade`/`extend` 的 g2 绑定数 5/4 → 6/4）。

**`rt_env.wgsl` 的绑定声明移出**：那是唯一一份 WGSL env 实现（CDF 反演 / 方向映射 /
双线性 / pdf），原来是自带 `@group(0) @binding(0)`。若保留，wavefront 引用它时会与
group(0) 的 slots 撞号。改成"绑定由**引用方**声明"——`rt_env_probe.wgsl` 挂 group(0)@binding(0)、
`rt_wavefront.wgsl` 挂 group(2)@binding(5)，**函数体共享而绑定号不共享**，避免复制第二份实现
（用户红线："wavefront 的逃逸/环境采样走与 CPU 同一份 CDF 语义，不许另写一套近似"）。

`scene_frame_v3` 侧不受影响（那是另一条腿，11 绑定全在 group(0)）。

### 8.1-ter 4 vs 8 弹射实测（**如实填数**）

**口径**：`prism-rt` 的 `wavefront` 是"估计量层面"的逐句重排（CPU 版），
已由 `wavefront_matches_integrator_bitwise_at_same_bounce_count` 证明**同弹射数下与
`integrator` 逐位相等**。故"4 vs 8 弹射的差异"在这里量的是
**`prism_rt::wavefront`（WF2_MAX_BOUNCES=4）vs `prism_rt::integrator`（8 弹射，CPU 权威）**。
它不是"WGSL 在 llvmpipe 上跑出来的差"——整条 WGSL wavefront **没有 SPIR-V 发射器**
（§8.2），这条腿的 GPU 数字本环境拿不到。

**场景**：金属球（`metalness=1, roughness=0.12`）+ 漫反射球（Lambert `0.85`）+ 无限地板

（凸性），`max_bounces ≥ 2` 与 `= 1` 输出逐位相同——判据什么都没测。这条已单独留作负控。

**口径**：12×12、spp=512、种子 `(2026, 11, 2)`；PSNR 在 Reinhard 域 `x/(1+x)` 上算（MAX=1）。

**旁证（无萤火钳制）**：漫反射球去掉 firefly 钳制后，4 vs 8 弹射 PSNR **34.398 dB** /
RMSE **3.8869e-2** / `max|Δ|` **4.1570e-1** / **117/144**；2 弹射 RMSE **1.6522e-1**。
即"钳制与否"不改变结论方向，只改变幅度（钳制把 4 弹射的尾部压掉一点）。

**负控（单凸球）**：4 弹射 vs 8 弹射 **逐位相同**（`max|Δ| = 0`）——与上面"凸性 ⇒ 无多次弹射"
的推理一致。这条证明上表的差异**确实来自弹射截断**，而不是"两条代码路径本来就不同"。

**结论**：4 弹射相对 8 弹射**存在固有差异**（金属球 31.97 dB、漫反射球 35.83 dB），
**不许把它当成 0 差异**。8 弹射是权威参考；4 弹射的差额主要落在间接光/多次反射上
（漫反射球 84% 像素有差异，比金属球的 78% 更广——漫反射的间接项占比更高）。

复现：

```bash

# 4 项：同弹射数逐位自检 / 4 vs 8 主判据 / 无钳制旁证 / 单凸球负控
```
