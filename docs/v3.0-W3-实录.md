## 0. 作者指令原文与交付口径

> **作者原话（本波核心）**：「画面能力/画面质感/美学体系/音乐体系跟与视频
> 直接相关的内容，必须要做到看起来不能像是代码生成而像是搓的一样。目前
> 代码生成的视频，我觉得就是塑料感……即便加上 CSS 等也一样」；
> 「必须是可选择的，如果用户就要匀质，就要均匀呢？」
>
> **加 CSS 也没用**：塑料感不在表面装饰，在生成逻辑本身太解析、太完美、
> 无介质。因此**禁止出完帧再贴 grain / 滤镜 / 色调模板冒充**（那是 CSS
> 等价物），痕迹必须注入到**渲染前的生成源头**。
>
> **历史死命令**：「直接治本不治标」「绝对不能留部分/遗留」
> 「几百行代码工程师随随便便就写完了，我们的工程师又不是真人那种」——
> 不许把能做完的活包装成「研究级实现量」甩成「待裁定」，不许把球踢回作者。

| 缺口（路线图 §5.3 W3 行 + §3 全章） | 本波处置 | 结论 |
|---|---|---|
| ① `finish` 双一等档（D-30）：显式声明 / 进产物哈希 / 漏填非法值报错 / 不默认选档 / 每维度独立开关+强度且能设 0 / 旧文件恒等 `analytic` | `prism-dsl/src/finish.rs` 一等声明面 + 行式扫描遮罩 + v2 `finish { }` 降级；`WiringPlan.finish` 挂到 W2 唯一事实源 | P9001–P9012 全判红带行号三段式；`analytic`/旧文件逐字节零变化 |
| ② 六族痕迹维度注入生成源头（§3.4） | `resolve_frame` → `wiring_frame_values` → `render_scene_frame` 渲染前链路逐帧注入 | 六族各 1 条静态注入断言 + 1 条帧值对拍断言全绿；注入点全部在组装 `Material`/`Light`/`Scene`/`Camera` 之前 |

**红线自查**：

- **红线 1 语言层不成为第二事实源**：质感/画质/音频数学全部下沉既有 crate；
  `finish.rs` 只做「声明 + 扫描 + 规范字节 + 种子化噪声注入 + 门禁」，
  不复制任何缓动/Voronoi/胶片/评分/作曲数学。
- **红线 3 / 4**：`finish` 漏填即报错（不取默认、不静默降级）；不贴皮、
  不偷加噪、不替用户选档、**不为「去塑料感」给 `analytic` 全局加噪**。
- **匀质是一等能力**：`analytic` 是合法交付物，不因「不够搓」被判失败（V4）；
  「只有运动带呼吸、几何绝对匀质」可表达（每族独立开关，关闭族连
  `signal=0` 键都不写）。
- **判据不放宽**：不删测试、不加 `#[ignore]`、不改判据原文、不放宽阈值、
  不事后调盲测门槛。盲测门槛 0.75 定桩于跑测之前。
- **每波可停**：旧文件 / `analytic` 零字节变化恒成立；
  `finish` 语法特性一次做完（声明 / 报错 / 注入 / 接线 / 凭证 / 文档 / 门禁），
  不留半截 ABI，不动 web / `scene_gpu.rs` 观感路径（本波无设备相关改动）。

## 2. 六族痕迹维度注入生成源头（§3.4）

### 缺口原文

> 六族「运动 / 几何 / 材质光照 / 时间镜头 / 构图色彩 / 剪辑音画」逐行冻结
> 「维度 | 引擎触点 | 注入点（生成源，禁止填 postfx 末端）| dsl 字段 |
> 强度范围 | analytic 值」，注入点必须落在
> `wiring.rs::bind_source/resolve_frame` 与
> `movie.rs::wiring_frame_values/render_scene_frame` 这条**渲染前**链路上，
> **不许是帧后效果节点**。每族至少一条静态注入断言 + 一条帧值对拍断言。

### 做了什么

- 完整冻结表见 `docs/v3.0-痕迹维度表.md` §2（六族逐行 + 引擎触点 + 注入点 +
  dsl 字段 + `0..1000` 定点强度 + analytic 恒 0）。
- **生成源头逐帧注入**：`wiring.rs::resolve_frame`（`:636`，`:672` 调
  `finish::inject_frame_values`）在渲染前把 `w3.<族>.strength/noise/signal`、
  `w3.mode` 写进 `WiringFrame`；`movie.rs::wiring_frame_values`（`:1591`）
  crafted 时补 `w3.frame`；`render_scene_frame`（`:1631`）在组装
  `Scene`/`Material`/`Light`/`Camera` **之前**消费六族信号。
- **种子化确定性噪声**：`finish.rs::dim_noise`（`:372`）——几何族走
  `prism_noise::pcg::hash2_f32`（与 `generators.rs:145` 同源），其余五族走
  `prism_core::eval::hash_mix` 链 + `hash_mix_unit_f32`；零真随机、零系统时间、
  零平台 libm、零线程。
- **帧值对拍**：`finish.rs::assert_frame_value_pairs`（`:419`）逐族逐帧对拍
  「声明强度 → 注入量」，`w3_finish.rs` 逐族只启用该族、逐帧 `0..8` 逐位对拍，
  并断言其它五族恒等 0。

## 4. 两条治本禁令 → 静态门禁（§3.3 / V2）

### 做了什么

- `finish.rs::posthoc_gate`（`:536`）：全文查 `POSTHOC_BLOCK_MARKERS =
  ["post {", "post{", "postfx"]`，命中 `P9011` + 行号 + 三段式；`finish` 块体
  内另严格查 `FORBIDDEN_POSTHOC_TOKENS`（grain/vignette/chromatic/bloom/
  filter/lut 等）。**只查块标记不查裸词**，避免误伤 W1 确定性采样样例
  `a = rand("grain")`。
- `finish.rs::true_random_gate`（`:517`）：全文查 12 个禁用 token
  （`SystemTime`/`thread_rng`/`getrandom`/`rand::`/`now()`/`OsRng`/…），
  命中 `P9012` + 行号 + 三段式。
- 两条门禁接在 `compile_v3` 的 `codegen_v3` **之后**（`lib.rs:380/381`），
  是编译期全文检查，**与选哪档无关**（`analytic` 同样判红）。
- **实现级静态门禁**：`w3_end_to_end.rs` 对 `finish.rs`/`wiring.rs`/
  `movie.rs`/`w3_eval.rs` 源码做静态检出，确认注入链路不含
  `eval_window`/`TileEffect` 帧缓冲贴皮调用，且随机源只走
  `hash_mix` / `pcg::hash2_f32`；`w3_finish.rs` 断言 `compile_v3`
  源码确实调用了两个门禁函数。
